# 3단계: 시간·행동력·예약 사건

후속 선택 기능: 월 일정·개인 행동력·병렬 세션·반복 예약은 [통합 시간 모델](unified-time.md)을 참고한다. 아래는 기존 독립 시계 모델의 계약과 검증 기록이다.

2026-10-14. 기존 프로젝트와 저장 계약을 유지하는 선택 기능이다. `project.progression`이 없으면 상태에 새 필드를 생성하지 않고 기존 월 일정·행동·사건을 그대로 실행한다.

## 제작

Qt **디자인 → 시간 · 행동력 · 예약 사건**에서 시간 단위 이름, 공용 행동력 최대/초기값/시간당 회복량을 설정한다. 기존 공통 행동에 소요 시간과 행동력 비용을 붙인다. 예약에는 고유 ID, 절대 게임 시각, 상호작용 사건, 필요하면 개인 사건 실행자를 지정한다. 기존 조건·효과·대본 제작기를 재사용한다.

예약 사건은 자동으로 별도 콘텐츠를 생성하지 않는다. 사건 편집기에서 발생 방식을 **행동에서 연결**로 만들고 예약 목록에서 선택한다. 개인 사건은 사건 범위를 **실행자별 완료 기록**으로 설정하고 예약의 실행자를 지정한다. 같은 프로젝트 변경/검증/버전 충돌 서비스를 사용하므로 MCP와 Qt가 같은 데이터를 편집한다.

기존 **공통 행동** UI 위젯은 시간 기능이 있으면 시간·행동력, 시작/대기, 진행 중 행동·남은 시간, 이어가기·취소를 표시한다. 새 행동 UI 종류나 게임별 코드가 필요하지 않다.

## 데이터 및 실행 계약

- `progression.unitLabel`: 표시 단위. 시간은 0부터 시작하는 정수 tick이다.
- `actionPoints: {max, initial, recoveryPerTick}`: 공용 행동력. 경과 tick마다 회복하며 최대값으로 제한한다.
- `actions: [{actionId, duration, actionPointCost}]`: 기존 공통 행동에 적용할 시간 설정. 수량에 비례한다. 이 목록에 없는 행동은 기존처럼 즉시 실행한다.
- `appointments: [{id, eventId, atTick, actorId?}]`: 한 번 처리하는 절대 시각 예약. 최대 128개. 같은 시각은 예약 ID 순서로 처리한다.
- 저장 상태 `progression`: 현재 tick·행동력, 처리한 예약과 fired/skipped 결과, 대기 중인 명령·실행자·남은 시간. 대본 자체는 기존 커서와 실행자 문맥을 사용한다.

`executeAction`/`executeActorAction`이 시간 설정된 행동이면 현재 실행 가능 여부를 복사 상태에서 검사한다. 실제 난수 상태와 비용·효과는 바꾸지 않고 행동력만 차감해 세션을 만든다. `advanceSession`은 다음 예약 또는 완료 시각까지 이동한다. 예약 대본이 끝나면 같은 세션을 이어간다. 일반 비용·효과·확률 흐름·연결 사건은 완료 시 한 번 실행한다.

예약 조건/기간을 만족하지 않거나 이미 완료한 사건이면 skipped로 기록하며 재시도하지 않는다. 같은 시각의 여러 예약은 여러 번 이어가기로 순차 처리한다. 행동 완료와 예약 시간이 같으면 예약을 먼저 처리한다. 예약 사건의 실행자와 진행 중 행동의 실행자는 서로 달라도 유지된다.

`waitTime {ticks}`는 효과 없는 대기 세션을 시작한다. `cancelSession`은 세션만 취소한다. 이미 지불한 행동력과 경과 시간, 발생한 사건은 되돌리지 않으며 아직 적용하지 않은 완료 효과는 발생하지 않는다. 완료 시 비용 부족 등으로 실패하면 해당 명령 전체를 취소해 직전 세션 상태를 유지한다. 이어가기 또는 취소를 선택할 수 있다.

세션 중에는 대본 진행·선택·세션 이어가기·취소만 허용한다. 별도 행동이나 월 일정으로 우회해 중복 실행할 수 없다. 저장·불러오기는 세션 시작 직후, 예약 대본 중, 완료 후 모두 가능하다. 저장은 기존 명령 재생과 전체 상태 비교로 변조를 검출한다.

## 호환성 및 현재 범위

- 기능 식별자 `progression-sessions-v1`. 검증한 배포 런타임은 Windows 네이티브 플레이어다. 구형 런타임은 내보내기를 거절한다. 웹·모바일·콘솔의 이 기능 지원 완료를 뜻하지 않는다.
- 이 게임 시계는 월 일정의 `periodIndex`와 독립적이다. 월별 기존 콘텐츠의 실행 순서와 엔딩 판정을 변경하지 않는다. 시간→날짜 자동 변환은 아직 추가하지 않았다.
- 시간 설정은 직접 실행하는 공통 행동의 바깥 세션에 적용한다. 행동 내부 흐름과 기존 정책/트리거 호출은 원자적 효과이며, 중첩 시간 세션을 만들지 않는다. 탐험 진입 행동의 시간 설정은 검증에서 거절한다.
- 현재 하나의 공용 행동력과 하나의 진행 세션이다. 개인 능력을 이용한 별도 비용은 기존 소유자 지정 조건·효과로 제작할 수 있다. 병렬 행동 세션, 동적/반복 예약, 개인 행동력 풀은 이번 범위가 아니다.

## 검증과 증거

샘플: `tests/fixtures/projects/time-session-demo`. 실행: `start-time-sessions.cmd`.

Qt 위젯을 통해 두 캐릭터, 서로 다른 행동과 사건을 만든 다음, 민서의 꽃 선물에 5시간/행동력 3, 하린의 공부에 4시간/행동력 2를 설정했다. 행동력 최대 6, 초기 4, 시간당 회복 1이며, 2시간 시점에 방문 사건이 발생한다. 파일 외부 생성만으로 GUI 제작을 주장하지 않는다. README는 검증 후 별도로 작성한 사용 설명이다.

- 코어 신규 10개 통과: C++/TS 상태·전이 일치, 중단과 전체 저장 재생, 행동력 부족·동시 명령 차단·버전 충돌, 취소/회복, 같은 시각 예약 순서, 개인 사건 실행자, 완료 실패, 오류 위치, 기존 저장, 자동 분석 경로, 미리 검사 중 난수 비소비와 확률 결과 결정성. 기존 회귀 73개도 통과했다.
- 실제 Qt 제작·undo/redo·저장·재열기 및 편집기의 플레이 버튼 통합 검증을 수행했다. 예약 사건 콤보박스의 ID 타입 불일치를 발견해 수정했고, 사건을 고르지 않은 행은 창 안에서 안내한다.
- 실제 SDL/RmlUi 버튼 입력으로 0시간/행동력 1에서 시작 → 2시간 방문 사건/남은 3시간 → 5시간 완료/행동력 6을 확인했다. 선물 효과는 완료 시 한 번만 발생한다. 사건 중 저장·진행·불러오기·재진행의 전체 상태가 일치한다. 별도 플레이어 프로세스에서 불러오기도 일치한다. 공부 시작 후 취소와 대기의 시간/행동력 결과도 검사했다.
