# 화면·연출 편집기

2026-10-11. 장면과 게임 UI를 같은 데이터로 편집하고 플레이어에서 실행하는 첫 버전입니다.

## 이번 미리보기 실행

- 실행 파일: `release/visual-preview/Raising Studio-win32-x64/Raising Studio.exe`
- 열 프로젝트 폴더: `projects/my-first-year-visual` — 기존 `my-first-year`를 복사해 이미지와 화면 구성을 추가했습니다.
- 앱에서 **열기 → 프로젝트 폴더 선택 → 화면·연출**로 들어갑니다. 다른 PC로 옮길 때는 실행 파일이 있는 폴더 전체와 프로젝트 폴더를 복사합니다.
- 이미지 원본과 생성 기록: `assets/visual-sample/` 및 `assets/visual-sample/PROMPTS.md`. 배경 2장과 투명 배경 인물 2장을 실제 샘플 에셋으로 포함했습니다.

이 실행 파일은 별도 포터블 미리보기입니다. 이전 설치판은 이번 변경으로 갱신되지 않습니다.

## 사용 순서

1. 새 편집기에서 **비주얼 샘플 새 프로젝트**를 눌러 빈 폴더에 샘플을 만듭니다. 기존 프로젝트에는 **화면·연출 → 화면 편집 사용**으로 적용할 수 있습니다.
2. 타이틀·일정/활동 결과·대화/선택지·엔딩 중 화면을 선택합니다.
3. 왼쪽 레이어에서 요소를 고르거나 캔버스에서 클릭합니다. 드래그로 이동하고 오른쪽 아래 모서리로 크기를 조절합니다. 방향키는 1px, Shift+방향키는 10px입니다. 8px 격자 맞춤을 켜거나 끌 수 있습니다.
4. **UI 속성**에서 좌표·크기·글자 크기·색상·불투명도·모서리·정렬·레이어 순서·잠금·숨김을 바꿉니다. 숫자는 입력 후 포커스를 옮기거나 Enter를 누르면 반영됩니다.
5. 텍스트에는 게임 제목·날짜·화자·대사·엔딩 이름을 연결할 수 있습니다. 버튼은 새 게임·진행·저장·불러오기·소리 전환을 실행합니다. 능력치·일정·선택지·활동 결과는 실제 게임 데이터를 표시하는 위젯입니다.
6. **장면·연출**에서 게임 시작, 활동, 사건/엔딩 시작 또는 기존 장면 노드를 선택하고 배경·인물·표정을 지정합니다. 사건/엔딩에 시작 연출이 없으면 기존 진입 노드 앞에 장면 노드를 추가해 연결합니다.
7. 이미지의 **UI 속성**에서 배경/왼쪽/가운데/오른쪽 인물 연결, 맞춤 방식, 페이드·슬라이드·확대 등장과 시간을 설정합니다. 페이드는 이전 이미지와 겹쳐 전환합니다. OS의 동작 줄이기 설정에서는 효과를 생략합니다.
8. **이미지 가져오기**로 PNG/JPEG/WebP를 프로젝트에 복사하고 에셋 목록에 등록합니다. 최대 20MB이며 동일 내용은 중복 등록하지 않습니다. 가져온 이미지는 고정 이미지 요소로 배치하거나 배경으로 선택할 수 있습니다. 인물 표정 매핑은 콘텐츠의 인물 폼에서도 설정할 수 있습니다.
9. **실제 플레이로 확인**에서 UI 동작과 장면 전환을 확인합니다. 미리보기의 저장/불러오기 버튼도 실제 게임 저장 파일을 사용합니다. 편집기로 돌아온 뒤 **초안 저장**하면 다음 실행에도 배치가 유지됩니다.

편집기의 능력치와 대사는 배치 확인용 예시입니다. 반투명하게 보이는 요소는 현재 예시 상태에서 표시 조건이 맞지 않는 요소입니다. 실제 플레이에서는 숨깁니다. 기준 화면의 비율을 유지하면서 창 안에 맞추며 남는 공간은 여백으로 처리합니다.

## 데이터와 검증

- `project.json`의 선택적 `visual` 필드가 화면 크기, 시작 장면, 화면별 요소 배열을 보관합니다. `packages/schema/visual.schema.json`이 데이터 계약입니다.
- 기존 프로젝트는 `visual`이 없으면 기존 플레이어를 사용합니다. 새 데이터는 이전 배포판에서 지원되지 않습니다.
- 요소 ID는 화면 안에서 유일해야 합니다. 화면 ID 중복, 누락, 영역 밖 좌표, 잘못된 이미지 참조/종류, 진행에 필요한 UI 누락을 검증합니다.
- 편집은 기존 StudioEditor의 변경 이력·검증·충돌 검사를 사용합니다. LLM/MCP도 기존 프로젝트 읽기·패치 서비스로 같은 `project.json`을 편집할 수 있습니다.
- 기본 장면은 실제 초기 상태에 포함됩니다. 장면과 UI를 변경하면 콘텐츠 fingerprint가 바뀌므로 이전 콘텐츠의 저장 파일과 혼용하지 않습니다.
- 이미지 가져오기는 파일을 덮어쓰지 않고 내용 해시로 이름을 정합니다. 실행 취소는 에셋 등록을 되돌리며 가져온 바이너리 자체를 삭제하지 않습니다.

## 구현 위치

- `packages/visual/model.ts`: 기본 화면 구성, 공유 타입
- `apps/player/renderer/VisualSurface.tsx`: 편집기/플레이어 공통 화면 표시
- `apps/player/renderer/VisualPlayer.tsx`: 실제 상태·명령 연결
- `apps/studio/renderer/VisualEditor.tsx`: 배치·속성·장면 편집
- `packages/validation/visual.ts`: 화면 의미 검증
- `examples/academy-visual`: 생성 이미지와 12개월/5엔딩 데이터가 들어간 샘플
- `scripts/create-visual-sample.mjs`: 빈 새 폴더로 기존 12개월 프로젝트와 아트를 복사하는 재현 스크립트

## 현재 범위

네 가지 게임 화면, 평면 레이어 배치와 정해진 게임 위젯/명령을 지원합니다. 화면별 중첩 컨테이너, 자유로운 새 화면 라우팅, 반응형 자동 재배치, 키프레임 타임라인, Live2D/Spine, 임의 스크립트 실행은 이번 버전에 포함하지 않습니다. UI 검증은 지원하는 구조와 기본 진행 요소를 검사하며 모든 사용자 배치의 가독성·겹침을 증명하지는 않습니다.
