# 4단계: 통합 제작 작업실

## 진입과 제작 흐름

Qt의 **디자인 → 제작 작업실 · 데이터 / 행동 / 진행**에서 연다. 기존 캔버스와 나란히 도킹하거나 독립 창으로 사용할 수 있다. 작업실은 기존 프로젝트 서비스의 초안·버전·되돌리기·저장·검증·플레이 경로를 사용한다. 별도 게임 데이터 형식을 만들지 않았다.

- 왼쪽: 이름·ID·종류 검색과 데이터/행동/사건/예약/화면 목록.
- 가운데: 선택 항목 속성, 비용, 조건·효과 수식, 참/거짓 후속 행동, 확률 분기, 시간·행동력·예약 시점.
- 오른쪽: 사용하는 항목과 사용하는 곳의 간접 참조 트리, 행동 분기·자동 규칙·예약·시간 연결 목록. 두 번 클릭하면 대상 편집 위치로 이동한다.
- 규칙 디버거 탭: 초안으로 독립 C++ 검사 시작, 캐릭터별 조건 검사, 명령 한 단계 실행, 실행 순서·상태 차이·현재 상태 확인, 플레이 저장 불러오기.

변경 적용은 초안 변경이다. 프로젝트 저장으로 디스크에 반영한다. 적용하지 않은 입력이 있으면 작업실의 저장·플레이·되돌리기를 막는다. 다른 편집에서 초안 버전이 바뀌면 입력을 유지하면서 적용을 거절한다. 새로 고침 / 입력 취소로 최신 내용을 다시 읽는다. 규칙 디버그 세션도 원본 초안이 바뀌면 재시작해야 한다.

## 지원하는 편집

능력·관계 정의의 범위와 초기값, 플래그 초기값, 물품 수량, 육성 대상의 기존 초기 능력·소지품·활동 배정, 행동·활동의 조건·효과·비용, 사건 조건과 기간, 엔딩 조건과 우선순위, 자동 규칙의 실행 시점·행동, 행동의 조건/확률 분기, 시간 단위·행동력·소요 시간·예약을 편집한다.

새 행동·물품·자동 규칙·예약 사건은 일반 프로젝트 JSON으로 생성된다. 생성 후 다른 정의와 같은 방식으로 편집한다. 특정 게임이나 시설 이름을 판별하는 동작은 없다. 자동 규칙은 기존 행동, 예약은 기존 공용 상호작용 사건을 시작값으로 삼는다.

각 분야의 전체 기능을 작업실 속성 폼에 모두 옮긴 것은 아니다. 화면 배치, 대본, 복잡한 관계 초기화, 정책·상점 등은 기존 전용 제작 창도 계속 사용한다. 다국어 객체 등 폼이 직접 편집하지 않는 기존 값은 보존한다.

## 참조와 디버깅의 의미

`packages/authoring-workspace`는 검증되지 않은 초안 문서에서도 ID 참조를 추출한다. 노드는 파일과 JSON Pointer를 갖는다. 중복 ID는 개별 정의로 표시하고 해당 ID를 향한 연결은 모호한 참조로 처리한다. 없는 참조도 제거하지 않는다. UI 영향 탐색은 깊이 4, 최대 약 500개 분기로 제한하며 순환 연결을 표시한다. 서비스에서는 깊이 1~8을 선택할 수 있다.

참조·영향은 알려진 ID 필드와 초기 상태 맵에 대한 **정적 의존성**이다. 문자열 전체 추측이나 실제 도달 가능성 증명이 아니다. 내부 대본 노드의 상세 편집과 기존 대량 플레이 경로 지도는 별도 도구다.

디버거는 실제 C++ 코어를 실행한다. 조건 검사 시 선택한 캐릭터의 상태를 읽지만 검사만으로 상태·난수를 바꾸지 않는다. 시간 행동의 사전 가능성 검사는 실행 추적에서 제외한다. 행동 시작에는 세션 시작만, 실제 완료에는 비용·효과·분기 기록이 나타난다. 예약 사건의 발동/건너뜀, 세션 취소/완료도 기록한다. 상호작용 사건 검사는 조건·기간·완료 여부를 보여 주되 별도의 행동/예약 호출이 필요하다고 표시한다.

## 검증 샘플

기존 `tests/fixtures/projects/time-session-demo`를 별도 디렉터리로 복사한 뒤, 실제 Qt 위젯을 QTest로 조작해 변경했다. 복사 자체는 파일 복사이며 GUI에서 새로 제작했다고 계산하지 않는다. 변경은 JSON 외부 편집 없이 작업실·조건/효과 편집기로 수행한다.

1. 책 최대 수량 10 → 25, 되돌리기·다시 실행.
2. 민서 꽃 선물의 소요 시간 5 → 6.
3. 방문 예약 시각 2 → 3.
4. 후속 훈련 행동을 새로 만들고 실행자 검술 +2 효과 작성.
5. 꽃 선물의 참 분기에 후속 훈련과 100% 확률 수식 연결, 참조에서 편집 대상으로 이동.
6. 초안 버전 충돌 시 입력 26을 유지하면서 적용 거절.
7. 프로젝트 저장·재열기, 선택 캐릭터의 조건 검사와 예약까지 디버그 진행.

Windows 플레이 검증에서는 3시간 시점 방문 사건 도중 저장하고 6시간 시점까지 진행한다. 완료 후 민서의 꽃은 2 → 1, 검술은 10 → 12, 하린 검술은 40으로 유지된다. 불러오기 후 전체 상태와 후속 결과가 일치한다. 별도 플레이어 프로세스에서도 저장을 재개한다. 다른 캐릭터 행동의 취소와 대기도 검사한다.

테스트: `tests/qt-studio/authoring-workspace.test.mjs`, `native/studio/authoring-workspace-test.inc`, `tests/native-player/authoring-workspace.test.mjs`. 관련 기존 캐릭터·시간·규칙 회귀와 함께 실행한다. 증거는 `docs/evidence/authoring-workspace/`, 프로젝트 위치는 `.cache/authoring-workspace-proof.json`에 기록한다.

최종 샘플은 `tests/fixtures/projects/authoring-workspace`, 실행 진입점은 `start-authoring-workspace.cmd`다. 관련 Node 테스트 39개가 통과했다. 최종 Qt 빌드에서 제작·충돌 보호·저장 재열기와 편집기 플레이 연동 2개 시험이 통과했으며, 확률 분기 추가 후 별도 Windows 플레이어의 저장 재개 시험도 통과했다. Qt의 초기화/정리 시험은 기능 시험 수에서 제외했다.

## 호환 범위

작업실은 기존 계약으로 저장하므로 기존 프로젝트에 마이그레이션을 요구하지 않는다. 원래 시간 샘플과 실행 중인 기존 편집기를 보존한다. 빌드는 `dist/qt-studio-workspace`, 플레이어는 `dist/native-player-workspace`를 사용한다. 시간 세션 샘플은 기존 `progression-sessions-v1` 지원 런타임을 요구하며, 이번 Windows 검증을 웹·모바일·콘솔 검증으로 간주하지 않는다.
