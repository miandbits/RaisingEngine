# 목표 도달 경로 탐색과 대체 경로 등록

## 편집기 사용

`start-commercial-pilot.cmd` → **디자인 → 목표 경로 기록 · 회귀 검사…**.

현재 실행 파일: `dist/qt-studio-goal-search-final/RaisingStudioQt.exe`. 플레이어 런타임: `dist/native-player-routes`.

1. **목표 엔딩 / 사건 경로 찾기**에서 목표를 고른다. 엔딩은 해당 엔딩의 완료, 사건은 해당 사건의 시작을 목표로 한다.
2. seed, 시간, 최대 상태 수, 경로당 명령 수, 탐색 폭을 정하고 **경로 찾기**를 누른다. 별도 작업 스레드에서 실행하며 진행 상황을 표시하고 취소할 수 있다.
3. 등록된 기록이 있으면 먼저 현재 콘텐츠에서 다시 실행해 참고한다. 과거 상태를 가져오지 않는다. 이때 참고 기록의 실제 seed를 사용하고 결과에 표시한다. 참고할 기록이 없거나 목표에 도달하지 못하면 지정 seed부터 최대 4개의 seed로 새 경로를 탐색한다.
4. 발견 결과에는 목표, 실제 seed, 명령 수, 저장/복원 통과 횟수, 참고 경로가 표시된다. 상세 JSON에서 처음 100개 명령을 미리 볼 수 있다. 100개를 넘으면 잘림 여부를 표시하며 등록 파일에는 전체 경로를 저장한다.
5. 새 ID와 이름을 입력하고 **발견 경로를 회귀 테스트로 등록**한다. 등록 직전에 현재 콘텐츠로 재검사한다. 이후 선택 검사·전체 검사·프로젝트 저장 시 자동 검사에 포함된다.

실패한 기존 경로는 표에서 선택하고 **선택 경로의 대체 경로 찾기**를 누른다. 원래 목표와 시작 조건을 사용해 일정을 바꾸거나 명령을 교체·제거하는 후보를 먼저 검사하고, 해결되지 않으면 새 경로를 탐색한다. 대체 경로는 별도 ID로 저장하며 `sourceRouteId`로 원본을 표시한다. 원본의 실패 기록을 숨기거나 수정하지 않는다.

탐색 중 설정을 바꿀 수 없고, 완료 후 목표/설정을 바꾸면 다시 탐색해야 한다. 탐색 뒤 초안이나 디스크 콘텐츠가 바뀌면 이전 결과의 등록을 거부한다. 기존 경로 ID로 덮어쓰기도 거부한다. 등록하지 않은 탐색 결과는 현재 편집기 세션에서만 보관한다.

## 계약과 한계

- 기존 `version:1`, `endingId` 경로를 그대로 읽는다. 새 경로는 `target:{kind:"ending"|"event",id}`를 사용한다. 서로 다른 두 목표를 동시에 지정할 수 없다.
- 콘텐츠·저장 데이터 형식은 변경하지 않는다. 파일은 `playtests/routes/<id>.json`에 저장한다.
- 저장 검사는 공통 런타임과 저장 코덱을 사용한다. 시작·끝·10명령 간격의 복원 결과를 원래 진행과 비교한다. 기존 경로의 실제 저장 위치도 기존 검사기에서 계속 지원한다.
- 탐색은 유한한 후보 탐색이다. 기본값은 30초, 상태 4,000개, 폭 24, 경로당 1,000명령이다. UI에서 120초/100,000상태/폭 64/10,000명령까지 조절한다. 원본 수정 후보는 최대 128개, 기존 참고 기록은 최대 32개다. 이 후보 수는 상태 확장 수와 별도로 표시된다.
- `not-found`는 **주어진 한도에서 검증된 경로를 찾지 못함**이다. 불가능 증명·최단 경로·전체 경로 열거·모든 seed 성공을 보장하지 않는다. 후보 생성기는 기존 분석기의 단위 수량 행동과 제한된 다인 활동 조합을 사용한다.
- 임의 사용자 플러그인의 외부 동작이나 UI 전용 행동을 모두 탐색한다고 주장하지 않는다. 발견 경로의 검증은 공통 런타임이 처리하는 명령 범위다.
- 기존 분석기의 동점 후보 정렬을 보완했다. 같은 목표 조건 점수에서는 시간 진행 단계가 장비/방문 반복에 밀리지 않도록 한다. 조건 점수보다 시간을 우선하지 않는다.

## 확인한 결과

- 기존 기록 없이 첫 달 사건과 `wanderer` 엔딩 경로를 새로 탐색하고 등록·재개방·저장 복원 검사를 통과했다.
- 기존 `success` 경로는 콘텐츠의 엔딩 검술 조건을 60으로 변경하면 실패한다. 변경된 콘텐츠에서 대체 경로를 찾아 저장 복원까지 통과했고 원본 파일은 바뀌지 않았다. 검사는 임시 복사본에서 수행했다.
- 기존 성공 기록을 참고한 `knight` 목표 탐색도 현재 스냅샷으로 재검증했다.
- Qt 실제 컨트롤로 사건/엔딩 선택 → 탐색 → 등록 → 전체 검사, 실패한 원본 선택 → 대체 탐색 → 별도 등록을 검증했다.
- 새로 발견한 `wanderer` 경로의 활동·선택을 실제 Windows 플레이어 컨트롤로 재현했다. UI 탐색 명령과 자동 대본 진행을 포함한 별도 세션의 상태를 비교했고, 중간 저장 복원 및 새 프로세스 불러오기가 통과했다. GUI에서 생성되는 명령열은 화면 이동과 중복 일정 적용 생략 때문에 탐색 명령열과 완전히 같지는 않다.
- 실제 사용자 파일럿에는 Qt UI로 `auto-friendship`을 등록했다. 관계 사건 시작까지 4명령, 저장 복원 2회가 통과했다. 기존 세 엔딩 기록은 보존했다.

검증 근거: `docs/evidence/goal-search/`의 `search-and-registration.json`, `alternative-regression.json`, `gui-verification.json`, `native-verification.json`, 화면 캡처.

## 재검증

```powershell
npx tsc -p tsconfig.json
node --test tests/analysis/goal-search.test.mjs tests/analysis/goal-routes.test.mjs tests/analysis/analysis.test.mjs tests/qt-studio/service.test.mjs
# 위 탐색 검증이 생성한 증거 경로의 발견 결과를 실제 플레이어로 재현
node --test tests/native-player/goal-search.test.mjs
node scripts/check-goal-routes.mjs projects/starlight-three-months
```

Qt 통합 테스트 `goalSearchAndRegister`에는 `RAISING_SEARCH_PROJECT`로 별도 파일럿 복사본을 지정한다. 같은 복사본에서 테스트가 생성한 ID를 다시 등록하지 않도록 실행마다 새 복사본을 사용한다. 기존 사용자 창/프로젝트에는 실패 재현용 변경을 적용하지 않는다.


경로의 시각적 비교와 단계 재생은 [목표 경로 그래프와 단계 비교](goal-route-comparison.md)를 참고하세요.
