# 6단계: 다인 전투·탐험·성장

2026-10-14. Windows Qt 편집기와 네이티브 플레이어에서 구현·검증한 첫 버전이다.

## 실행과 제작

저장소 루트의 `start-party-tactics.cmd`로 `tests/fixtures/projects/party-tactics-lab`을 연다. 편집기는 `dist/qt-studio-tactics/RaisingStudioQt.exe`, 플레이어는 `dist/native-player-tactics/RaisingPlayer.exe`다. 기존 편집기 출력 폴더와 사용자 프로젝트는 교체하지 않았다.

디자인 메뉴의 **다인 전투 · 탐험 · 성장…**에서 다음을 편집한다.

1. 전투원: ID·표시 이름·캐릭터 연결·진영·제어 방식·행/열·능력치·기술 목록. 선택적으로 최대 HP/공격/방어/속도를 기존 캐릭터 속성 ID에 연결한다.
2. 기술과 상태: 적/전열 적/아군/자신/전체 대상, 피해·회복·상태 부여, 명중률, 시전 턴, 재사용 대기, 지속 피해·회복·공격/방어 보정·기절.
3. 전투: 참가자, 세미콜론으로 구분한 적 웨이브, 경험치·아이템·일반 효과 보상.
4. 탐험 연결: 기존 탐험의 노드·연결·전투·퇴장 여부와 진입 조건. 상세 조건은 기존 규칙 편집기를 사용한다.
5. 의뢰와 성장: 기존 의뢰에 전투 완료 조건을 연결하고 경험치 기준·레벨 상한·레벨별 능력 증가를 설정한다. 새 의뢰는 기존 의뢰 제작 도구에서 만든다.

화면 배치를 선택하면 일반 화면·행동·전투 위젯으로 준비실과 전투 HUD를 만든다. 이후 기존 화면 캔버스에서 수정할 수 있다. 이미 생성한 샘플을 수정할 때는 화면 배치를 다시 선택하지 않는다. 대화상자 저장은 초안에 반영하고, 프로젝트 저장으로 디스크에 기록한다. 실행 취소·다시 실행 및 다시 열기를 검증했다. ID 참조와 규칙 오류는 공통 검증 서비스가 검사한다.

## 샘플 플레이 순서

1. 플레이를 시작하고 시장에서 연습용 검을 구매한다.
2. 집에서 새 탐험 준비실로 이동한다. Vanguard에게 검을 장착하고 첫 탐험 의뢰를 수락한다.
3. 탐험 출발을 확인한다. 명성 조건이 부족한 봉인된 길은 막혀 있고, 공터로 이동하면 전투가 시작된다.
4. Mage의 Spark를 선택하고 대상을 선택한다. 시전 중 F5로 저장하고, 다음 행동 후 F9로 불러와 같은 시점으로 돌아오는지 확인한다.
5. Vanguard의 Strike/Guard, Mage의 Spark/Venom/Mend를 사용해 두 웨이브를 완료한다.
6. 입구로 돌아와 탐험을 마치고 의뢰 보상을 수령한다. 성장·아이템·장비와 저장 복원을 확인한다.

## 규칙과 호환성

`project.systems.tactics`와 `state.systems.tactics`는 선택 사항이다. 기존 `systems.battle`의 1대1 전투와 일정·저장 계약은 유지한다. 탐험 노드의 `encounterId`가 새 전투를 시작하며 기존 `enemyId`와 동시에 지정할 수 없다. 신규 명령은 `tacticsAction`, `tacticsEquip`, `tacticsUnequip`, `tacticsFlee`다.

속도, 행, 열, ID 순으로 턴 순서를 결정한다. 전열 대상은 살아 있는 적 중 가장 앞선 행으로 제한한다. 시전·대기·상태 지속 시간은 전투원 턴 기준이며 게임 달력과 별개다. 상태 재적용은 지속 시간을 갱신한다. 현재 AI는 가능한 첫 기술과 결정적인 대상 순서를 사용한다.

웨이브 사이에 아군의 남은 HP를 유지하고, 모든 웨이브 승리 시 경험치·보상·의뢰를 처리한다. 패배와 철수는 승리 보상을 지급하지 않고 기존 진행 상태로 복귀한다. 저장은 RNG·행동 기록·시전·상태·웨이브·장비·성장을 보존하며 재생 검증을 거친다.

전투 능력치는 연결한 캐릭터 속성(없으면 공용 속성), 성장과 장비 보정으로 계산한다. 전투 HP와 성장 수치는 생활 능력치를 직접 덮어쓰지 않는다. 장비 수량은 기존 공용 소지품에서 예약하며 기존 주인공과 새 전투원의 중복 장착을 막는다. 캐릭터 개인 소지품에서의 장비 소비는 이번 범위에 포함하지 않는다.

## 검증 증거

- 실제 Qt 위젯으로 기존 `data-ui-lab` 복사본에 전투원·기술·상태·웨이브·탐험 분기·의뢰를 작성했다. 초기 폴더 복사와 GUI 제작을 구분한다.
- Qt 제작 저장/다시 열기/실행 취소 및 편집기 플레이 실행 테스트 2건 통과.
- `tests/native/tactics.test.mjs` 5건: TS/C++ 결과 일치, 시전 중 저장·재생, 장비 예약/해제, 웨이브·성장·의뢰, 잘못된 대상/턴/참조, 패배·철수·독·방어·회복·기절·명중 실패, 저장 변조 거부.
- `tests/native-player/tactics.test.mjs` 1건: 실제 네이티브 입력으로 구매→준비→탐험→전투→보상 및 새 프로세스 불러오기. 구형 런타임 내보내기 거부도 검증했다.
- 기존 일정·탐험·전투·UI 회귀 27건과 새 플레이어의 기존 계층·데이터 UI 실제 플레이 2건 통과. 합계 JavaScript 테스트 35건 통과.
- 이미지·플레이 보고서·저장 파일: `docs/evidence/tactics/`. 핵심 결과는 `core-verification.json`, `verification.json`, `editor-play-report.json`이다.
- 랜덤 자동 플레이 8회(seed 42, 회당 최대 400명령)를 완료했고 새 전투 행동·철수 경로를 관측했다. 2회는 게임 종료, 6회는 명령 한도에 도달했다. `analysis-smoke.json`에 기록했으며 완주율이나 모든 경로의 도달 가능성을 보증하는 결과는 아니다.

## 지원 범위와 남은 작업

이번 버전은 턴제, 아군 최대 8명, 웨이브당 적 최대 16명, 최대 20웨이브를 지원한다. 전투 로그는 최근 200줄, 자동 턴 처리는 512회로 제한한다. 임의 AI 스크립트·공간 이동 전술·실시간 전투는 구현하지 않았다.

새 콘텐츠는 `party-tactics-v1` 런타임 기능을 요구한다. Windows 네이티브 실행을 검증했으며, 해당 기능이 없는 웹/구형 런타임 내보내기는 오류로 차단한다. 모바일·콘솔 실기기와 웹 렌더러 지원 완료를 의미하지 않는다. 대량 랜덤 플레이는 경로 관측이며 모든 엔딩의 도달 가능성 증명이 아니다.
