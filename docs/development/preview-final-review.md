It downloads the candidate artifacts, verifies hashes, installs to a fresh folder, removes system Node/Qt paths from application tests, exercises real Qt creation/edit/export, native save/restore, uninstall preservation and the extracted portable package. It also runs all three advanced-language widget tests.

The small hash-pinned validation kit is a temporary draft asset, not part of the user installer/ZIP. After validation, preserve it in the CI evidence artifact and remove it from the release's download list. The installer includes corresponding QtBase sources for the kit's LGPL QtTest/offscreen libraries. Recreate/re-upload the matching kit if repeating the workflow after removal.

GitHub documents that standard hosted runner jobs receive a [new VM](https://docs.github.com/en/actions/concepts/runners/github-hosted-runners). The runner still has preinstalled developer software; removing runtime paths verifies application independence, but does not reproduce a consumer Windows 11 installation or its SmartScreen/Smart App Control policy. No such certification is claimed.

## Owner decision: signing

No signing key, certificate, publisher identity or paid service is configured. The owner must choose either an explicitly **unsigned limited preview**, or a signed distribution using a trusted code-signing service/certificate. Do not self-sign and describe it as a trusted publisher signature. Signing changes hashes, so signing must precede final checksum generation and artifact verification. Timestamp the trusted signature and sign both application executables and installer as appropriate.

Microsoft documents that [SmartScreen reputation is separate from signing](https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation), and [Smart App Control may block unsigned apps](https://support.microsoft.com/en-us/windows/security/smart-app-control-frequently-asked-questions). A signed first release is not guaranteed to avoid all reputation prompts. Never instruct users to disable security protections to satisfy the release checks.

The draft is not published automatically. Final release readiness remains false until the signing choice and technical evidence are recorded; an independent native-speaker review and consumer Windows manual acceptance remain disclosed quality limitations rather than fabricated passes.
