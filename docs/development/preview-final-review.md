# Preview publication review

Release candidate: `0.1.0-preview.3`. Earlier preview packages remain local/review artifacts and are not the publication candidate.

## Sample media

The reviewed binary template inventory contained 18 PNG copies of seven image-tool-generated designs. Prompts/provenance existed, but no explicit sample redistribution grant was recorded. Rather than assert rights that are not established by those records, the binary packager replaces those copies with original geometric designs generated by MIT source code. The original workspace, source files and existing user projects are preserved.

`config/release-sample-media.json` pins target paths and original hashes. `scripts/release-sample-media.mjs` writes a per-image license/hash ledger and verifies all media in packaged examples. Additional, modified or missing images fail the audit. No bundled audio/video requires an additional sample license. Noto Sans KR/JP retain their separate OFL notices. Qt DLLs remain replaceable, and four matching Qt source archives are distributed with the LGPL notices. See [sample media](release-sample-assets.md) and [dependency review](preview-license-review.md).

## Translation review

Both catalogs contain non-empty English/Japanese translations with no remaining Korean text in translated columns; placeholder checks pass. Review covered destructive actions, preservation of user files, cancellation, partial approvals, restoration and the distinction between an unobserved route and proven unreachability. The Japanese spreadsheet instruction `結末` exposed a missing accepted keyword; it now maps to the existing ending type without changing stored IDs.

The actual Qt editor test covers three languages, nine advanced tools, font coverage, measured label widths, opaque diagnostic parameters and an actual Node-service error sent through the editor bridge. This is automated widget testing plus model-assisted language review, not independent human/native-speaker certification.

## Installation evidence

The local host does not have Windows Sandbox. The `Preview Windows installation` workflow uses a fresh GitHub-hosted Windows Server 2022 VM, not the developer's local checkout state. It downloads the candidate artifacts, verifies hashes, installs to a fresh folder, removes system Node/Qt paths from application tests, exercises real Qt creation/edit/export, native save/restore, uninstall preservation and the extracted portable package. It also runs all three advanced-language widget tests.

The small hash-pinned validation kit is a temporary draft asset, not part of the user installer/ZIP. After validation, preserve it in the CI evidence artifact and remove it from the release's download list. The installer includes corresponding QtBase sources for the kit's LGPL QtTest/offscreen libraries. Recreate/re-upload the matching kit if repeating the workflow after removal.

GitHub documents that standard hosted runner jobs receive a [new VM](https://docs.github.com/en/actions/concepts/runners/github-hosted-runners). The runner still has preinstalled developer software; removing runtime paths verifies application independence, but does not reproduce a consumer Windows 11 installation or its SmartScreen/Smart App Control policy. No such certification is claimed.

## Owner decision: signing

No signing key, certificate, publisher identity or paid service is configured. The owner must choose either an explicitly **unsigned limited preview**, or a signed distribution using a trusted code-signing service/certificate. Do not self-sign and describe it as a trusted publisher signature. Signing changes hashes, so signing must precede final checksum generation and artifact verification. Timestamp the trusted signature and sign both application executables and installer as appropriate.

Microsoft documents that [SmartScreen reputation is separate from signing](https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation), and [Smart App Control may block unsigned apps](https://support.microsoft.com/en-us/windows/security/smart-app-control-frequently-asked-questions). A signed first release is not guaranteed to avoid all reputation prompts. Never instruct users to disable security protections to satisfy the release checks.

The draft is not published automatically. Final release readiness remains false until the signing choice and technical evidence are recorded; an independent native-speaker review and consumer Windows manual acceptance remain disclosed quality limitations rather than fabricated passes.
