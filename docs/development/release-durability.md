# 장편 내구성 · 출시 품질 검증

규칙 제작실 도입 후 2026-10-18 재검증은 [4단계 장편 내구성](rule-durability.md)에 별도로 기록한다. 아래 수치는 이전 실행 결과다.

2026-10-15. 기존 프로젝트·저장 형식은 유지한다. 이번 결과는 Windows 개발 PC와 Chromium에서 얻은 값이며 모바일 실기기·콘솔 인증 결과가 아니다.

수치·표본 수·기능 선언을 담은 [측정 기록](../archive/durability-results.json)을 함께 보관한다. 원본 프로젝트와 실행 이미지 대신 개인정보·게임 에셋이 없는 집계 결과만 소스에 포함했다.

## 실제 측정과 개선

`npm run benchmark:durability`는 공개 `academy-journey`를 `.cache/durability`로 복사해 **합성** 대형 프로젝트를 만든다. GUI로 사람이 제작한 콘텐츠라고 간주하지 않는다. 기본 추가 데이터는 사건 1,000개, 엔딩 1,000개, 인물 1,000개, 아이템 7,000개다. 기존 콘텐츠를 포함한 카탈로그는 10,073개다.

| 작업 | 측정 결과 |
|---|---:|
| 카탈로그 검색, 30회 p95 | 약 12ms |
| 정렬, 10회 p95 | 14.2 → 3.3ms |
| 문서 교체 + 실행 취소, 5회 p95 | 약 47ms |
| 의미 검증, 3회 p95 | 약 122ms |
| 변경 없는 저장, 각 1회 | 11.06 → 6.17초 |
| 변경을 포함한 저장, 1회 | 5.95초 |
| 변경 저장 후 다시 열기, 1회 | 3.78초 |
| 실제 Qt 프로젝트 열기 | 4.23초 |
| Qt 정리 창의 3,039개 문서 검색 | 8ms, 해당 사건 1개 표시 |

저장 검사에서 독립적인 파일 읽기를 최대 8개로 제한해 병렬 실행한다. 모든 작업이 끝난 후 실패를 반환하며, 저장 전후 외부 파일 변경·잠금·바이트 검사는 생략하지 않는다. 문서를 매번 선형 검색하던 저장 처리는 파일별 Map을 사용한다. 카탈로그는 Collator를 재사용하고 진단 배열의 반복 복사를 제거했다.

최종 프로세스 RSS는 약 537 MiB였다. 순간 최대 메모리나 누수 판정은 아니며, 전체 기록은 `final-10000.json`에 있다. 검색/편집/검증/취소 예산 초과 시 벤치마크는 0이 아닌 종료 코드를 반환한다. 저장·열기는 표본 1~3회인 관찰값이며 제품 성능 보장이 아니다.

대형 프로젝트에서 잘못된 아이템 참조의 정확한 위치 검출 → 실행 취소 → 실제 변경 저장 → 재개방도 검증했다. 목표 경로 탐색은 2초 예산에서 13개 상태를 탐색하고 `not-found`로 끝났다. 이는 **도달 불가능 판정이 아니다**. 중단 요청은 즉시 반환했다. 더 긴 탐색과 수만 개의 상호 연결 사건은 후속 부하 시험이 필요하다.

96개월 별도 시험은 1,250개 명령으로 기본 엔딩까지 진행하고 10개 지점에서 저장·불러오기를 수행했다. 매 지점과 엔딩에서 직접 진행한 실행과 전체 상태·명령·난수 상태가 같았다. 최종 저장은 48,196바이트다. 수십 MB 저장이나 여러 시간 GUI를 사용하는 누수 시험을 대신하지 않는다.

## 콘텐츠 업데이트 후 저장 이전

편집기 **파일 → 콘텐츠 업데이트 · 저장 이전 / 복구…**에서 다음을 지정한다.

1. 저장을 만들 당시의 이전 프로젝트 폴더.
2. 업데이트된 새 프로젝트 폴더. 현재 초안 대신 **디스크에 저장된 콘텐츠**를 사용한다.
3. 원본 저장 파일과 아직 존재하지 않는 새 저장 경로.
4. `검사·비교` 후 변경 위치·이전 값·새 값을 검토한다.
5. `검토한 결과를 새 파일로 저장`을 누른다.

이전 프로젝트로 원본 저장의 구조·버전·명령 재현·상태를 먼저 검사한다. 새 프로젝트에서는 동일 초기 조건과 명령을 처음부터 재현한다. 수정된 비용·효과·엔딩 때문에 결과가 달라지면 비교 표에 표시한다. 명령이 더 이상 실행되지 않으면 `/commands/N`과 원인을 반환한다. ID를 추측해 치환하거나 기존 상태에 새 지문만 붙이지 않는다.

적용 시 원본·목표 콘텐츠·결과 저장의 SHA-256에 연결된 검토 토큰을 다시 확인한다. 원본이나 콘텐츠가 바뀌면 다시 검토해야 한다. 이 토큰은 변경 확인용이며 사용자 인증 서명이 아니다. 원본과 기존 출력 파일은 덮어쓰지 않는다. 임시 파일을 동기화하고 배타적인 하드 링크로 새 파일을 게시한다. 하드 링크 미지원 파일시스템에서는 실패하고 원본을 보존한다.

기존 로더의 `CONTENT_MISMATCH` 보호는 그대로다. 같은 게임과 지원하는 저장/코어 버전만 이전할 수 있다. 이전 프로젝트를 잃어버린 저장, 삭제된 필수 명령, 변경된 코어 실행 규칙은 자동 복구하지 않는다. 기존 릴리스의 프로젝트·에셋·플러그인 잠금 파일을 함께 보관해야 한다.

연출·플러그인 재생 위치가 있는 저장은 자동 이전하지 않는다. 명시적으로 초기화를 선택하면 게임 진행은 재현하고 연출 저장 부분을 제외하며, 보고서에 이를 표시한다. 플러그인 내부 상태의 새 규격 변환이나 수집 도감 프로필 이전은 별도 작업이다. 차이가 2,000개를 넘으면 보고서는 잘림을 표시하고 GUI 승인을 막는다.

복구는 보관한 이전 프로젝트에서 **원본 저장**을 여는 방식이다. 이번 시험에서 원본 바이트 보존과 재개방, 덮어쓰기 거부, 변조·잘못된 게임·삭제된 활동·취소·검토 토큰 불일치 차단을 확인했다. 실제 Windows 플레이어에서도 이전된 저장의 F9 로드 → F5 저장 → F9 재로드가 동일했다. 별도로 네이티브 자동 저장의 손상/누락 시 백업 복구와 두 파일 모두 손상 시 거부를 확인했다.

CLI도 같은 서비스를 사용한다.

```powershell
npm run save:migrate -- --from "OLD_PROJECT" --to "NEW_PROJECT" --save "ORIGINAL_SAVE" --report "NEW_REPORT.json"
# 보고서의 approval 값을 검토한 뒤 사용한다. 원본 경로를 출력으로 사용하지 않는다.
npm run save:migrate -- --from "OLD_PROJECT" --to "NEW_PROJECT" --save "ORIGINAL_SAVE" --output "NEW_SAVE.json" --approve "REPORT_APPROVAL"
```

필요할 때만 `--reset-presentation`을 두 실행에 동일하게 지정한다. 보고서 파일도 기존 파일을 덮어쓰지 않는다. 일반 로더는 이전된 저장도 다시 재현 검사한다.

## 웹 출시 품질

공유 React 플레이어에 어느 화면에서나 열 수 있는 환경 설정을 추가했다.

- 소리 켜기, 배경음·효과음 개별 음량. 음량 변경으로 배경음이 처음부터 다시 시작되지 않는다.
- 기기 내 음량·고대비·장식 움직임 줄이기 설정 보관. 저장소를 사용할 수 없거나 값이 잘못되어도 기본 설정으로 실행한다.
- 키보드 포커스 표시, 설정 대화상자의 포커스 격리와 Escape 닫기/원래 버튼 복귀, 44px 조작 영역, 좁은 화면 스크롤과 안전 영역 여백.
- 설정창을 열거나 탭이 숨겨지면 일정 자동 진행·타임라인 tick을 보류한다. 숨김 상태의 일회성 효과음은 버리고 배경음은 기존 위치에서 다시 재생한다.
- 설정 UI는 한국어·영어 문구를 제공한다. 기존 게임 번역 제작·폴백 및 연출 데이터 검사를 회귀 검증했다.
- 월 일정 설명도 고정된 3회 대신 프로젝트의 실제 일정 수를 따른다.

Chromium에서 실제 WAV 디코딩·재생 상태, 음량 반영, 숨김 이벤트에 따른 일시정지/복원, 설정 후 본편 상태 유지, 새로고침 후 설정 유지, 다운로드/업로드 저장과 네이티브 상태 일치를 검사했다. 숨김 시험은 visibility 이벤트를 주입한 통합 시험이며 모바일 OS 중단 시험이 아니다. 390×844 터치 에뮬레이션과 844×390 작은 가로 화면도 확인했다.

이 설정은 브라우저/React 플레이어의 변경이다. SDL 플레이어에 동일한 설정 메뉴가 생긴 것은 아니다. 게임 대사·전체 기본 UI 번역, 모든 플러그인의 움직임 억제, 스크린리더 전체 탐색, 큰 글씨 재배치, 게임패드 재매핑, 기기별 오디오 코덱 검증은 남아 있다. 장식 CSS 움직임 억제는 게임의 애니메이션 타이밍·상태 전이를 변경하지 않는다.

## 플랫폼별 현재 범위

`npm run report:platforms`는 선택한 빌드의 capabilities.json과 해시에서 기능표를 생성한다. **선언된 기능과 실기기 검증을 구분**한다. 이번 빌드의 Windows 선언은 35개, 웹은 20개다. 기존 내보내기의 미지원 기능 차단은 유지했다.

| 기능 / 배포 | Windows SDL + Qt | 웹 Chromium | Android / iOS |
|---|---|---|---|
| 일정·공통 규칙·행동 흐름·데이터 UI | 기존 지원, 회귀 확인 | 기존 지원, 실제 플레이 확인 | 실기기 미검증 |
| 기본 부품·앵커·반응형·계층·활동 연출 | 기존 지원 | 기존 지원, 작은 화면 확인 | 웹 터치 에뮬레이션만 확인 |
| 다인 시간 세션·개인 데이터·다인 전투 | 선언/기존 구현 | 아직 내보내기 차단 | 미검증 |
| 중첩 UI 구성·연출 시퀀스 | 선언/기존 구현 | 아직 내보내기 차단 | 미검증 |
| 편집 가능한 도감·회상·선택 분기 | 선언/기존 구현 | 아직 내보내기 차단 | 미검증 |
| 저장 이전 비교 제작 도구 | Qt + CLI, 실제 플레이 확인 | 변환된 기본 저장의 공통 계약 사용 | 실기기 미검증 |
| 새 음량·접근성 설정 | React 플레이어만 | 이번에 추가·검증 | 모바일 브라우저 에뮬레이션 |
| Android 패키지 | 해당 없음 | 해당 없음 | 준비 단계 4개 검사, 실제 APK 빌드 아님 |

Android 시험은 가짜 SDK로 준비 작업의 파일 목록·빌드 ID·라이선스·비공개 파일 제외를 검사한다. 이 PC에는 기본 Android SDK 경로와 adb가 확인되지 않았다. iOS는 macOS/Xcode와 실기기 빌드가 필요하다. macOS/Linux 독립 플레이어 배포도 이번에 검증하지 않았다. Switch·PlayStation·Xbox는 승인된 SDK·개발기 확보 전이므로 빌드·인증 완료로 표기하지 않는다.

다음 우선순위는 (1) 이식 가능한 UI 구성/시간 세션/도감부터 웹 기능 동등성 확보, (2) Android SDK와 실기기에서 설치·복원·터치·오디오 중단 검증, (3) 전체 UI 번역·스크린리더·입력 재매핑, (4) 수만 건 연결 콘텐츠와 장시간 메모리·저장 업데이트 시험이다. 콘솔 검증은 SDK 접근 이후 별도 트랙으로 진행한다.

## 실행·증거

새 Qt 빌드: `dist/qt-studio-durability/RaisingStudioQt.exe`.
새 웹 빌드: `dist/web-durability`.
편집기에서 이 웹 빌드를 내보내려면 `RAISING_WEB_PLAYER_RUNTIME`에 해당 절대 경로를 지정한다. 기존 실행 중 빌드는 교체하지 않았다.

```powershell
npm run build:headless
npm run test:durability
npm run benchmark:durability
npm run report:platforms
# Qt UI 시험용 별도 프로젝트·원본 저장 생성 후 실행
node scripts/prepare-migration-ui.mjs
$env:QT_STUDIO_OUT='dist/qt-studio-durability'
node scripts/test-qt-studio.mjs saveMigrationReview
# 대형 GUI 시험은 optimized-10000.json의 테스트 프로젝트를 사용한다.
node scripts/test-qt-studio.mjs durabilityLargeProject
$env:WEB_OUT='dist/web-durability'
node --test tests/journey/web.test.mjs
node --test tests/native-player/migrated-save.test.mjs
```

대형 GUI 시험을 새 환경에서 재현하려면 먼저 `DURABILITY_REPORT=.cache/durability/optimized-10000.json`으로 벤치마크를 실행한다. 이전 저장 UI 시험을 다시 실행할 때는 준비 스크립트가 새 경로를 생성한다.

로컬 증거: `.cache/durability/{baseline-10000,optimized-10000,final-10000,qt-large-project,long-campaign,native-migration-result,platform-support}.json`, `migration-review.png`, `migration-published.png`, `qt-large-search.png`. 웹 증거는 `.cache/journey-web-ui/{mobile-settings,touch-settings,wasm-relationship-event,landscape-small}.png`다. 자동 생성 프로젝트·저장·이미지 원본은 공개 소스에 추가하지 않았다.
