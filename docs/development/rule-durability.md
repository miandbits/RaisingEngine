# 4단계: 규칙 제작실 이후 장편 내구성

2026-10-18 실행. 과거 결과와 분리해 공개 예제의 복사본으로 검사했다. 사용자 첫 달 프로젝트, 실행 중 창, 저장 파일은 변경하지 않았다. 대량 콘텐츠는 **스크립트 생성 부하 표본**이며, 편집기만으로 제작한 게임이라고 표시하지 않는다. 실제 Qt 폼에서 수행한 수정·저장·재개방은 별도로 기록한다.

## 범위와 발견한 문제

- 같은 장비에서 규칙 없는 1만 건과 규칙 있는 1만 건을 비교했다. 후자는 패키지 16개, 진행 인스턴스 32개, 연결 사건 256개에 조건·효과 호출 각 256개를 추가했다. 모든 대량 사건이 규칙을 호출하는 표본은 아니다.
- 규칙 확장 후 일반 참조 오류가 상위 배열 항목 위치로 뭉개졌다. 이제 원본 필드까지 위치를 보존한다. 여러 효과로 확장되어 뒤 항목의 인덱스가 이동해도 원본 위치를 찾고, 생성 행동의 오류는 원래 진행 인스턴스로 돌아간다.
- 이미 취소한 저장 이전도 원본 저장 재생을 먼저 시작했다. 파싱·재생 전에 취소를 검사하고 원본 검증 직후에도 다시 확인한다. 실행 중인 동기 네이티브 호출을 중단하는 기능은 아니다.
- 기존 부하 생성기는 5만 건까지 받지만 고정 비율로 물품을 늘려 데이터 계약을 위반했다. 이제 지원 범위를 100~19,000건으로 명시하고 물품·문서 제한에 맞춰 분배한다. 엔진의 제한을 몰래 늘리지 않았다.

## 저장 업데이트와 복구

규칙 `1.0.0 → 1.1.0`, 수련 비용 `3 → 4`, 효과 `12 → 15`를 바꾼 별도 릴리스로 검증했다.

- 일반 불러오기는 계속 `CONTENT_MISMATCH`로 거부한다.
- 명시적 이전은 원래 콘텐츠로 저장을 검증한 뒤 같은 명령을 새 콘텐츠에서 재생한다. 능력치 +3, 자원 -1의 차이를 검토한 후 새 파일로 승인한다.
- 새 저장에서 진행을 계속한 뒤 다시 저장·복원해 명령·RNG·상태 전체가 같은지 비교한다.
- 삭제된 행동과 비용 부족은 `/commands/1`에서 `MIGRATION_REPLAY`로 실패한다. 기존 파일 덮어쓰기와 오래된 승인은 거부한다. 원본 저장은 바이트가 동일하고 원래 콘텐츠에서 복원 가능하다.
- 240개월 규칙 적용 캠페인: 3,122명령, 16회 중간·엔딩 저장, 마지막 기간 719, `ordinary` 엔딩. 계속 실행한 세션과 복원한 세션의 상태·명령·관계 변화·RNG가 모두 일치했다.

연출·플러그인 상태의 임의 마이그레이션은 이번 범위에서 추가하지 않았다. 기존의 명시적 연출 초기화 승인 규칙을 유지한다. 원본 릴리스가 없거나 기록 명령 자체가 새 규칙에서 불가능하면 자동 복구를 보장하지 않는다.

## 측정 방법과 한계

서비스 검색 30회, 정렬 10회, 일반 편집·되돌리기 5회, 규칙 편집·되돌리기 10회, 검증 3회, 열기 3회를 측정한다. 저장·스냅샷·탐색은 각 1회다. 최종 수치와 실제 Qt 검증 결과는 결과 JSON (historical internal evidence; not distributed)에 기록한다.

| 작업 | 1만 건 기존 콘텐츠 | 1만 건 + 규칙 | 1.8만 건 + 규칙 |
|---|---:|---:|---:|
| 검색 p95 | 11.91ms | 11.95ms | 19.63ms |
| 편집·되돌리기 p95 | 56.68ms | 57.62ms | 124.55ms |
| 규칙 편집·되돌리기 p95 | 해당 없음 | 66.15ms | 137.35ms |
| 검증 p95 | 241.63ms | 404.06ms | 886.11ms |
| 변경 저장 1회 | 6.87초 | 8.23초 | 22.57초 |
| 재개방 1회 | 4.70초 | 5.31초 | 13.90초 |
| 2초 예산 탐색 실제 종료 | 2.10초 | 2.63초 | 4.86초 |

카탈로그는 원본 콘텐츠를 포함해 각각 10,073 / 10,073 / 18,073항목이다. 큰 표본은 사건·결말·인물 각 2,667개와 물품 9,999개를 추가했다. Qt의 1만 건 프로젝트 열기는 6.06초, 3,039문서 중 필터 적용은 9ms였다. 실제 폼에서 이름·성장량을 수정한 뒤 저장·재개방했고, 저장 이전 승인과 원본 덮어쓰기 거부가 통과했다. 이전한 저장의 Windows F9→F5→F9 결과도 전체 상태와 명령 기록이 동일했다.

저장 호환성 18개, 검증·규칙 계약 56개, Qt 시작/종료 포함 4개 검사가 통과했다. 샌드박스에서 하드링크·심볼릭 링크를 만들지 못한 검사는 권한 있는 동일 임시 경로 실행으로 별도 확인했다. 공개 콘텐츠 경계 검사도 통과했다. 저장·재개방 시간은 대화형 검색·편집 p95 예산에 포함하지 않으므로, 예산 위반 없음이 저장 지연 해결을 뜻하지 않는다.

- 목표 탐색의 2초 예산은 동기 명령 한 개의 작업 중간을 끊는 하드 실시간 제한이 아니다. `not-found`는 예산 내 미발견이며 도달 불가능 판정이 아니다.
- 1만 건 표본의 강제 GC 후 재개방·검증 6회 힙 관측은 단기 추세다. 피크 RSS나 수시간 누수 없음의 증거로 사용하지 않는다.
- 3만 건 고정 비율 표본은 `/gameplay/items`의 `maxItems: 10000`으로 거부됐다. 엔진 문서 수 상한도 10,000개다. 표본 종류를 바꾸면 총 카탈로그 수는 달라지므로 이를 모든 콘텐츠 합계 1만 건 제한으로 해석하지 않는다.
- 규칙 API의 기존 제한(패키지 64개, 진행 인스턴스 64개, 확장 100,000노드/깊이 32)도 유지한다. 이번 표본을 초과하는 제작 규모는 추가 측정이 필요하다.
- 대규모 전체 저장·재개방의 수초 지연은 남아 있다. 증분 검증·저장, 별도 규칙 의존성 캐시, 긴 탐색의 중단 응답 개선은 후속 최적화 대상이다.

## 재현

```powershell
npm run build:headless
npm run test:rule-contracts
npm run test:durability
npm run benchmark:durability
npm run benchmark:rule-durability
$env:DURABILITY_COUNT='18000'
npm run benchmark:rule-durability
```

Qt 검증은 전용 출력 폴더와 offscreen을 사용한다. `test:durability`가 `.cache/durability/stage4-migration-ui.json`에 새로운 이전 시험 경로를 기록한다. 각 실행은 별도 프로젝트를 만들며 기존 증거를 덮어쓰지 않도록 결과 경로를 지정할 수 있다.

```powershell
$env:QT_STUDIO_OUT='dist/qt-studio-rule-durability'
$env:BUILD_JOBS='2'
node scripts/build-qt-studio.mjs
$env:QT_QPA_PLATFORM='offscreen'
$env:QT_PLUGIN_PATH='C:/Qt/6.10.1/mingw_64/plugins'
$env:QT_DURABILITY_EVIDENCE='.cache/durability/stage4-qt'
$env:QT_DURABILITY_REPORT='.cache/durability/report-rules-10000.json'
$env:QT_MIGRATION_FIXTURE='.cache/durability/stage4-migration-ui.json'
node scripts/test-qt-studio.mjs durabilityLargeProject saveMigrationReview
node scripts/verify-durability-player.mjs
```

Qt 시험은 대규모 검색, 진행 이름·입력값 폼 편집, 저장·재개방, 이전 차이 검토·승인·원본 덮어쓰기 거부를 수행한다. 플레이어 시험은 검토 후 생성된 저장을 별도 슬롯으로 복사해서 숨김 Windows 플레이어의 F9→F5→F9와 전체 상태를 비교한다. 창을 전면에 띄우거나 사용자 입력을 보내지 않는다. 하드링크·심볼릭 링크 관련 검사는 실행 환경이 해당 파일 작업을 허용해야 한다.

GitHub Actions에도 `test:durability`를 추가했다. 로컬 전용 Qt/Windows 시험은 CI에서 실행했다고 주장하지 않는다.
