# 웹 플레이어의 부품 대상 연결

Qt에서 제작한 `tests/fixtures/projects/component-context`를 변경하지 않고 웹으로 내보낸다. React 표시는 Windows와 같은 부품 확장·대상 치환·조건 평가 계약을 사용하며, 시뮬레이션은 C++ Wasm에서 실행한다.

## 동작

- 각 카드에 연결한 캐릭터의 이름과 개인 능력치, 연결한 행동 이름, 활동별 문구를 표시한다.
- 조건은 해당 수행 캐릭터로 해석한다. 처음에는 검술 10인 소운의 행동만 비활성이고, 연화의 행동은 연화의 검술만 증가시킨다.
- `executeActorAction`과 `assignActivities`를 웹 컨트롤러에서 기존 상태 버전 검사와 명령 처리로 전달한다. 다른 캐릭터의 활동 배정은 유지한다.
- 캐릭터별 프로젝트의 일정 위젯은 인물별 선택·배정 적용·함께 실행을 제공한다. 카드에서 활동을 배정하면 일정 위젯도 갱신된다. 결과는 각 인물 이름과 함께 표시한다. 단일 캐릭터 프로젝트의 기존 월 일정은 유지한다.
- 게임 시작 전에는 활동 배정 버튼을 비활성화한다. 결과·사건·엔딩 등에서 사용할 수 없는 행동은 런타임 검사에 따라 비활성화한다.
- 연결된 문구는 명시적인 여백이 없으면 불필요한 기본 여백을 넣지 않는다. 작은 카드에 스크롤 화살표가 생기는 문제를 방지하며, 기존 연결 없는 문구의 기본 여백은 유지한다.

## 저장·불러오기

웹의 저장 버튼은 표준 JSON 파일을 다운로드한다. 불러오기 버튼에서 파일을 선택하면 검증 후 명령 기록으로 상태를 복원한다. 브라우저 내부 전용 저장 형식을 만들지 않았으며, 같은 콘텐츠의 네이티브 저장도 가져올 수 있다. 페이지를 새로고침해 세션을 새로 시작한 후에도 같은 저장을 불러올 수 있다.

## 재현

```powershell
npm run build:headless
npm run build:web
$env:RAISING_HEADED='1'
node --test tests/journey/component-context-web.test.mjs
```

Chrome 설치가 필요하다. `RAISING_WEB_RUNTIME`으로 별도 웹 빌드 경로를 지정할 수 있으며 기본값은 `dist/web`이다. 테스트는 공개 GUI 저장본을 실제 내보내기 서비스로 묶고 로컬 HTTP 서버와 Chrome을 실행한다. 클릭·선택·다운로드·파일 선택기로 게임을 조작한다. 게임 API로 명령을 몰래 주입하지 않는다. 읽기 전용 조회로 각 상태를 네이티브 코어의 같은 seed/명령 결과와 비교한다.

검사 항목:

- 시작 전 버튼 제한, 캐릭터별 이름·검술·활동 표현·행동 활성 조건.
- 기존 진행 버튼, 인물별 수동 활동 배정, 두 부품의 활동 배정, 다른 인물 배정 보존.
- 연화의 독립 행동, 소운의 조건 충족 후 행동, 공유 비용, 결과와 사건 선택, 6기간 후 엔딩.
- 실제 다운로드 파일의 네이티브 복원, 브라우저 업로드, 네이티브 저장 가져오기.
- 행동 직후·활동 결과·엔딩 저장, 새로고침 후 중간/엔딩 복원.
- 다인 일정이 기본 샘플 영역 안에 들어가는지와 브라우저 예외 발생 여부.

보고서는 `.cache/web-component-context/run-*/report.json`, 최근 결과 위치는 `.cache/web-component-context/evidence.json`, 화면 증거는 `output/playwright/component-context-web-*.png`에 생성된다. 기존 `test:journey:ui`에도 이 시험을 포함한다.

## 배포 기능표

새 웹 빌드는 `component-context-v1`, `roster-activities-v1`, `character-scoped-rules-v1`을 선언한다. 이에 따라 기존 Qt 편집기의 웹 내보내기도 이 샘플을 허용한다. 구형 런타임의 기능표를 우회하거나 호환성 검사를 제거하지 않는다. 실제 브라우저 확인은 Windows Chrome에서 수행했으며 다른 브라우저·모바일 검증은 별도이다.
