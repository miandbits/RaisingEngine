# 8단계: 자동 검증과 여섯 유형 제작 시험

2026-10-14. Windows Qt 편집기와 네이티브 플레이어에서 검증했다. 각 샘플은 한 달·두 기간·목표/대체 엔딩으로 구성한다. 장편 상용 게임의 콘텐츠 규모나 모든 규칙 조합을 검증했다는 뜻은 아니다.

## 사용 순서

1. 저장소 루트의 `start-genre-suite.cmd`를 실행한다. 자유 행동형 샘플이 열린다.
2. **디자인 → 완결 샘플 제작…**에서 유형, 제목, 초기 자금, 새로운 절대 경로를 입력한다. 기존 폴더는 덮어쓰지 않는다. 현재 프로젝트에 미저장 변경이 있으면 저장하거나 되돌린 뒤 생성하도록 안내해 초안을 보존한다.
3. 생성된 일반 프로젝트를 기존 화면 캔버스·속성·규칙 작업실에서 수정한다. 새로운 전용 게임 규칙이나 원작 에셋은 필요하지 않다.
4. **플레이**로 실행한다. 생활 공간에서 행동하고 일정 화면에서 두 기간을 진행한다. F5/F9 또는 저장/불러오기 버튼을 사용한다.
5. **디자인 → 제작 시험 검증…**에서 1~128회를 지정한다. 현재 초안으로 검사하며, 창을 연 뒤 초안이 변경되면 다시 열도록 안내한다. 결과는 프로젝트 `.studio/assurance/report-*.json`에 보존한다.
6. 대량 병렬 실행·목표 탐색·경로 지도·회차 재생은 기존 분석 창을 사용한다. 새 제작 시험 창은 상태·실패·취소·저장 재생과 명령 가능/거부 집계를 제공한다.

## 완결 샘플

`projects/genre-suite/<유형>`에 있다. Qt의 실제 템플릿 제작 창에서 제목과 자금 45를 설정하고 저장·재열기했다. 모든 콘텐츠를 빈 캔버스에서 수작업으로 만든 시험은 아니다.

| 폴더 | 목표 엔딩을 보는 흐름 | 공통 기능 |
|---|---|---|
| schedule | 두 기간 모두 훈련 | 월 일정, 능력치 조건 |
| free | 제작 행동 → 완료까지 진행 → 두 기간 진행 | 비용, 행동력, 시간 세션, 취소 |
| relationship | 대화 두 번 → 두 기간 진행 | NPC 관계와 관계 조건 |
| adventure | 출발 → 숲 안쪽 → 공격 → 입구 복귀 → 귀환 → 두 기간 진행 | 탐험, 전투, 보상 플래그 |
| roster | 두 기간 각각 주인공 훈련·동료 휴식 배정 | 개체별 속성과 활동 |
| pet | 먹이 두 번 → 두 기간 모두 훈련 | 개체별 행동과 속성, 비용 |

목표 미달 시 대체 엔딩으로 끝난다. 자유 행동의 완료까지 진행은 세 틱을 한 번에 진행한다. 펫 행동은 확인창 없이 즉시 실행되는 기존 개인 행동 계약을 따른다.

## 검사 구조

- `analysis-service/runner.ts`의 대상 ID를 포함하는 명령 후보를 자동 플레이와 제작 시험이 공유한다. 실제 코어 판정으로 실행 가능 여부와 거부 원인을 얻는다.
- `analysis-service/assurance.ts`는 명령 기록을 공통 런타임 서비스로 재실행한다. 중간 저장 인코딩·디코딩 후 남은 명령을 재생해 최종 상태와 난수 결과를 비교한다.
- 각 전이에서 이전 상태 불변, 버전 증가, 유한 수치, 속성 범위, 소지품 정수·비음수, 전투 HP 범위를 확인한다.
- 회차 중간 상태에서 명령 후보·거부 사유를 집계하고, 버전 충돌 거부와 원본 상태 보존을 검사한다. 진행 세션이 관측되면 별도 상태에서 취소도 검사한다.
- 실패에는 회차·명령 위치·종류·원인을, 거부 사례에는 실제 대상 명령과 사유를 최대 30종 기록한다. 엔딩별 명령 재생 증거도 보존한다.
- 기존 프로젝트에 필수 필드를 추가하지 않았다. 기존 로더·스키마·의미 검증·코어·저장 계약을 재사용한다.

## 검증 결과

| 유형 | 자동 회차 | 목표 엔딩 | 대체 엔딩 | 저장 복원 | 관측 세션 취소 |
|---|---:|---:|---:|---:|---:|
| 일정 | 128 | 64 | 64 | 128 | 0 |
| 자유 행동 | 128 | 45 | 83 | 128 | 28 |
| 관계 | 128 | 16 | 112 | 128 | 0 |
| 모험 | 128 | 19 | 109 | 128 | 0 |
| 다인 운영 | 128 | 4 | 124 | 128 | 0 |
| 펫 | 128 | 6 | 122 | 128 | 0 |

총 **768회 모두 완결**, **8,590개 상태 전이**, 저장 복원과 버전 충돌 거부 각각 768회를 확인했다. 후보를 무작위로 고르는 봇의 분포이므로 인간 플레이의 엔딩 확률이나 밸런스 추정치가 아니다.

- Qt 위젯 시험: 여섯 프로젝트 생성·저장·재열기, 편집기의 플레이 실행, 목표 엔딩, 각 유형 32회 제작 시험 결과 표시.
- SDL/RmlUi 실제 플레이: 여섯 유형 성공 경로, 월 중간 저장·변경·복원, 새 프로세스에서 엔딩 저장 복원. 자유 행동의 확인창 취소·세션 취소·복원, 모험의 전투 중 저장·승리·복원·재승리도 확인했다.
- 자금 0인 별도 시험: 비용 부족 거부, 대상·원인 기록, 원본 상태 보존.
- 기존 예제 5개와 캐릭터·시간·작업실·UI·전투·연출 프로젝트 6개, 총 11개가 마이그레이션 없이 로드·검증을 통과했다. 기존 분석의 결정성·목표 탐색·취소·병렬 실행·캐시 회귀도 통과했다.
- 제한 탐색은 6개 중 5개 목표 경로를 찾았다. 자유 행동형은 4,000 상태 제한으로 `not-found`였다. 무작위 회차(seed 47)와 실제 플레이에서는 도달했으므로 불가능 판정이 아니다.

## 증거와 재실행

`docs/evidence/genre-suite/`의 `summary.json`, `target-summary.json`, `compatibility.json`, `insufficient-resources.json`에 집계를 저장했다. `author-<유형>.png`는 실제 Qt 제작 창이다. 유형별 폴더의 `play-report.json`, `editor-play-report.json`, `fresh-report.json`, `editor-assurance.png`는 플레이·복원·결과 표시 증거다.

`.cache/genre-suite-proof.json`은 실제 GUI 제작 시험이 만드는 경로 기록이다. 빌드 후 아래 순서로 재실행한다. `RAISING_BENCHMARK_ROOT`에는 아직 없는 폴더를 지정한다. 기존 샘플을 지울 필요가 없다.

```powershell
$env:QT_STUDIO_OUT='dist/qt-studio-assurance'
$env:RAISING_NATIVE_PLAYER_RUNTIME="$PWD/dist/native-player-direction"
$env:RAISING_BENCHMARK_ROOT="$PWD/.cache/genre-retest-새이름"
node scripts/test-qt-studio.mjs benchmarkAuthoringSuite
node --test tests/analysis/assurance.test.mjs
node --test tests/native-player/genre-suite.test.mjs
node scripts/test-qt-studio.mjs benchmarkPlayAndAssurance
```

## 검증 한계

후보는 단위 수량·현재 위치 연결·최대 256개 다인 배정 조합을 사용한다. 모든 수량·임의 대상·전체 도달 상태의 완전 탐색이 아니다. 가능/거부 표는 회차 중간 상태의 관측 집계다. 상태 검사는 위에 열거한 불변 조건이며 모든 커스텀 규칙의 의미를 자동 증명하지 않는다.

제작 시험 창은 최대 128회 단위로 실행한다. 대규모 병렬 탐색은 기존 분석 창을 사용한다. 이번에는 Windows를 검증했으며 신규 웹·모바일·콘솔 실행이나 장편 규모 성능 검증은 포함하지 않았다.
