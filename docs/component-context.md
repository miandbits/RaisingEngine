# 재사용 UI 부품의 대상 연결

하나의 부품 정의를 여러 곳에 배치하고, 배치본마다 수행 캐릭터·활동·대상을 연결한다. 텍스트, 수치, 표시/활성 조건, 조건별 표현과 버튼 행동이 그 연결을 공유한다. 기존 고정 참조는 그대로 유지한다.

## 편집기에서 제작

1. **디자인 → 재사용 UI 부품 작업실**에서 카드의 글자나 버튼을 선택한다.
2. **선택 요소의 대상·데이터·조건 연결…**에서 이름 또는 수치 표시를 선택한다. 개인 능력치에는 **연결된 수행 캐릭터**를 사용한다.
3. 다른 배치본의 대상을 따라야 하는 필드만 **대상 사용**에서 선택한다. 예를 들어 대상 인물의 관계를 표시하는 요소는 `대상 인물`, 행동 버튼은 `행동`을 사용한다. 고정 인물/상품을 가리켜야 하는 참조는 선택하지 않는다.
4. 조건 편집기로 표시·활성 조건을 설정한다. 활동별 문구·이미지·애니메이션은 기존 **조건별 표현**에서 연결한다.
5. 화면에 같은 부품을 두 번 배치한다. 각 배치본의 개별 설정에서 **이 배치본의 캐릭터·활동·대상 연결…**을 열고 수행 캐릭터·활동·행동 등을 이름으로 선택한다.
6. 적용 후 프로젝트를 저장하고 플레이한다. 취소하면 부품과 배치본 변경은 저장되지 않는다.

**부품 실행 인물의 행동**은 기존 캐릭터 행동 명령을 사용한다. **부품 인물에게 활동 배정**은 해당 캐릭터의 활동만 변경하고 다른 인물의 배정을 유지한다. 활동의 실제 실행 시점과 비용·효과는 기존 시뮬레이션 규칙을 따른다.

## 데이터 계약과 우선순위

- `uiContext`: 수행 캐릭터(`actorId`), 활동(`activityId`), 대상 인물(`characterId`), 상품(`itemId`), 행동(`actionId`), 장소(`locationId`), 상점(`shopId`), 능력치(`attributeId`). 이번 단계는 이 타입 있는 슬롯을 제공한다. 임의 사용자 정의 매개변수나 임의 코드 실행은 추가하지 않았다.
- 부모 그룹/부품/목록의 연결을 자식이 상속한다. 가까운 자식에 지정한 슬롯만 부모 값을 덮어쓴다.
- `contextBindings`: 대상에 따라 바꿀 참조 필드만 명시한다. 요소의 명령 인자, 수치 바인딩, 표시·활성 조건, 표현 변형에 적용된다. 원본 정의를 변경하지 않는다.
- `owner.kind=actor`: 이 부품에 연결한 수행 캐릭터의 개인 데이터. 구체적인 `character` 소유자는 자동 교체하지 않는다. 부모 조건은 부모의 수행 캐릭터로 먼저 해석하므로 자식이 자신의 수행 캐릭터를 변경해도 부모 조건의 의미는 유지된다.
- `binding=context-name`과 `contextField`: 슬롯에 연결된 콘텐츠의 이름을 표시한다.
- 명시적으로 연결한 활동은 모든 단계에서 해당 활동의 표현을 사용한다. 활동을 연결하지 않고 수행 캐릭터만 연결하면 활동 결과 단계에서 그 캐릭터의 결과 활동을 사용한다. 연결이 전혀 없는 기존 요소는 종전 대표 활동 규칙을 유지한다.
- 목록 선택과 부품 연결이 같은 필드를 동시에 제어하면 검증 오류로 처리한다. 필수 슬롯 누락, 없는 대상, 대상에게 없는 관계 수치도 저장 위치를 포함한 오류로 알린다.

연결 값은 게임 콘텐츠이며 별도 가변 세이브 데이터가 아니다. 실제 변화는 기존 명령/저장 계약으로 처리한다. 저장·불러오기 후 동일 콘텐츠와 상태에서 같은 표시와 행동을 재구성한다.

## 검증과 예제

`tests/fixtures/projects/component-context`는 Qt의 실제 편집 폼으로 저장한 공개 회귀 샘플이다. 원작 에셋을 포함하지 않는다. 같은 카드 정의를 소운과 연화에 배치한다.

- 소운: 검술 10, 수련, 검술 다듬기(소지금 2 / 개인 검술 +5).
- 연화: 검술 40, 연회, 비전 연마(소지금 3 / 개인 검술 +7).
- 행동의 활성 조건은 연결된 인물의 검술 20 이상. 처음에는 소운의 버튼만 비활성이다.
- 두 활동 배정, 사건 선택, 엔딩, 행동 직후/활동 결과/엔딩 저장과 새 플레이어 프로세스에서의 복원을 검사한다.

```powershell
npm run build:headless
node --test tests/visual/component-context.test.mjs tests/runtime/component-context.test.mjs
$env:RAISING_COMPONENT_CONTEXT='tests/fixtures/component-context.json'
$env:RAISING_NATIVE_PLAYER_RUNTIME='dist/native-player-component-context'
node --test tests/native-player/component-context.test.mjs
```

Qt 제작 시험은 `RAISING_QT_COMPONENT_CONTEXT=1`, `RAISING_QT_PROJECT`를 **reusable-activities의 새 복사본**으로 설정하고 `qt-studio-test.exe componentContextAuthoring`을 실행한다. 기존 프로젝트에 시험 데이터를 추가하므로 사용자 프로젝트를 지정하지 않는다. 다른 GUI 시험을 같은 복사본이나 동시에 실행하지 않는다.

## 배포 범위

Windows 네이티브 플레이어를 실제 검증한다. 새 기능은 런타임 기능표의 `component-context-v1`을 요구한다. 지원 표시가 없는 구형 Windows 및 웹 런타임에는 내보내기를 차단한다. TypeScript 표시/명령 경로는 구현했지만 웹 전체 통합 검증 및 기능표 승격은 별도 작업이다. 모바일·콘솔 검증을 의미하지 않는다.
