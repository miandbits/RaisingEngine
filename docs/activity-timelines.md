# 일정 · 일별 연출 타임라인

2026-10-12 추가. 실행 파일은 `dist/qt-studio-timeline/RaisingStudioQt.exe`, 제작 샘플은 `projects/timeline-lab`이다. `Edit-Timeline-Lab.cmd`로 함께 연다.

## 편집기 사용

**디자인 → 일정 · 일별 연출 타임라인**에서 시작한다.

1. 연출을 추가하고 이름을 정한다. 클립마다 이미지, 문구, 시간(ms), 즉시/서서히 등장을 설정한다.
2. 클립을 앞뒤로 옮기거나 삭제한다. 연출 전체를 복제할 수도 있다.
3. 미리 재생·일시정지·1/4배속과 시간 슬라이더로 확인한다. 편집 미리보기는 게임 상태를 변경하지 않는다.
4. **활동 · 성공/실패 연결** 탭에서 활동의 기본 연출을 고르고, 필요하면 성공/실패 연출을 따로 연결한다. 기본 연출은 판정이 없는 활동과 분기 미지정 시 사용한다.
5. 일정 칸당 한 번 또는 논리 날짜마다 반복을 선택한다. 날짜별 반복에는 논리 일자 달력이 필요하며, 기존 자동 규칙과 같은 달력을 사용한다.
6. 저장하고 실제 플레이한다. 활동 결과 위에 연출 재생창이 나타난다. 재생창에서 일시정지·4배속·건너뛰기·저장·불러오기를 사용한다. 완료하거나 건너뛴 후 계속 진행한다.

문구 변수:

| 변수 | 내용 |
| --- | --- |
| `{activity}` | 실제 활동 이름 |
| `{outcome}` | 실제 성공/실패 결과 |
| `{day}` | 해당 논리 날짜 또는 일정 칸의 날짜 설명 |
| `{changes}` | 확정된 수치 변화. 날짜 반복 시 첫 날짜에만 표시 |

GUI는 사용 중인 연출 삭제, 빈 클립, 없는 이미지, 잘못된 변수, 달력 없는 날짜 반복을 막는다. 기존 프로젝트에 게임 규칙 설정이 없으면 일정 칸당 한 번 재생을 사용할 수 있다.

## 데이터와 저장 계약

- `visual.timelines`: `{id, name, clips}` 목록.
- 클립: `{id, durationMs, imageAssetId?, text?, transition?}`. 시간은 1~60,000ms, 등장은 `none` 또는 `fade`다.
- `visual.activityTimelines`: `{activityId, timelineId, successTimelineId?, failureTimelineId?, repeat?}`. 반복은 `once` 또는 `logicalDays`다.
- 재생 계획은 코어의 확정된 `lastActivityResult`에서 만든다. 연출 자체는 비용·효과·난수·명령 기록을 갱신하지 않는다.
- 저장 봉투의 선택적 `playerPresentation`이 연출 커서를 보관한다. 상태 리비전, 활동/연출 ID, 클립 위치, 경과 시간, 일시정지, 배속, 완료 여부를 포함한다.
- 불러오기는 커서를 현재 결과와 대조한다. 다른 결과의 커서나 범위를 벗어난 커서는 거부하고 현재 플레이를 보존한다. 연출 커서가 없는 이전 형식은 확정된 결과의 연출을 처음부터 보여주며 활동 효과를 다시 적용하지 않는다.
- 재생 중에는 다른 게임 명령으로 결과를 바꿀 수 없다. 저장·불러오기와 연출 조작은 가능하며, 결과 확인은 완료/건너뛰기 후 명시적으로 진행한다.
- 배포 기능 식별자는 `activity-timeline-v1`이다.

## 범위

현재 코어는 일정 한 칸의 활동 결과를 한 번 계산한다. **날짜 반복은 이 결과를 날짜별로 시각화하는 기능**이며 날짜마다 새 성공 판정이나 비용·효과를 생성하지 않는다. 진짜 하루 단위로 다른 활동과 결과를 계산하는 일정 규칙은 별도 작업이다.

이번 버전은 이미지 전환·문구·페이드와 활동 결과 재생창을 지원한다. 사운드 큐, 스프라이트 시트 재생, 다중 트랙 키프레임, 재생창의 자유 UI 배치, 별도 전투 연출은 포함하지 않는다. 편집기 미리보기의 문구 변수는 예시 값이며 실제 상태는 플레이로 확인한다.

## GUI 제작 샘플

`timeline-lab`은 이전 데이터 UI 샘플을 복사한 뒤 Qt GUI로 제작했다.

- `Activity days`: 기본 연출. 두 이미지 클립으로 구성된다.
- `Success scene`, `Failure scene`: 확률 활동의 성공/실패 분기.
- 검술 수업(`study`)은 날짜 반복, 휴식(`rest`)은 한 번, 숲 탐사(`expedition`)는 날짜 반복과 성공/실패 분기를 사용한다.
- 각 연출의 클립 시간은 1.5초와 0.9초다. 날짜 반복은 월 30일을 일정 칸으로 나눈 범위에서 재생한다.

검증 소스:

- `native/studio/timeline-test.inc`: 실제 GUI 제작·미리 재생·순서 변경·연결·저장/재열기, 기존 게임 규칙 없는 프로젝트 호환성, 취소/빈 클립 검사.
- `tests/visual/timeline.test.mjs`: 재생 계획·토큰·논리 날짜·커서 검증, 여러 seed의 정상/4배속/건너뛰기 결과 일치.
- `tests/native/timeline-controller.test.mjs`: 네이티브/Wasm 컨트롤러의 저장·복원·잘못된 커서 거부·날짜 경계 일시정지.
- `tests/native-player/timeline.test.mjs`: GUI 제작본의 실제 Windows 플레이와 저장 커서 검증.
- `scripts/verify-timeline.mjs`: GUI 제작본 웹 내보내기와 실제 브라우저 재생.

Qt 제작 및 호환성 시나리오 2개, 기존 Qt 회귀 16개, 기존 저장/플레이어/비주얼 회귀 37개가 통과했다. 기본 Qt 회귀에서는 전용 복사본을 요구하는 시나리오를 건너뛰고 새 시나리오는 별도 실행했다. 결과와 스크린샷은 `docs/evidence/timeline/`에 보존한다.

Windows 실제 플레이에서는 정상/4배속/건너뛰기 후 최종 저장의 코어 상태·난수·명령 기록 일치, 375ms 일시정지 위치 복원, 잘못된 커서의 원자적 거부, 성공/실패 분기, 실제 시간 진행과 정지까지 확인했다. 웹에서도 실제 이미지 로딩과 중간 저장·복원, 같은 세 재생 방식의 결과 일치, 날짜 전환 뒤 일시정지가 통과했다. 커서 검사는 실제로 기다린 뷰 응답과 화면의 날짜 표시를 함께 확인했다. 최종 웹 실행 정보는 `.cache/timeline/latest.json`에서 찾을 수 있다.
