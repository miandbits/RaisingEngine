# 공통 시간·진행 시스템 보완

## 호환성

`project.progression.model: "unified-v2"`를 선택한 프로젝트에만 새 규칙을 적용한다. `progression`이 없는 프로젝트는 추가 시간 상태가 없고, 모델을 지정하지 않은 기존 시간 세션은 기존 단일 공용 행동력·독립 시계 규칙을 유지한다. 기존 프로젝트를 열거나 저장하는 것만으로 모델을 바꾸지 않는다.

모델을 변경한 콘텐츠에서 이전 진행 저장을 그대로 이어가는 마이그레이션은 별개다. 기존 저장의 콘텐츠 지문 검사와 명령 재생 검증을 우회하지 않는다.

## 같은 시간 예산 안에서 월 일정과 행동 실행

`ticksPerPeriod`는 일정 한 칸의 시간이다. 월 칸 수는 기존 `periodsPerMonth`를 사용한다. 예를 들어 한 칸이 10시간이면 첫 칸은 0~10, 둘째 칸은 10~20이다.

- 직접 행동과 대기는 현재 칸의 공통 시계를 소비한다. 남은 시간을 넘는 시작은 명확한 오류로 거절한다.
- 월 일정 실행은 현재 칸의 남은 시간을 사용하는 세션을 만든다. 직접 행동으로 이미 6시간을 썼으면 일정은 4시간 후 정산한다. 두 경로가 시간을 이중으로 더하지 않는다.
- 현재 칸의 시간을 모두 썼어도 일정의 조건·비용·효과·결과 확인은 생략하지 않는다. 남은 시간이 0인 일정 세션으로 정산한다.
- 일정 정산 뒤 기존 기간 종료 사건·월 경계·엔딩 규칙을 따른다. 정산 전에는 기간 번호를 먼저 넘기지 않는다.
- 일정 효과의 수치는 기존 콘텐츠 그대로다. 남은 시간 비율로 자동 축소하지 않는다. 디자이너는 직접 행동과 일정 효과의 균형을 설정해야 한다.

이는 일정 칸을 명시적으로 완료하는 모델이다. 칸을 넘어 계속 실행하는 장기 행동, 시계만으로 월 일정을 생략하는 자동 날짜 진행, 병렬 탐험·전투는 지원하지 않는다. 탐험 진입 활동과 통합 일정의 중첩은 검증에서 거절한다. 기존 독립 시간 모드의 장기 행동은 바뀌지 않는다.

## 개인 시간·행동력과 병렬 처리

`actorPools`에서 육성 대상별 최대/초기 행동력과 시간당 회복량을 지정한다. 생략한 대상은 공용 설정을 개인 풀의 기본값으로 사용한다. 상태의 `actors[id].elapsed`는 해당 대상이 실제 행동 또는 월 일정으로 사용한 누적 시간이다. 세계 시계 `tick`과 별개로 서로 다른 세계 날짜를 갖는다는 뜻은 아니다. 쉬는 대상도 세계 시간이 흐르는 동안 설정된 행동력을 회복한다.

`parallel: true`이면 서로 다른 캐릭터의 시간 행동을 동시에 시작할 수 있다. 같은 캐릭터에게 두 행동을 중복 배정할 수 없다. 공용 행동·대기·월 일정은 다른 세션과 동시에 시작하지 않는다. 개인 행동은 기존 실행자 지정 규칙을 통해 개인 능력·소지품·관계·사건과 연결된다.

시작 시 행동력을 차감한다. 일반 비용·효과·확률은 완료 시 한 번 정산한다. 두 행동이 같은 공용 자원을 사용할 때 먼저 완료한 행동이 지불한다. 나중 정산이 실패하면 해당 명령 전체가 직전 상태로 복원된다. 다른 세션이나 이미 완료한 효과를 잃지 않으며, 실패한 개인 세션을 취소할 수 있다.

`cancelActorSession {actorId}`는 해당 캐릭터만, 기존 `cancelSession`은 모든 진행을 취소한다. 이미 사용한 행동력과 시간, 발생한 사건은 환불하거나 되돌리지 않는다.

## 예약과 실행 순서

예약의 기존 `id`, `eventId`, `atTick`, `actorId?`에 `repeatEvery`, `repeatCount`를 함께 지정하면 반복한다. 반복 간격은 양수, 총 횟수는 2~1000이며 프로젝트 전체 예약 발생 수는 최대 4096회다. 무한 반복 예약이나 런타임 중 예약 추가는 이번 범위에 포함하지 않는다.

한 번의 이어가기는 다음 예약 또는 가장 빠른 완료 시각까지 진행한다. 같은 시각에서는 예약 ID 순서로 사건을 처리한 뒤 캐릭터 ID 순서로 세션을 한 개씩 완료한다. 대본이 진행 중이면 모든 세션의 시간은 멈춘다. 같은 시각의 다음 처리 사이에도 저장할 수 있다.

반복 예약은 앞선 회차의 사건 완료 기록과 무관하게 다시 진입할 수 있다. 매회 사건 기간과 조건은 다시 검사하며, 불충족이면 그 회차를 skipped로 남긴다. 사건의 일반 완료 목록은 중복 없는 집합으로 유지하고 예약별 회차·시각·결과를 별도로 보존한다. 저장에는 모든 병렬 세션·실행자·남은 시간·개인 행동력·누적 시간과 처리한 예약 회차가 들어간다.

## 제작과 플레이

Qt **디자인 → 시간 · 행동력 · 예약 사건**에서 통합 모델, 한 칸의 시간, 병렬 옵션을 선택한다. 탭에서 행동 시간, 캐릭터 행동력, 월 일정의 개인 행동력 비용, 예약 간격과 횟수를 편집한다. 기존 공통 행동 UI는 각 캐릭터의 행동력·사용 시간, 진행 중인 모든 세션과 개인 취소를 표시한다. 기본 진행 버튼으로도 다음 시점까지 진행할 수 있다.

테스트용 프로젝트는 실제 Qt의 기존 프로젝트 복제 및 설정 대화상자로 제작했다. 게임 JSON을 직접 수정해 GUI 제작이라고 주장하지 않는다. 저장된 `project.json`의 사본을 `tests/fixtures/unified-time-project.json`으로 보존하고, 자동 플레이 테스트가 기존 공개 fixture 콘텐츠와 결합해 재현한다.

Windows 플레이어 기능 식별자는 `unified-time-v2`다. 이 기능이 없는 구형 Windows 또는 웹 런타임에는 내보낼 수 없다. 웹·모바일·콘솔의 새 모델 지원을 검증한 것은 아니다.

## 검증 항목

- `tests/native/unified-time.test.mjs`: C++/TypeScript 전체 상태·전이 일치, 두 개인 세션, 반복 개인 사건, 같은 시각 순서와 공용 비용 충돌, 개인/전체 취소, 시간 한도, 자동 탐색 후보, 저장 재생·변조 검출, 12개월 일정과 엔딩.
- 기존 단일 세션 10개 및 기존 코어·런타임·검증·캐릭터·저장 회귀 118개.
- 자동 분석·제작 시험의 기존 장르 샘플과 새 병렬 탐색 후보.
- Qt `unifiedTimeAuthoring`: 기존 프로젝트 복제, 통합 설정, 잘못된 반복 입력 수정, undo/redo, 저장·재열기·무변경 저장.
- `tests/native-player/unified-time.test.mjs` 및 Qt `unifiedTimePlay`: 실제 플레이어 버튼 입력, 병렬/예약 대본 중 저장과 상태 변경 후 복원, 월 일정 정산, 개인 취소, 새 프로세스에서 최종 저장 재개.

증거와 실행 로그는 `.cache/unified-time/` 및 `.cache/unified-*.log`에 보관한다.

### 실행 결과

- C++/TypeScript 통합 시간 시험 7개, 기존 단일 세션 시험 10개 통과. 새 시험과 addon 동시 실행 시험을 포함한 addon 경로도 18개 통과했다.
- 기존 코어·런타임·검증·캐릭터·저장 회귀 118개, 분석·제작 시험 묶음 29개 통과했다. 묶음 사이에는 중복 시험이 있으므로 합산 수치를 별도 시험 개수로 해석하지 않는다.
- Qt `unifiedTimeAuthoring`, `unifiedTimePlay` 통과. 실제 플레이어 시험 3개(통합 시간, 구형 시간 프로젝트, 이전 무협 제작 샘플의 두 엔딩) 통과했다.
- 새 모델의 기능 식별자가 없는 Windows·웹 런타임에 대한 내보내기 거절도 확인했다.
- 공개 대상 검사와 공개 샘플 로드 시험 2개도 통과했다. 샌드박스 안의 폴더 읽기 `EPERM`으로 중단된 샘플 로드 시험은 동일 명령을 데스크톱 권한으로 실행하여 확인했다. 현재 추적 파일 경계를 검사한 결과이며 Git 전체 이력의 에셋 출처를 보증하는 것은 아니다.

재현 명령:

```powershell
node --test tests/native/unified-time.test.mjs tests/native/progression.test.mjs
$env:RAISING_NATIVE_PLAYER_RUNTIME = "$PWD/dist/native-player-unified"
node --test tests/native-player/unified-time.test.mjs tests/native-player/designer-pilot.test.mjs
& ./dist/qt-studio-unified/qt-studio-test.exe unifiedTimeAuthoring unifiedTimePlay
```

사용자 확인용 프로젝트는 `projects/unified-time-lab`, 편집기는 `dist/qt-studio-unified/RaisingStudioQt.exe`, 플레이어는 `dist/native-player-unified/RaisingPlayer.exe`다. 이 프로젝트는 한 일정 칸의 병렬 행동·반복 사건·중간 저장 시험용이며, 하린의 행동력 회복을 0으로 설정하여 개인 풀의 차이를 확인한다. 계속 진행할 게임으로 사용하려면 시간 제작 도구에서 회복량이나 일정 비용을 조정해야 한다. 12개월 엔딩 완주는 별도의 코어 시험에서 검증했다.
