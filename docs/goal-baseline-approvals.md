# 경로별 기준 승인과 복원

콘텐츠 저장 후 **디자인 → 저장 기준 비교 결과…**에서 경로를 선택한다. 능력치·자원·비용·효과·조건의 차이를 확인하고, 필요하면 **차이 시작 그래프로 이동**으로 단계별 내용을 확인한다.

1. 의도한 변화라면 사유를 입력하고 **선택 경로를 새 기준으로 승인**한다.
2. 현재 실행 결과를 별도의 불변 기준 기록으로 저장하고 해당 경로의 활성 기준만 전환한다. 전체 경로를 재검사하므로 승인한 경로는 ‘동일’, 아직 승인하지 않은 변화는 ‘변화 있음’으로 남는다.
3. 이전 기준 목록에서 기록을 선택하고 **선택한 이전 기준으로 복원**하면 그 기준과 현재 콘텐츠를 다시 비교한다. 콘텐츠 자체를 되돌리는 기능은 아니다.
4. 승인·복원 시각과 사유는 경로 상세에 표시된다. 이전 기록을 덮어쓰거나 삭제하지 않으며 편집기 재시작 후에도 선택과 이력을 유지한다.

목표 도달에 성공한 ‘변화 있음’ 경로만 승인할 수 있다. 실행 오류·목표 미도달·기준 없음·검사 미완료는 승인으로 숨길 수 없다. 의도적으로 목표나 경로를 바꾸었다면 등록 경로를 먼저 수정한 뒤 저장·검사한다. 기준이 없는 경로는 기존 경로 비교 창에서 초기 기준을 저장한다.

## 저장과 충돌 처리

- `playtests/baselines/<UUID>.json`: 이전과 동일한 불변 실행 기록. 원래 기준을 보존한다.
- `playtests/baselines/.approvals`: 버전 1 활성 기준 맵과 승인·복원 이력. 프로젝트와 함께 버전 관리한다.
- 기존 프로젝트는 명시적 선택이 없으면 종전처럼 경로의 최신 정상 기준 파일을 사용한다. 첫 승인·복원에서 기존 선택을 고정한다. 이후 단순한 참고 기록 저장은 활성 기준을 바꾸지 않는다.
- 검사 결과는 활성 기준과 이력의 해시를 포함한다. 콘텐츠·경로·런타임·활성 기준이 달라진 오래된 검사 결과로 승인하거나 그래프를 여는 요청은 거절한다. 다른 편집기 창에서도 동일한 검사를 적용한다.
- 승인 처리에는 프로젝트별 배타 잠금과 비교 후 쓰기를 사용한다. 새 기록을 만들기 전에 기존 선택을 고정하므로 중단으로 남은 기록이 자동으로 승인되지 않는다. 이력은 임시 파일 후 교체로 저장한다.
- 선택한 기준 파일이 사라지거나 손상되면 오류로 표시하며 다른 기록으로 자동 대체하지 않는다. 승인 기록이 손상된 경우도 검사를 통과로 표시하지 않는다.
- 승인 후 재검사에 실패하면 기준 변경 완료와 검사 실패를 구분해 알린다. 콘텐츠 저장 실패로 오인시키지 않는다.

## 검증

`tests/analysis/goal-approvals.test.mjs`는 선택 경로 승인, 다른 회귀 유지, 원본 불변, 두 서비스 인스턴스의 오래된 승인 거부, 복원, 재시작, 참고 기록의 활성 기준 비변경, 실패 경로 승인 거부와 손상된 승인 파일을 검사한다.

Qt `goalSaveImpact`는 실제 검사 결과 창에서 승인 사유 입력 → 승인 → 결과·이력 확인 → 이전 기준 복원 → 첫 차이 그래프 이동을 실행한다. 원본 프로젝트 대신 `.cache` 복사본을 사용한다. 관련 증거는 `docs/evidence/goal-impact/approved-baseline.png`, `restored-baseline.png`, `gui-verification.json`에 저장한다.

기준 파일 한도는 기존 프로젝트당 128개, 승인 이력 파일은 2 MiB다.

## 한 경로 안의 부분 승인

경로를 선택하면 아래 변경 목록에서 **능력치·자원, 비용 정의·실행, 효과 정의·실행**을 개별 체크할 수 있다. 행을 선택하면 상세 영역에 그 항목이 달라진 모든 단계와 기준 값 → 현재 값이 표시된다. 사유를 입력하고 **체크한 변화만 승인**한다. **경로 전체 승인**은 기존처럼 경로 전체의 현재 실행 결과를 새 기준으로 저장한다.

- 부분 승인은 선택한 항목에만 적용한다. 비용 정의를 승인해도 소지금 결과나 효과를 함께 승인하지 않는다. 같은 경로의 미선택 항목은 ‘미승인’, 경로는 ‘변화 있음’으로 남는다.
- 항목은 종류·경로와 발생 단계별 이전/현재 값 묶음이다. 같은 항목의 여러 발생은 함께 승인하며, 개별 발생만 따로 승인하는 기능은 아니다. 목록의 발생 수와 상세 값을 확인한다.
- 원본 실행 기록을 일부 고쳐 가상의 플레이 결과를 만들지 않는다. 원본 기준, 현재 등록 경로, 런타임과 정확한 차이에 결합된 승인 기록을 별도로 저장한다. 승인한 값은 그 항목의 새 기대값이다. 비용 2→7을 승인한 뒤 9로 바꾸거나 원래 값 2로 돌아가도 기대값 7과 비교해 다시 미승인 회귀로 표시한다. 이를 다시 승인하면 최신 승인 값이 기대값이 된다. 경로·런타임이 바뀌어도 과거 부분 승인을 그대로 적용하지 않는다.
- 조건 검사·경로 구조·기타 실행 상태 변화는 목록에 ‘검토 필요’로 남으며 부분 승인으로 숨길 수 없다. 목표 미도달·실행 실패는 여전히 실패다.
- 복원 목록에서 **부분 승인 N개** 기록을 선택하면 그때의 활성 기준과 승인 항목 집합으로 돌아간다. 3개 승인 → 1개 추가 승인 후 3개 상태로 돌아가거나, 0개 상태로 돌아가 모든 차이를 다시 표시할 수 있다. 기준 파일을 직접 선택하는 복원은 해당 파일 기준으로 부분 승인 없이 비교한다.
- 그래프는 미승인 차이의 첫 단계로 이동한다. 원래 실행 기록과 현재 플레이를 비교하는 그래프이므로 이미 승인한 차이도 실행 값에는 그대로 나타난다.

기존 승인 파일은 그대로 읽으며 `partials`, 이력의 `previousSelection`·`selection`을 선택적으로 확장했다. 부분 승인 중 새 기준 파일은 만들지 않는다. 승인 이력과 정확한 차이 자료는 프로젝트의 `.approvals` 파일에 보존한다. 변경 목록은 2000개 항목까지이며 제한 초과 시 검사 오류로 알린다. 잘린 목록을 정상 검사로 승인하지 않는다.

`tests/analysis/goal-partial.test.mjs`는 종류별 선택, 남은 회귀, 중복/임의/읽기 전용 항목 거부, 저장 후 재시작, 부분 이력·원본 복원, 재변경 회귀 및 그래프 이동을 검증한다. Qt `goalPartialApproval`은 실제 체크 목록과 승인·복원 버튼으로 같은 흐름을 확인한다. 증거는 `docs/evidence/goal-partial/`에 저장한다.
