# 네이티브 전환·육성 제작 흐름 독립 검증

## 완료 판정

이번 검증은 편집기에서 만든 데이터가 실제 플레이에 연결되는지 확인한다. 테스트 내부에서 JSON을 직접 작성한 결과만으로 GUI 제작 완료를 주장하지 않는다. C++ 바이너리 컴파일 성공과 게임 실행 전체의 C++ 전환도 구분한다.

| 검증 대상 | 통과 조건 |
| --- | --- |
| 기존 기능 | 기존 데이터 계약·코어·대본·저장·MCP·분석 테스트가 계속 통과 |
| GUI 제작 | 기본 프로젝트를 연 뒤 편집기 조작만으로 자유 화면과 행동, 장소, 상점, 아이템, 선물, 관계 사건을 구성 |
| 실제 흐름 | 집 → 일정 진행 → 도시 → 상점 구매 → 선물 → 관계 사건을 실제 플레이 버튼으로 진행 |
| 행동 원자성 | 부족한 비용·아이템, 잘못된 참조, 오래된 명령은 시간·재화·인벤토리·관계·RNG를 부분 변경하지 않음 |
| 저장·복원 | 구매 전후와 선물/사건 경계에서 저장·복원 결과 및 이후 실행 결과가 일치 |
| 편집 충돌 | GUI 미저장 초안과 MCP 저장이 충돌하면 양쪽 변경을 보존하고 충돌 원인을 표시 |
| C++ 실행 | 실제 실행 백엔드와 지원 범위를 확인하고 결정적 결과·오류를 기존 코어와 비교 |
| 화면 품질 | 생성 이미지 로드, 창 크기 변경, 목록·버튼·대사 표시, 런타임 오류 없음 확인 |

## 초기 기준선

- 확인일: 2026-10-11 (America/Los_Angeles)
- `npm test`: **176개 통과, 실패 0개**. 변경 전 기준선이다.
- PATH에서 사용 가능한 네이티브 도구: CMake, MinGW g++.
- PATH에서 확인되지 않은 도구: Ninja, clang++, MSVC cl, Emscripten emcc, Android adb.
- 따라서 Windows 네이티브 검증과 웹·Android·콘솔 빌드 검증은 별도로 보고한다. SDK·빌드·실기기 실행 증거 없이 모든 플랫폼 지원 완료로 표시하지 않는다.

## 검증 기록

구현이 준비되는 순서대로 독립 테스트 결과와 재현 가능한 명령, 남은 제약을 기록한다. GUI 테스트는 `.cache/journey-ui` 아래의 테스트용 프로젝트를 사용하며 사용자 원본 프로젝트를 수정하지 않는다.

### 독립 테스트 구성

- `tests/journey/native-parity.test.mjs`: 운영용 TypeScript 브리지를 사용하지 않고 C++ 실행 파일의 JSON-lines 프로토콜에 직접 요청한다. TypeScript 기준 코어와 초기 상태, 모든 명령의 전체 상태와 전이, 오류 코드·위치·실패 상태를 비교한다. 2개월 두 경로와 12개월 다섯 경로, seed 경계값, 초기값 오류, 구매·선물·관계 사건과 정수 오버플로가 포함된다.
- `tests/journey/legacy-save.test.mjs`: 전환 전 실행 파일로 생성한 고정 세이브를 읽어 정확한 상태를 복원하고 다음 명령 뒤 재저장·복원한다. 테스트가 기준 파일을 다시 생성하지 않는다.
- `tests/journey/gameplay-adversarial.test.mjs`: 잘못된 수량·위치, 소진된 재고, 보유 한도, 선물 비용 지불 이후 효과 오류의 원자성, 프로토타입 이름과 같은 ID를 검사한다.

### 발견하여 수정한 결함

유효한 상점 ID `constructor`로 구매하면 빈 객체의 상속 프로퍼티를 구매 기록으로 잘못 사용했다. 구매 성공 후에도 기록이 JSON에 남지 않고 전역 `Object`에 프로퍼티가 기록될 수 있었다. 구현 담당자가 상점·물품별 구매 기록에 own-property 검사를 추가했고, 독립 회귀 테스트에서 구매 기록·전역 객체 불변·세이브 재현을 함께 확인했다. 관련 부정 입력 테스트 4개와 기존 세이브 테스트는 수정 후 모두 통과했다.

### 플랫폼 판정의 한계

C++ 시뮬레이션이 Windows에서 실행된다는 사실만으로 C++ 그래픽 플레이어, WebAssembly, 모바일, 콘솔의 빌드·입력·저장·인증까지 완료된 것은 아니다. UI 테스트와 최종 보고에서는 실제 실행 백엔드, 그래픽 경로, 검증한 플랫폼을 각각 명시해야 한다.

### 1차 통합 결과

- 기존 회귀·생활 규칙·독립 네이티브 검증을 합친 컴파일 결과 테스트: **206개 통과, 실패 0개** (`.cache/journey-compiled-regression.log`). 이 수치는 이후 추가한 카탈로그 2개와 MCP 2개를 포함하지 않는다.
- 독립 카탈로그 검증 2개 통과: 위치·아이템·상점·교류·화면의 개별 검색/JSON pointer, 이동·판매·선물·관계 효과·사건·UI 연결의 그래프.
- 독립 MCP 검증 2개 통과: 인간의 상점 가격 초안과 MCP 관계 효과 변경의 충돌 보존, 잘못된 상점 참조가 포함된 변경의 전체 거절.
- 실제 Electron GUI 제작·플레이 테스트 1개 통과. JSON 주입 없이 UI로 장소 2개, 아이템, 상점, 선물 효과, 관계 사건, 임의 안내 화면, 이동 버튼, 배경과 인물 연출을 작성했다. 집에서 일정 1기간을 진행한 뒤 도시·상점 구매·선물·관계 사건으로 이어졌으며 실제 백엔드는 `native`였다. 선물 직전 저장 후 사건 진입·불러오기·재진입 결과와 1000×700 창에서 화면 전체 표시를 확인했다.
- GUI로 작성한 결과: `.cache/journey-ui/authored-project`. 증거 이미지: `authoring.png`, `free-screen.png`, `home.png`, `shop.png`, `relationship-event.png`, `minimum.png`.

### 전환 초기 성능 측정

`node tests/journey/benchmark-native.mjs`는 같은 22,007바이트 콘텐츠와 159개 명령의 12개월 경로로 비교한다. 초기 IPC 구현 측정은 TypeScript 경로 5.887ms, C++ 경로 244.938ms였다. 모든 명령 뒤 저장·복원을 검증하는 경우 각각 715.642ms, 37,742.195ms였다. C++ 코드 자체 성능으로 해석하면 안 된다. 저장 재현에서 과거 명령마다 전체 콘텐츠를 JSON으로 IPC 전송한 것이 주된 병목이며, 네이티브 일괄 재현 및 콘텐츠 등록 방식으로 개선 후 재측정해야 한다. 초기 기록은 `.cache/journey-native-benchmark.json`에 저장했다.

콘텐츠 등록·일괄 재현 적용 후 같은 검증은 네이티브 3,098.399ms로 약 12.2배 단축되었다(TypeScript 749.820ms). 일반 159명령 경로는 네이티브 161.895ms, TypeScript 6.042ms였다. 최신 측정 JSON이 같은 경로에 저장되므로 초기 수치는 이 문서의 기록을 기준으로 한다. 단일 UI 동작 지연은 작지만 대규모 자동 플레이는 IPC 호출을 더 줄이는 실행 방식이 유리하다.

### 내보내기 검증

`tests/journey/export.test.mjs` 4개 통과: 실제 PNG 바이트와 콘텐츠/메타데이터 보존, 검증 이후 에셋 변경 시 전체 취소, 기존 폴더 및 프로젝트 상위 폴더 보존, 위조된 외부 에셋 경로 및 런타임 심볼릭 링크 차단. 실패 후 대상이나 임시 staging 폴더가 남지 않는 것도 확인했다.

독립 브라우저 검증은 임시 HTTP 서버에서 내보낸 폴더를 실제 Chrome으로 연다. 최초 실행에서 생성된 AJV 검증 코드의 `require` 호출이 브라우저 시작을 막는 결함을 발견했고, 구현 담당자의 정적 ESM import 수정 후 `tests/journey/web.test.mjs`가 통과했다. 실제 Wasm 실행으로 집→도시→상점→선물→관계 사건을 진행하고 다운로드·파일 업로드를 사용했다. 브라우저 저장을 네이티브 데스크톱 컨트롤러가 읽고, 네이티브 저장을 브라우저가 읽는 양방향 상태 일치도 확인했다. 변조된 저장은 현재 상태를 보존하며 거절했고 844×390 화면에서도 게임 영역이 화면 안에 들어왔다. 증거는 `.cache/journey-web-ui/wasm-relationship-event.png`, `landscape-small.png`에 있다.

`tests/journey/native-ui.test.mjs`는 독립 Windows 폴더로 내보낸 SDL3/RmlUi 실행 파일을 실행한다. 상태 주입 없이 실제 포인터 이벤트 경로로 집→일정·휴식→도시→상점→선물→관계 사건을 통과했다. 잔액·선물 부족 버튼 비활성, 저장 후 선물 실행 후 불러오기 상태 복원, 그래픽 플레이어 저장을 데스크톱 컨트롤러에서 읽은 결과 일치, 변조 저장 거절을 검사한다. 한글 폰트·배경·인물 이미지를 직접 확인했고 `.cache/journey-native-ui/verified-relationship.png`에 증거를 남겼다.

`tests/journey/polish-editor.test.mjs`는 `examples/academy-journey`를 열고 꽃 이미지를 가져와 아이템에 연결·저장한다. 실제 상점에서 해당 이미지가 표시되는 것을 확인했다(`.cache/journey-polish-ui/flower-shop.png`). 메뉴 내보내기에서는 Node API 테스트로 드러나지 않았던 Electron의 디렉터리 복사 EEXIST 오류를 발견했다. 런타임의 각 항목을 staging 폴더 안에 복사하도록 수정한 뒤 Windows·웹 메뉴 내보내기 모두 통과했다. 오류가 자동 검증에 의해 지워지거나 모달 뒤에 가려지는 문제도 수정되었다.

### 최종 독립 검증 집계

확장된 기존·계약·네이티브 비교·충돌·내보내기·저장 테스트 220/220개가 11.35초에 통과했다. 로그는 `.cache/journey-final-regression.log`다. 별도로 실제 GUI를 쓰는 편집기 제작, 이미지 가져오기와 메뉴 내보내기, 브라우저 Wasm, 독립 Windows 그래픽 플레이어 4개 테스트가 통과하여 이번 검증 집합은 중복을 제외하면 224개다. 편집기 관계 사건 생성 직후 한 번의 실행 취소로 사건 문서와 교류 연결이 함께 제거되고, 다시 실행으로 함께 복원되는 것도 실제 버튼으로 확인했다.

`tests/journey/analysis-storage.test.mjs` 2개는 실제 Windows `FileStream`의 `FileShare.Read` 잠금을 사용한다. 일시적인 교체 잠금 중 이전 JSON이 읽히고 잠금 해제 후 새 값이 기록된다. 지속되는 잠금은 제한된 재시도 후 실패하며 이전 값과 임시 파일 정리가 보장된다. 파일 시스템 오류를 흉내 낸 테스트가 아니다.

이번에 실제 실행한 배포 대상은 Windows SDL3/RmlUi와 Chrome의 C++ WebAssembly다. 모바일 브라우저 크기는 검사했지만 모바일 앱, macOS, Linux, 콘솔 SDK 빌드나 실기기 실행을 완료한 것은 아니다. 각 SDK·서명·배포 체계와 입력 방식 검증은 별도 작업으로 남는다.

### 대규모 콘텐츠 편집 검증

`tests/journey/scale-ui.test.mjs`는 원본 샘플을 건드리지 않는 별도 프로젝트에 공유 `StudioEditor` 일괄 편집 API로 엔딩 500개, 사건 500개, 인물 100명, 능력·자원 100개, 물품 1,000개, 장소 50개, 상점 50개, 교류 100개를 만든다. 공유 검증을 통과한 뒤 실제 편집기로 마지막 물품과 엔딩을 검색하고, 물품 목록 끝까지 스크롤하고, 장소 연결을 검색하고, 2단계 관계 그래프를 연다. 물품 목록은 버튼 11개, 콘텐츠 목록은 행 22개, 관계 그래프는 선 200개 이내로 제한되었다. 잘못된 참조를 한 개 주입했을 때 `/gameplay/interactions/99/itemId`의 정확한 오류가 나오는 것도 확인하고 원복했다.

측정 예시는 파일 열기 약 3초, 의미 검증 약 168ms, 마지막 물품 검색 25ms, 마지막 엔딩 검색 58ms였다. 이는 현재 PC에서 얻은 관측치이고 통과 여부를 특정 시간으로 판정하지 않는다. 최신 수치와 재현 프로젝트 위치는 `.cache/journey-scale-ui/evidence.json`, 화면은 같은 폴더의 `last-item.png`, `bounded-flow.png`에 남는다. 대규모 GUI 검증 1개가 추가되어 검증 집합은 225개다.

집·꽃집 배경도 실제 이미지 가져오기와 장소 배경 선택으로 `examples/academy-journey`에 연결했다. 해당 배경이 실제 플레이에 표시되고 Windows·웹 메뉴 내보내기에 포함되는 것을 재검증했다. 증거는 `.cache/journey-polish-ui/authored-home.png`, `flower-shop.png`다.

### Node-API 경계 검증

`tests/journey/addon-fallback.test.mjs` 2개가 통과했다. 일치하는 네이티브 애드온과 명시적인 C++ 자식 프로세스가 동일한 상태·전이를 만들고, 잘못된 실행 파일/CPU/N-API 버전 또는 없는 애드온 파일은 원인을 표시하며 실제 C++ 자식 프로세스로 돌아간다. 이 경우에도 변경 충돌과 게임 상태를 보존한다. 검증 집합은 총 227개다.

같은 159명령 경로를 다시 측정하면 Node-API 네이티브는 19.217ms, TypeScript는 5.593ms였다. 모든 명령마다 저장·복원을 검증하는 경우 각각 1,755.935ms와 704.531ms다. 이전 자식 프로세스 경계보다 일반 경로는 크게 개선되었지만, 이 결과로 C++가 모든 작업에서 TypeScript보다 빠르다고 주장하지 않는다. 전체 분석을 네이티브에서 일괄 실행하는 측정과 구분한다.

### 네이티브 수동 일정 선택 추가 점검

### Android 네이티브 어댑터와 Windows 회귀 검증

Android에서는 동일 C++ 코어와 SDL3/RmlUi 렌더러를 `libmain.so`로 빌드하고 공유 SDL3를 사용한다. Java가 추출한 실제 게임 디렉터리와 글꼴을 읽고, 저장은 SDL 앱 전용 경로를 사용한다. 터치는 창 좌표에서 논리 캔버스 좌표로 변환하며 합성 마우스 중복을 막는다. SDL Android가 백그라운드 진입 시 이벤트 펌프 내부에서 중단되므로 `SDL_AddEventWatch`에서 대기 동작을 한 번 처리하고 자동 저장·오디오 일시 정지를 수행한다. 수동 저장 슬롯은 보존하며 중복 진입 이벤트는 추가 저장하지 않는다. 시작 시 자동 저장을 재현 검증하고, 주 파일이 없거나 손상된 경우 검증 가능한 백업을 복구한다.

기존 배포물을 덮어쓰지 않고 `dist/native-player-mobile-check-app`을 별도 빌드했다. 새 `tests/journey/mobile-input-lifecycle.test.mjs`와 기존 네이티브 렌더·입력·오디오 검증 9개를 해당 실행 파일로 돌려 **10/10 통과(17.12초)**했다. 터치 취소, 레터박스 좌표, 구매·선물, 중복 백그라운드 이벤트, 수동 슬롯 보존, 자동 저장 백업 복구·거절을 확인했다. `.cache/journey-mobile-input/evidence.json`에 실제 상태와 생성 파일 경로를 기록했다. 기존 검증은 실행 파일 경로만 별도 산출물로 바꾼 임시 사본으로 실행한 후 제거했다.

부모 작업은 Android APK 컴파일과 에뮬레이터의 실제 터치 구매·선물·관계 사건, 백그라운드→강제 종료→재시작의 저장 JSON 일치를 별도로 확인했다. 이 검증을 iOS나 콘솔 지원으로 확대 해석하지 않는다. iOS 앱 빌드·서명, 콘솔 승인 SDK·개발기, 물리 기기의 입력·오디오 중단, 노치 안전 영역과 터치 스크롤은 추가 작업/검증이 필요하다.

### 탐험·전투·장비·의뢰의 실제 네이티브 UI

`tests/journey/native-systems.test.mjs`의 세 경우가 별도 Windows SDL/RmlUi 실행 파일에서 **3/3 통과(6.82초)**했다. 실제 창 좌표를 누르는 입력으로 장착·해제·사용자 배치 버튼 장착, 의뢰 수락, 일정의 숲 탐험, 노드 이동, 방어·회복약·공격, 전투 중 저장·불러오기, 귀환·의뢰 보상·관계 사건까지 진행했다. 전투 저장을 다시 불러와 같은 행동을 실행한 상태가 RNG와 보상까지 정확히 일치했다. 가방이 가득 찬 전리품 손실도 화면에 표시된다.

세 경우는 전투/탐험 화면이 없는 프로젝트, 올바른 위젯이 있는 화면, 화면은 있지만 필수 위젯이 빠진 프로젝트다. 뒤의 경우도 안전한 기본 화면을 표시해 진행이 막히지 않는다. `.cache/journey-native-systems/`에 상태 보고서와 스크린샷을 남겼다. 최초 스크린샷에서 새 위젯 문단이 RmlUi 기본 스타일 때문에 한 줄로 이어지는 문제를 발견해 범위를 한정한 블록 스타일을 추가하고 다시 실행·육안 확인했다. 이 검증의 콘텐츠는 테스트용 프로그램 생성 fixture이며 편집기로 작성한 상용 수준 샘플이라는 주장은 하지 않는다.

편집기의 실제 컨트롤로 작성된 `examples/academy-adventure`는 수정 없이 임시 복사본에서 별도 Windows/Web 번들로 내보냈다. `tests/journey/authored-adventure-native.test.mjs`가 실제 SDL 창 좌표 입력으로 **1/1 통과(4.01초)**했다. 의뢰 수락 → 상점의 연습용 검 구매 → 장착 → 일정에 첫 숲 탐험 배치 → 슬라임 전투 → 꽃 전리품 → 귀환 → 의뢰 보상 → 신뢰 15와 유나의 인정 사건까지 확인했다. 전투 전 저장을 불러와 두 번의 공격을 재실행한 상태가 정확히 일치한다. 첫 검증의 한 번 공격 승리 가정은 실제 9 피해 결과에 맞춰 두 번으로 수정했으며, 대사는 스크린샷에서 직접 확인했다. `.cache/journey-adventure-native/evidence.json`이 최종 독립 실행 보고서와 두 번들 경로를 기록한다. 원본 샘플과 사용자의 열린 편집기는 변경하지 않았다. 새 화면의 상단 버튼은 배경색이 지정되지 않아 밝은 배경 위 흰 글자의 대비가 약한 개선점을 부모에게 전달했다.

상단 버튼 일곱 개의 배경색을 실제 화면 편집기로 지정한 뒤 원본을 다시 복사·내보내 네이티브 검증이 **1/1 통과(3.74초)**했다. 스크린샷에서 버튼 대비 개선을 확인했다. 같은 콘텐츠 지문 `sha256:dc79f6d4357d4de7e831596f0c455af10408c936b27f2369e0eca49705a47d7d`의 최종 Web 내보내기도 `tests/journey/authored-adventure-web.test.mjs`에서 **1/1 통과(3.61초)**했다. 실제 Chrome UI로 전체 경로와 장착→장착 해제→재장착을 수행하고, 전투 저장을 다운로드·업로드하여 정확히 같은 전투 결과를 재현했다. Wasm 런타임 표시와 관계 사건 대사를 확인했으며 브라우저 페이지 오류는 없었다. 증거는 `.cache/journey-adventure-web/evidence.json`과 관계 사건 스크린샷이다. 첫 브라우저 시도는 검증용 HTTP 서버에서 `.mjs` MIME을 빠뜨린 문제였으며 테스트 서버를 수정한 후 통과했다.

Android 새 샘플의 HOME 키 직후 파일을 읽거나 강제 종료하면 화면 전환 중인 운영체제가 아직 pause 콜백을 전달하지 않아 이전 자동 저장이 보일 수 있었다. 부모가 전환 완료 뒤 새 콘텐츠 지문·상태 버전을 확인하자 정상 자동 저장이 확인되었다. 제품 로직 변경은 하지 않았다. 검증은 고정된 짧은 대기나 이전 파일끼리의 일치에 의존하지 말고, **예상 콘텐츠 지문과 상태 버전이 자동 저장에 기록되었음을 제한 시간 내 확인한 뒤** 강제 종료·재시작·전체 상태 일치를 검사해야 한다. 비호환 자동 저장 거절 후 새 게임·구매·백그라운드 저장의 독립 회귀 검증도 1/1 통과(5.81초)했다.
