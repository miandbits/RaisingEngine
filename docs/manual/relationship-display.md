# 관계 수치·최근 변화 표시 (2026-10-17)

상단 **관계 표시** 또는 **콘텐츠 → 관계 표시 배치…**에서 인물·관계를 이름으로 선택합니다. 특정 화면 또는 기본 일정·대화·엔딩 세 화면에 배치할 수 있습니다. JSON이나 내부 ID 입력은 필요 없습니다.

생성된 표시는 일반 `text` 요소입니다. 캔버스에서 이동·크기를 바꾸고 속성에서 인물·관계, 글꼴, 색, 앵커와 표시 형식을 편집합니다. 다른 화면에 같은 ID로 배치한 텍스트에는 기존 **다른 화면에 이 텍스트 연결 적용…**도 사용할 수 있습니다. 재사용 부품의 텍스트에도 같은 바인딩을 사용할 수 있습니다.

예: `{label}: {value} (최근 {delta})` → `소하 · 신뢰: 3 (최근 +3)`.

- `{label}`: 인물 이름과 관계 이름.
- `{value}`: 현재 공용 관계 수치. 기존 `relationship-value`와 동일한 대상 범위입니다.
- `{delta}`: 마지막으로 관계가 실제 변한 명령의 순증감. 여러 효과와 상·하한 적용이 끝난 뒤의 차이입니다. 관계가 변하지 않는 진행에서는 유지되고 새 게임에서는 0으로 초기화됩니다. 회상 화면에는 본편의 최근 변화가 노출되지 않습니다.

최근 변화는 핵심 실행 상태에 추가하지 않았습니다. 저장된 명령을 재현하면서 다시 계산하므로 저장 형식 `1.0.0`, 기존 상태 비교, RNG와 콘텐츠 지문 규칙을 유지합니다. 콘텐츠 자체를 변경한 경우의 저장 호환성 정책도 기존과 동일합니다. 내보내기에는 `relationship-change-v1`을 지원하는 새 플레이어가 필요하며, 구형 플레이어는 내보내기 단계에서 차단합니다.

## 검증

- Qt에서 기존 독립 제작 시험 프로젝트의 복사본을 열어 소하·신뢰를 이름으로 선택하고 일정·대화·엔딩에 배치·저장. 재개 후 관계 요소를 검색해 선택하고 캔버스의 초깃값, 속성의 대상과 형식을 확인했습니다.
- 실제 GUI에서 발견한 `{delta}` 검증 오류를 수정했습니다. 최종 프로젝트 19개 문서, 오류 0·경고 0.
- C++ 및 TypeScript 저장 회귀: 기존 두 엔딩, 매 명령 저장·복원, 순증감/상한, 변화 없는 명령, 새 게임 초기화. 새 관계 표시 형식 검증도 통과.
- 실제 SDL 플레이어: GUI 제작 번들의 두 선택(+3/-1)을 버튼·드롭다운 입력으로 진행. 각 단계의 상태를 코어의 예상 상태와 비교했습니다. 두 분기 모두 엔딩의 저장 버튼 → 다시 시작 → 불러오기 버튼, 별도 프로세스에서 타이틀의 불러오기 버튼까지 통과했습니다. 화면에 표시되는 수치와 최근 변화도 비교했습니다. 콘텐츠 파일 외부 수정이나 저장 상태 주입으로 플레이를 대체하지 않았습니다.
- C++ WASM 웹 컨트롤러에서도 엔딩 저장·새 게임·불러오기 후 상태와 관계 변화가 일치. 웹 번들 및 React 타입 검사 통과. 브라우저 수동 클릭 시험은 이번 범위에 포함하지 않았습니다.
