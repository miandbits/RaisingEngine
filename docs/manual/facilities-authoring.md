# 식단 · 병원 · 거래 제작 도구

이 문서는 기존 시설 데이터의 호환 경로를 설명한다. 새 콘텐츠는 [범용 정책 · 행동 · 공유 한도](generic-rules.md)를 사용한다. 새 Qt 빌드에서 기존 작업실 메뉴는 **거래 · 기존 시설 데이터**이며, 정책 작업실에서 기존 시설을 범용 규칙으로 변환할 수 있다.

Qt 편집기의 **디자인 → 식단 · 병원 · 거래 작업실**에서 게임 데이터를 편집하고 현재 화면에 목록을 배치한다. 비용·효과·수량·확인창을 설정할 때 JSON이나 C++를 수정할 필요가 없다. 화면 여러 곳에 배치한 목록은 같은 시설 데이터를 사용한다.

`Edit-PM2-Facilities.cmd`는 새 편집기 `dist/qt-studio-facilities/RaisingStudioQt.exe`와 별도 프로젝트 `projects/pm2-facilities-lab`를 연다. 기존 PM2 프로젝트는 유지된다. 실습 경로는 **우리 집 → 식단**, **외출 → 병원**, **외출 → 상점 → 구매 / 물품 판매**다.

## 제작 순서

1. 목록을 배치할 화면을 연다. 필요하면 **화면 → 새 화면**으로 만든다.
2. 작업실에서 구매 상품, 판매 매입표, 병원 서비스, 지속 식단 중 하나를 고른다.
3. 거래는 상점과 상품, 이용 장소, 화폐, 단가, 최대 수량을 설정한다. 구매에는 초기 재고 또는 무제한 재고를 설정한다. 판매는 별도의 매입 단가를 사용한다.
4. 병원과 식단은 이용 장소, 비용 자원, 효과 대상과 증감/고정값을 행으로 설정한다. 병원은 최대 수량, 식단은 적용 간격을 설정한다.
5. 확인창 제목·안내·실행·취소 문구를 입력한다. 비워 둔 문구는 플레이어 기본값을 사용한다. 실제 비용과 수량, 효과 요약은 플레이어가 별도로 표시한다.
6. **현재 화면에 목록 배치**를 누른다. 캔버스에서 위치·크기·앵커를 조정한다. 병원·식단·판매 위젯의 **위젯 구성**에서도 같은 작업실을 연다.
7. 집이나 도시 화면에 이동 버튼을 연결하고 **저장 → 처음부터 플레이**로 실행한다. 화면 이동은 현재 장소를 바꾸지 않으므로, 시설의 이용 장소와 실제 장소가 맞아야 한다. 장소 이동 버튼은 위치도 변경한다.

## 실행 규칙

- **구매:** 단가 × 수량을 지불하고 소지품을 늘린다. 돈, 재고, 최대 소지량, 작성한 최대 거래 수량을 검사한다.
- **판매:** 매입 단가 × 수량을 받고 소지품을 줄인다. 보유량과 화폐 상한을 검사하며 장착 중인 장비를 판매할 수 없다. 판매는 상점의 구매용 재고를 늘리지 않는다.
- **병원:** 선택한 수량만큼 비용과 효과를 적용한다. 증감 효과는 반복되며 고정값은 지정값으로 설정된다. 실제 효과가 전혀 없으면 비용을 청구하지 않는다.
- **식단:** 선택 시에는 비용이나 효과가 발생하지 않는다. 다음 일정 실행 직전에 적용하고, 이후 설정한 일정 칸 간격으로 반복한다. 기본 1칸은 프로젝트의 `periodsPerMonth`에 따른 일정 단위이며 달력 하루가 아니다. 선택 해제·재선택으로 적용 시점을 앞당길 수 없다.
- 식단과 해당 활동의 비용을 함께 지불할 수 없으면 그 일정 명령 전체가 거부된다. 일부 비용이나 효과만 남지 않는다.
- 확인창의 취소 또는 Escape는 명령을 실행하지 않으며 상태 버전도 바꾸지 않는다. 확인창의 명령과 버전을 고정하고 한 번 소비한 확인은 다시 실행하지 않는다.
- 확인창이 열린 동안 저장·불러오기와 뒤쪽 게임 행동을 막는다. 취소하거나 확정한 뒤 F5/F9를 사용한다. 미확정 확인창은 저장 대상이 아니다.
- 현재 식단과 다음 적용 시점, 돈·소지품·능력치는 저장에 포함된다. 저장 내용을 명령 재생으로 검증한다.

## 데이터와 호환성

`gameplay.diets`, `gameplay.services`, `gameplay.shops[].sellOffers`가 추가되었다. 구매/판매 상품에는 `maxQuantity`, `confirmation`을 설정할 수 있다. 식단은 `intervalPeriods`를 사용한다. 새 런타임 명령은 `setDiet`, `useService`, `sell`이다. 시각 요소는 `diets`, `services`, `sell`이며 기존 `shop` 목록도 수량 선택을 지원한다.

기존 프로젝트와 기존 구매 저장 기록을 유지하기 위해 새 필드는 선택 사항이다. 시설 기능을 사용하는 프로젝트는 `facilities-v1`을 지원하는 Windows/웹 런타임으로만 내보낼 수 있다. 모바일·콘솔에서의 이번 기능 실기 검증은 포함하지 않는다.

Windows 확인창은 실제 C++ 명령을 복제 상태에 계산해 범위 제한까지 반영한 수치 변화를 표시한다. 웹은 작성된 비용·효과 요약을 표시하고 실행 시 같은 C++ Wasm 코어가 최종 판정한다.

## 검증 자료

- `native/studio/facilities-test.inc`: Qt 폼으로 네 시설과 화면 이동을 제작하고 저장·새 편집기로 다시 열기·실제 Windows 플레이를 수행한다. 취소 전후 전체 상태가 동일한지, 구매·판매·수량 치료 결과와 F5/F9 복원이 맞는지 검사한다.
- `tests/gameplay/facilities.test.mjs`, `tests/native/facilities.test.mjs`: 비용·수량·범위·상태 버전, 식단 주기, 원자적 실패, TypeScript/C++ 일치와 저장 재생 검증.
- `.cache/qt-facilities-evidence`: GUI에서 작성된 프로젝트, 실행 명령, 실제 플레이 보고서와 스크린샷.
- `native/studio/pm2-facilities-test.inc`: 기존 PM2 복사본의 식단·병원·매입표를 Qt 폼으로 작성하고 실제 플레이한다. `.cache/pm2-facilities-evidence`에 결과를 남긴다.
- `scripts/verify-facilities.mjs`: GUI 작성 데이터를 Windows·웹으로 내보내고 실제 브라우저에서 네 종류의 취소, 중복 확인, 저장 다운로드·파일 업로드 복원을 확인한다. `.cache/facilities/latest.json`에서 최근 결과를 찾을 수 있다.

이번 검증에서는 Qt 전체 14개 항목과 별도 PM2 화면 정리·플레이 검증이 통과했다. 거래/식단 TypeScript 신규·기존 15개, C++ 신규·기존 일치 검증 10개, 실제 Wasm 명령 전달 검증 1개가 통과했다. 최종 PM2 Windows·웹 내보내기 실행은 500G에서 차 2개 구매 후 460G, 1개 판매 후 468G, 진료 2회 후 418G와 체력 110을 확인했다. 네 확인창 모두 취소 시 전체 상태가 같았고, 저장 파일 복원 결과도 완전히 같았다. 보고서는 `docs/evidence/facilities`에 보관했다.

질병별 치료 공식, 질병 상태 전용 편집기, 체중·영양소 모델은 이번 범위에 포함하지 않는다. 현재는 프로젝트에 정의된 능력·자원에 비용과 효과를 연결하는 시설 제작 도구다.
