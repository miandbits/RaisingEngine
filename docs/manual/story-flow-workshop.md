# 이야기 제작 작업실

## 목적

새 콘텐츠를 확장하기보다, 인물 → 활동 → 만남과 선택 → 관계 변화 → 후속 사건을 ID·JSON·조건식·표 입력 없이 만드는 제작 흐름을 개선한다. Qt 상단 `이야기 제작`과 콘텐츠 메뉴에서 같은 작업실을 연다.

## 작업 흐름

1. 이야기 이름, 만날 인물, 변화시킬 관계를 정한다. 인물과 관계는 이름으로 선택하거나 그 자리에서 만든다.
2. 주인공이 일정에서 할 활동을 고른다. 새 활동은 이름·비용 자원·능력 변화량으로 만들고, 분류가 있는 일정 화면에는 표시할 분류를 선택한다.
3. 만남 제목, 인물의 대사, 질문, 발생할 일정 범위를 쓴다. 이 활동을 한 번 이상 한 뒤 일정 끝에 최초 한 번 발생한다.
4. 선택지마다 문구·응답·관계 변화량을 정한다. 후속 사건을 켜면 그 선택을 경험했고 관계 기준과 일정 기준을 충족할 때 열리도록 연결한다.
5. 연결 트리를 확인한다. 트리 항목을 두 번 누르면 해당 제작 단계로 돌아간다. 적용 후 프로젝트를 저장하고 플레이한다.

저장된 이야기를 다시 선택해 문구·대사·숫자·발생 시점·후속 사건을 수정할 수 있다. 작업실 안에서 다른 이야기를 선택했다 돌아와도 입력 중인 초안은 유지한다. 기존 이야기의 인물/관계/활동 대상 교체는 연결 손상을 피하기 위해 잠겨 있다. 다른 대상은 새 이야기로 만든다.

## 데이터와 호환성

- 런타임 전용 게임 분기를 추가하지 않는다. 일반 character/activity/event 문서와 기존 플래그·관계 효과·완료 조건으로 구성한다.
- 생성한 문서는 기존 대본/활동 도구에서도 사용할 수 있다. 다만 다른 도구에서 소유 문서를 변경한 뒤 작업실에서 다시 적용하면 충돌로 거부한다. 고급 편집 내용을 자동으로 평탄화해 잃어버리지 않는다.
- 프로젝트의 선택 필드 `authoring.storyFlows`에 편집 상태와 소유 문서 해시를 저장한다. 이 필드가 없는 기존 프로젝트는 그대로 유지한다.
- 비용/능력 효과는 새 활동일 때만 작성한다. 기존 활동에는 경험 여부를 기록하는 효과 하나만 추가하며 기존 조건·비용·성공 판정은 보존한다.
- 기존 관계를 고르면 인물 문서를 수정하지 않는다. 새 관계를 추가하면 다른 관계와 초상을 유지한다.
- 관계는 현재 프로젝트의 공유 관계를 사용한다. 다인 로스터의 개인별 만남 이력을 자동으로 만들어 주는 도구는 아니다.
- 후속 사건을 해제해도 문서를 삭제하지 않고 발생 불가능하게 바꾼다. 외부 참조와 이전 저장의 문서 ID를 보존한다.
- 적용은 기존 편집 서비스의 배치 트랜잭션과 버전 확인을 사용한다. 전체를 실행 취소/다시 실행할 수 있다. 프로젝트 저장과 플레이 저장은 별개다.
- 만남 우선순위는 80, 후속 사건은 70이다. 같은 일정의 여러 사건 처리 여부는 기존 프로젝트 설정을 유지한다. 다른 사건과의 우선순위 조정은 기존 대본 도구에서 가능하다.

## 검증

`tests/native/story-flow-authoring.test.mjs`는 테스트 전용 C++ 실행 파일로 실제 작업실의 생성 로직을 호출한다. 별도 생성기를 흉내 내지 않는다.

- 일반 스키마/의미 검증, 기존 데이터 보존, 다시 열어 수정
- 잘못된 참조·일정·관계 범위·중복 선택지의 적용 거부
- 필터된 일정 목록에 활동 연결, 연결 누락 거부
- 다른 도구에서 수정한 문서의 덮어쓰기 거부
- 후속 사건 해제 시 참조 보존
- 기존 인물·관계·활동 재사용과 완료 효과의 중복 추가 방지
- 두 선택 분기의 C++/TypeScript 실행 일치, 선택하지 않은 후속 사건 차단, 대사/선택/관계/후속 사건 경계의 저장 재생

현재 자동 검사 결과: 위 생성·실행 통합 검사 5개 통과. 독립 재시험에서 발견한 접근성 선택 회귀를 추가해 Qt 위젯 검사 28개도 통과했다. 위젯 검사는 선택지 전환 때 문구/관계/후속 대사가 유지되는지, 연결 트리의 분기, 버전 충돌 시 적용 차단과 오류 표시, 선택만 변경하는 접근성 동작에서 편집 폼·제작 단계가 함께 바뀌는지 확인한다. 화면 없는 검사에는 `QT_QPA_PLATFORM=offscreen`, `QT_QPA_PLATFORM_PLUGIN_PATH=C:/Qt/6.10.1/mingw_64/plugins/platforms`를 지정한다.

첫 사용성 시험은 Windows Computer Use 실행·상태 조회가 반환되지 않아 제품 GUI에 진입하지 못했다. 당시 미검증 기록은 첫 시도 보고서 (historical internal evidence; not distributed)에 보존했다.

이후 정상 동작하는 공식 데스크톱 도구 연결을 확인하고, 이전 대화를 전달하지 않은 새 에이전트에게 제작 목표만 주어 재시험했다. 에이전트는 편집기에서 새 프로젝트, 소하·신뢰 관계, 약초 손질 활동, 만남·두 선택·후속 사건을 만들었다. JSON이나 소스 편집 없이 저장·재열기·문구 수정·기본 플레이 화면 생성까지 수행했다.

- 도움 선택: 신뢰 +3, 두 번째 일정에 답례 사건 발생. 선택 전·선택 후·후속 사건 도중 저장과 불러오기 확인.
- 거절 선택: 신뢰 -1, 중간 저장 복원 후 전체 6개 일정과 엔딩까지 답례 미발생. 활동 반복에도 첫 만남 중복 없음.
- 저장된 이야기의 문구 수정이 새로운 실제 플레이의 선택지에 반영됨.
- 부모는 실제 플레이어가 작성한 저장의 사본만 읽어 관계 0 / 3 / 3 / -1을 별도로 확인했다. 저장 파일 편집이나 상태 주입으로 경로를 만들지 않았다.

첫 재시험부터 막힘이 없었던 것은 아니다. 접근성 호출이 동기 모달 진입에 걸리는 문제와, 목록 선택 강조만 바뀌고 폼이 남는 문제를 발견했다. 별도 빌드에서 비동기 모달과 선택 동기화를 수정했고, 같은 에이전트가 실제 GUI의 의미 기반 열기·선택지 선택·제작 단계 선택을 다시 확인했다. 작은 제작 흐름의 통과이며, 모든 규모의 제작 사용성이 검증됐다는 뜻은 아니다.

시험 프로젝트: `.cache/blind-story-retest/game`.
결과와 남은 불편: 독립 재시험 보고서 (historical internal evidence; not distributed).
도구 복구 및 결함 재현/수정: 복구 기록 (historical internal evidence; not distributed).

최종 프로젝트 정적 검사: 문서 19개, 오류 0·경고 0 (`.cache/creator-retest-project-validation.json`). 실제 저장 사본 네 개의 읽기 전용 감사 결과는 `.cache/blind-story-retest/save-audit.json`이다. 기본 생성 플레이 화면의 관계 수치 표시와 엔딩 이후 추가 저장의 실제 조작은 이번 시험에서 완결하지 않았다. 엔딩 화면에는 저장/불러오기 버튼이 있으며, 중간 저장·복원은 위와 같이 검증했다. 엔딩 이후에는 도구의 창 초점 제한으로 추가 저장·정상 종료 기록을 확보하지 못했다.
