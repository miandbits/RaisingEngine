# 날짜·활동·장소에 연결한 후속 사건

사건 연결 지도에서 선택·약속을 연결하고, 후속 사건이 발생할 시점을 이름으로 정할 수 있다. Windows와 C++/Wasm 웹 플레이어가 같은 규칙을 사용한다.

## 편집기에서 연결하기

1. 대본 도구에서 선행 사건을 열고 **사건 연결 지도**를 연다.
2. 선행 사건이나 특정 선택지를 고른 뒤 후속 사건을 만든다. 기존 후속 사건을 연결할 수도 있다.
3. 해당 선택에서 기록한 약속을 선택한다. 캐릭터별 사건이면 선행 사건 완료·선택 경험·약속 조건을 모두 **같은 행동 캐릭터**의 기록으로 만든다.
4. **발생 시점**과 일정 범위를 정한다. 날짜는 숫자 ID 대신 프로젝트 달력의 연·월·몇 번째 일정으로 선택한다.
5. 활동 뒤에 열려면 활동을, 장소에 도착하면 열려면 장소를 이름으로 선택한다. 조건 미리보기를 확인하고 적용한 뒤 프로젝트를 저장한다.
6. 지도에서 활동·장소와 후속 사건의 연결을 확인한다. 대본의 기본 정보에서도 발생 시점·활동·장소를 다시 편집할 수 있다.

| 발생 시점 | 판정 시점 | 설정 예 |
|---|---|---|
| 일정 시작 | 새 일정 구간에 진입할 때 | 시작·종료를 모두 1년 4월 두 번째 일정으로 지정 |
| 활동 완료 | 활동 결과를 확인한 뒤 | 검술 수업을 마친 캐릭터의 약속 확인 |
| 장소 도착 | 다른 장소에서 지정 장소로 실제 이동했을 때 | 마당에 도착했을 때 각자의 약속 확인 |
| 선행 사건 직후 | 선행 사건의 대본이 끝날 때 | 기존 즉시 후속 사건 |

기존 사건을 연결할 때 **기존 방식 유지 / 새 사건은 기본 방식**이 기본이다. 발생 시점을 바꾸지 않으면 기존 기간·활동·장소 설정도 보존한다. 취소하거나 검증에 실패하면 원본 문서를 변경하지 않는다.

## 캐릭터와 발생 순서

- 캐릭터별 활동 사건은 실제 완료한 **그 캐릭터의 활동 결과**로 판정한다. 첫 캐릭터가 검술 수업을 하고 두 번째 캐릭터가 휴식했다면 검술 후속 사건은 첫 캐릭터에게만 열린다.
- 장소는 현재 파티의 공유 위치다. 지정 장소에 도착하면 각 캐릭터의 개인 조건을 따로 검사한다. 캐릭터마다 독립된 지도 위치를 제공하는 기능은 아니다.
- 같은 약속을 기록하는 두 선택지가 있어도, 특정 선택에서 연결한 후속 사건에는 **그 선택을 직접 경험한 기록**이 추가로 필요하다. 다른 캐릭터의 기록으로 대신 통과하지 않는다.
- 여러 사건이 가능하면 우선순위·사건 ID 순으로, 같은 사건의 여러 캐릭터는 로스터 순서로 처리한다. 각 사건의 즉시 후속 대본을 마친 뒤 다음 캐릭터로 이어진다.
- 새 발생 방식의 사건은 캐릭터별로 한 번만 완료한다. 공유 사건은 프로젝트 전체에서 한 번이다. 공유 활동 사건은 기존 대표 활동 결과를 사용하므로 각자의 활동을 구별하려면 캐릭터별 범위를 사용한다.

## 날짜와 저장의 범위

날짜 단위는 프로젝트의 **일정 구간(period)** 이다. 일정을 월 4개로 설정했다면 한 달에 네 번의 시작 시점이 있다. 시작과 종료를 같게 두면 그 구간에서만 가능하고, 범위를 넓히면 그 안에서 조건을 만족하는 시작 시점을 기다린다. 첫 구간(0)은 새 게임 시작에도 검사한다. 이미 지난 구간은 뒤늦게 발생시키지 않는다.

이 기능은 정해진 달력 구간을 연결한다. 대사에서 “내일”이라고 썼다고 상대 날짜를 계산하거나, 특정 시각·현실 시간에 예약하지는 않는다. 활동·장소 사건의 일정 범위 역시 발생 가능한 기간을 제한한다.

후속 사건 도중 저장하면 행동 캐릭터, 개인 선택·약속, 다음 사건을 검사할 발생 시점, 복귀 화면·진행 단계가 함께 유지된다. 불러온 뒤 남은 캐릭터의 사건을 이어서 처리한다. 새 필드가 없는 기존 프로젝트와 저장은 기존 동작을 유지한다. 콘텐츠 자체를 바꾼 뒤의 옛 저장은 별도의 콘텐츠 이전 절차를 따른다.

## 내보내기와 검증

새 발생 방식을 사용하는 프로젝트는 `story-appointments-v1` 기능을 요구한다. 최신 Windows 플레이어와 Wasm·웹 플레이어를 함께 빌드해야 한다. 예전 런타임으로 내보내기는 명확한 오류로 막으며, 선언 파일만 복사해서 지원을 가장하지 않는다. 이미 게시된 프리뷰 설치 파일에는 소급 적용되지 않는다.

```sh
npm run build:headless
npm run build:native-player
npm run build:web
node --test --test-concurrency=1 tests/native/story-appointments.test.mjs tests/native/story-appointments-web.test.mjs tests/runtime/actor-story-export.test.mjs
```

2026-10-21 검증: Qt 사건 지도·후속 사건 폼 검사 96개 및 위 런타임·웹 컨트롤러·내보내기 검사 11개 통과. 장소 진입 규칙과 후속 사건 모두 현재 장소에 머무르는 명령에는 다시 발동하지 않는지도 검사했다. 같은 두 캐릭터 프로젝트의 사본에서 실제 Qt 대화상자·저장 위젯을 오프스크린 자동 조작하여 날짜·활동·장소 후속 사건을 제작했다. 이동 장소와 버튼은 공통 편집 서비스를 통해 준비했다. 이 과정은 수동 마우스 제작 시험과 구분한다.

내보낸 Windows 플레이어와 실제 Chrome에서 두 캐릭터의 약속, 장소 사건의 순차 처리, 서로 다른 활동, 다음 일정의 날짜 사건을 플레이했다. 세 사건 도중 저장·복원과 새 프로세스/페이지에서 불러오기를 확인했으며 **다섯 웹 저장 지점의 전체 상태가 Windows의 대응 지점과 정확히 일치**했다. 원본 프로젝트·사용자 저장은 보존했고 검증 사본과 화면 증거는 공개 저장소 밖에 둔다. 다른 브라우저·모바일·콘솔까지 검증했다는 의미는 아니다.
