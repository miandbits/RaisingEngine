# 콘텐츠 저장 시 기준 경로 자동 비교

프로젝트를 저장하면 파일 저장을 먼저 마치고, 저장 당시의 스냅샷으로 **목표 경로·중간 저장 복원 검사와 기준 경로 비교**를 백그라운드에서 실행한다. 검사하는 동안 계속 편집할 수 있다. 저장 성공과 비교 성공은 별개다. 비교 실패 때문에 이미 저장된 콘텐츠를 되돌리거나 기준 기록을 갱신하지 않는다.

## 사용 방법

1. 목표 경로를 등록하고, 수정 전 실행 결과를 [기준 기록으로 저장](goal-route-history.md)한다.
2. 콘텐츠를 편집하고 **프로젝트 저장**을 누른다.
3. 저장 후 상태 표시줄의 **저장 검사** 버튼이나 디자인 → **저장 검사 진행 · 결과…**에서 진행률과 취소를 확인한다. 결과 창은 자동으로 열리지 않는다. 기준 비교 결과는 디자인 → **저장 기준 비교 결과…**에서 연다.
4. **변화 · 주의 항목만**을 켜면 동일한 경로가 숨겨진다. 경로를 선택하면 세부 값·규칙 변경·실패 정보를 확인할 수 있다.
5. **차이 시작 그래프로 이동** 또는 행 더블클릭으로 첫 차이 단계에 바로 이동한다. 왼쪽은 저장된 기준 결과, 오른쪽은 검사한 현재 등록 경로의 재실행 결과다.

## 검사 중 편집과 다시 저장

검사는 저장할 때 확보한 콘텐츠와 경로 명령을 사용한다. 검사 도중 편집해도 실행 중인 경로에 새 초안이 섞이지 않는다. 결과의 저장 버전과 콘텐츠 지문을 확인하고, 이전 저장본 결과는 새 초안의 통과 결과로 사용하지 않는다.

같은 내용으로 다시 저장하면 진행 중인 검사를 유지한다. 내용이나 등록 경로가 바뀐 새 저장은 이전 자동 검사를 취소하고 가장 최근 저장본을 검사한다. 여러 번 저장해도 예전 저장본 검사가 무한히 쌓이지 않는다. 수동 검사가 실행 중이면 자동 검사는 기다리며, 저장 때문에 제작자가 시작한 수동 검사를 취소하지 않는다.

검사 진행 창을 닫아도 저장 후 자동 검사는 계속된다. 취소 버튼은 자동 검사만 중단하며 저장된 파일에는 영향을 주지 않는다. 프로젝트를 바꾸거나 편집기를 종료하면 해당 편집기가 소유한 검사를 종료한다. 취소·시간 초과·미실행은 통과와 구분한다.

## 결과 해석

| 결과 | 의미 |
| --- | --- |
| 도달 / 실행 실패 | 목표 엔딩·사건에 도달하지 못했거나 명령 실행이 중단됨. 기준의 도달 여부도 함께 표시하므로 기준도 실패했는지 구분할 수 있음 |
| 변화 있음 | 상태, 능력·자원, 조건·비용·효과, 경로 명령·시작 조건 또는 런타임이 달라짐 |
| 동일 | 검사한 상태와 관측 결과에 위 변화가 없음. 외부 에셋이나 픽셀까지 동일하다는 뜻은 아님 |
| 기준 없음 | 등록 경로에 대응하는 기준이 없음. 자동으로 기준을 만들거나 통과 처리하지 않음 |
| 미완료 / 검사 오류 | 시간 제한, 손상된 기록 등의 이유로 비교를 완료하지 못함 |

각 경로 ID에 연결된 **가장 최근의 유효한 기준 기록**을 사용하고 이름과 시점을 보고서에 남긴다. 손상된 기준이 있으면 별도로 오류 수를 표시하며 전체 검사가 완료되었다고 표시하지 않는다. 기준 파일은 덮어쓰지 않는다. 새 기준을 저장하면 다음 콘텐츠 저장부터 해당 기준을 사용한다.

현재 경로 파일의 명령이나 초기 조건이 수정되었다면 **경로 명령/시작 조건** 변화로 표시한다. 기준 안의 예전 명령으로 현재 등록 경로를 대신하지 않는다. 과거와 현재 경로의 길이가 달라도 실패 이후의 현재 상태는 만들지 않는다.

조건·효과 검사 결과에는 이전 단계에서 누적된 상태 차이가 반영될 수 있다. 그래프의 **콘텐츠 변경 원인** 및 실행 전 상태 차이로 직접 규칙 변경과 누적 영향을 구분한다. 규칙 변경을 유일한 원인으로 증명하는 검사는 아니다.

## 결과와 그래프의 연결

보고서는 `.studio/goal-impact-<UUID>.json`에 저장한다. 등록 경로 목록, 각 경로의 지문, 기준 ID·무결성 값, 콘텐츠 지문, 런타임 식별자를 함께 기록한다.

그래프를 열 때 이 값들을 다시 확인한다. 콘텐츠·등록 경로·기준·런타임이 검사 당시와 다르면 다시 저장해 검사하라는 안내를 표시한다. 검사 결과에서 연 그래프는 해당 보고서에 고정되며 다른 기준으로 바뀌지 않는다. 새 초안으로 임의 재계산해 예전 보고서의 결과처럼 보여주지 않는다.

최근 저장 결과는 편집기를 다시 실행해도 불러올 수 있다. 콘텐츠나 등록 경로가 바뀌었다면 오래된 결과임을 표시한다. 검사 도중 편집한 초안은 검사 대상이 아니다. 비교 중 콘텐츠가 외부에서 바뀌면 현재 저장의 정상 결과로 게시하지 않는다.

## 한도와 검증

- 목표 경로 검사는 경로별 시간 예산을 사용한다. 한 경로의 시간 초과와 시작하지 않은 경로를 구분하며, 시간 초과는 통과가 아니다. 기준 비교 역시 별도로 완료 여부를 표시한다. 기준이 없는 경로를 회귀 검사 통과나 비교 성공으로 해석하지 않는다.
- 저장 후 자동 검사의 기본 예산은 경로당 120초, 기준 비교를 포함한 전체 작업은 900초다. 더 긴 경로는 목표 경로 도구에서 선택 검사와 시간 제한을 설정한다.
- 경로별 변경 값과 관련 규칙 예시는 각각 최대 40개를 보고서에 보관하고 전체 개수를 표시한다. 전체 단계 비교는 그래프에서 확인한다.
- 보고서 파일은 최대 8 MiB다. 기준 파일과 그래프의 기존 크기 제한도 적용된다.
- `tests/analysis/goal-impact.test.mjs`: 저장 자동 검사, 변화/동일/기준 없음, 엔딩·실행 실패, 최신 기준 선택, 기준 보존·손상, 시간 제한, 보고서 재열기, 변경된 콘텐츠/경로의 그래프 차단.
- `tests/qt-studio/save-background.test.mjs`: 저장·편집 응답성, 연속 저장 통합, 저장 당시 입력 보존, 수동 검사 대기, 취소와 종료, 기준 변경 차단, 검사 시작 실패 시 저장 보존.
- `native/studio/goal-impact-test.inc`: 속성 편집 → 저장 → 백그라운드 완료 → 결과 창 → 필터 → 첫 차이 그래프 → 다시 편집 시 이전 결과 표시 → 재저장 갱신.
- 검증 증거: `docs/evidence/goal-impact/`. 사용자 원본과 분리된 시험 프로젝트에서 검증한다.


경로별 의도한 변경 승인과 이전 기준 복원은 [goal-baseline-approvals.md](goal-baseline-approvals.md)를 참고한다. 명시적으로 선택한 활성 기준은 최신 파일 생성 시각보다 우선한다.
