# 제작 상태 미리보기

게임을 진행하지 않고 캐릭터·사건·상태에 따른 실제 값과 조건별 표현을 확인한다.

편집 캔버스 자체에 저장 상태를 적용하고 배치를 수정하려면 [실제 저장 상태로 화면 편집](canvas-state-preview.md)을 사용한다. 아래의 별도 검사 도구와 동일한 Windows 렌더러를 사용하며, 캔버스 검사 설정은 프로젝트별로 복원된다.

## 사용 방법

1. 화면을 열고 도구 모음의 **실제 렌더러 검사**를 연다.
2. **검사 대상**에서 부품 전체 또는 자식 요소를 선택한다.
3. **제작 상태 설정**에서 **가상 검사 상태 사용**을 켠다.
4. **기준 상태**에서 새 게임 또는 **플레이 저장 · 재현 검사**를 선택한다. 저장을 선택하면 같은 콘텐츠에서 만든 플레이 저장 JSON을 지정한다. C++ 코어가 명령을 재생해 저장 상태와 일치하는지 검사한다.
5. 캐릭터와 검사할 사건을 선택한다. 필요하면 활동·능력치·자원·사용자 정의 상태·선택/약속 기록을 가상으로 변경한다. 플래그는 **공용 기록 / 선택 캐릭터의 기록**을 구분한다. 숫자는 프로젝트에 정의한 범위 안에서만 입력한다.
6. 적용 후 **현재 화면 렌더링**을 누른다. 해상도·언어·버튼 상태도 바꿔 검사할 수 있다.
7. **대상·상태·조건**에서 현재 값과 기준 값, 사건 조건의 충족 여부, 선행 사건·선택·약속의 이름과 실제 값을 확인한다. 발생 시점·활동/장소 연결은 필요 조건과 별도로 표시한다. 조건이 충족돼도 현재 단계에서 자동 발생하지 않는 사건이 있다.
8. 화면·표현 규칙에서 적용된 첫 규칙과 탈락 이유를 확인한다. 요소 행을 누르면 제작 대상으로 이동한다. **비교 기준으로 보관**하면 두 결과를 나란히 볼 수 있다.

기본은 편집 중인 화면을 고정해서 검사한다. **조건에 따라 연결된 화면 확인**을 켜면 플레이와 같은 화면 연결 우선순위를 사용한다. 화면 고정과 실제 연결 결정은 이유 목록에서 구분한다.

캐릭터는 화면 전체를 검사할 때도 선택할 수 있다. 이때 수치와 사건 조건의 검사 대상만 바뀐다. 부품을 선택했다면 캐릭터·활동 연결을 그 부품 인스턴스에만 적용한다. 다른 부품의 명시적 연결과 자식의 더 구체적인 연결은 유지한다. 능력치는 선택한 캐릭터의 개인 값 또는 프로젝트의 공용 값으로 구분된다. 같은 캐릭터를 참조하는 다른 UI에는 같은 임시 수치가 표시된다.

**기준 상태 유지**는 초기 상태 또는 선택한 저장의 해당 값을 덮어쓰지 않는다. 숫자는 **변경**을 켠 항목에만 입력한다. **초기화 → 적용**은 가상 검사를 해제한다. 프로젝트를 바꾸면 검사 설정을 지운다. 설정·콘텐츠가 바뀐 후에는 이전 결과라는 안내가 표시된다.

## 격리와 호환성

- 기존 프로젝트와 저장 스키마 변경 없음. 검사 설정은 프로젝트에 저장하지 않는다.
- 편집기 서비스의 현재 초안과 같은 검증·내보내기를 거친 임시 번들에 별도 검사 파일을 만든다. 저장하지 않은 UI도 검사할 수 있다.
- 초기 실행 상태 또는 재현 검증한 저장 상태의 복사본만 수정한다. 프로젝트 파일, 버전, 실행 취소/다시 실행, 본편 저장과 도감 기록을 변경하지 않는다.
- 저장 파일의 콘텐츠 지문이 다르거나 명령 재현 결과와 수치가 다르면 오류로 표시한다. 이 도구에서 저장을 자동 마이그레이션하거나 덮어쓰지 않는다. 콘텐츠 수정 뒤에는 기존 저장 마이그레이션/경로 검증 도구를 사용하거나 수정된 콘텐츠로 새 저장을 만든다.
- 선택한 사건은 조건만 검사한다. 강제로 사건을 시작하지 않는다. 다른 캐릭터의 대화 중이어도 선택한 캐릭터의 조건을 검사하며, 저장 속 대화 대상은 유지한다.
- Windows 렌더러는 `--preview-screen`과 함께 전달된 `--preview-inspection`만 받아들이며 번들의 지문을 검사한다. 미리보기 중 게임 명령·저장·자동 진행은 기존 격리 정책을 따른다.
- `authoring-preview-v1` 기능이 없는 구형 런타임은 명시적으로 거부한다. 기존 초기 상태/장면 미리보기는 계속 지원한다.
- 조건부 화면 연결과 부품 확장·표현 조건은 기존 공통 함수를 사용한다. 버튼의 실제 실행 가능성은 렌더러의 진단 결과에서 확인한다.

## 범위

재현 검증한 저장은 실제 명령 경로의 상태를 사용한다. 값을 덮어쓴 가상 상태는 실제 도달 가능한 상태라는 보장이 없다. 모든 전투·탐험·회상 연출 시점의 동일성을 이번 시험에서 검증한 것은 아니다. 경로 도달과 게임 진행 자체는 실제 플레이와 목표 경로 회귀 검사로 확인한다. 캔버스의 편집용 자리표시자 전체를 교체하는 기능은 아니며, **실제 렌더러 검사**에서 플레이와 같은 렌더링을 확인한다.

렌더러 검사 화면은 Qt/Windows 기반이다. 웹은 같은 작성 데이터로 내보내고 실제 브라우저 플레이·저장 복원을 별도로 검사한다. 웹에서 이 제작 검사 패널을 제공한다는 의미는 아니다.

## 검증

- `tests/qt-studio/authoring-preview.test.mjs`: 검사 값/대상 검증, 개인 상태 격리, 표현 이유, 조건 화면 우선순위, 구형 런타임 거부, 파일·초안·이력 불변성.
- `native/studio/state-preview-test.cpp`: 별도 프로젝트/재현 가능한 저장을 받아 실제 제작 위젯에서 캐릭터·사건·저장 선택 → Windows 렌더링 비교 → 가상 값 변경 → UI 이름 편집 → 저장·재열기. `RAISING_STATE_PREVIEW_PROOF`에 시험 설정 JSON 경로를 지정하며 비공개 프로젝트를 포함하지 않는다.
- `native/studio/authoring-preview-test.inc`: 실제 Qt 제작 위젯으로 텍스트 작성 → 초안 미리보기 → 캐릭터/활동/상태/능력치 변경 → 조건 버튼/표현 확인 → 세로 해상도 → 프로젝트 저장.
- `tests/native-player/authoring-preview.test.mjs`: 실제 Windows 렌더링, 명령 차단, 저장 격리, 다른 지문/플레이 모드 검사 파일 거부.
- 기존 `component-context` Windows·브라우저 시험은 GUI로 저장한 같은 프로젝트 복사본을 받아 독립 캐릭터 행동·배정·조건·엔딩 및 중간/엔딩 저장 복원을 확인한다.

Qt 시험은 `RAISING_QT_AUTHORING_PREVIEW=1`, `RAISING_QT_PROJECT=<component-context 복사본>`을 사용한다. 플레이 시험은 `RAISING_COMPONENT_CONTEXT=<root가 복사본인 fixture JSON>`을 공유한다. 새 런타임 경로는 `RAISING_NATIVE_PLAYER_RUNTIME`으로 지정할 수 있다.

`qt-state-preview-test`는 별도 빌드 대상이다. `RAISING_STATE_PREVIEW_PROOF` JSON에는 `root`(편집 가능한 시험용 복사본), `output`(증거 폴더), `save`(동일 콘텐츠에서 재현 가능한 저장), `screen`, `element`, `attribute`, `override`, `event`, `actors`, `texts`를 지정한다. `actors` 각 항목은 `id`, `rowLabel`(예: `검술 · 연화`), `value`(문자열), 선택 항목 `requirements`(모든 조건의 예상 참/거짓)를 가진다. `texts`는 실제 플레이에서 수집한 요소 ID별 문구다. 시험은 UI 이름을 변경하고 저장하므로 반드시 복사본을 사용한다. 설정이 없으면 시험을 건너뛴다.

- 두 육성 대상의 저장 당시 개인 능력 20/10, 피로 6, 공용 자금 16이 Windows 플레이와 제작 미리보기에서 일치했다. 같은 저장에서 선택·약속 조건의 충족/미충족도 대상별로 달랐다.
- Qt 생산 위젯을 조작하는 자동 시험으로 저장 선택, 인물 변경, 사건 조건, 실제 플레이 문구 비교, 가상 값 변경의 격리, UI 이름 편집·저장·재열기를 확인했다.

- 서비스·규칙 디버거·Windows 렌더러 회귀 검사 12개와 Qt 통합 시나리오 1개가 통과했다. 한국어/영어/일본어 리터럴 번역 검사 및 저장소 검사도 통과했다.
