# 제작 상태 미리보기

우선순위 2: 게임을 진행하지 않고 캐릭터·활동·조건별 표현을 확인한다.

## 사용 방법

1. 화면을 열고 도구 모음의 **실제 렌더러 검사**를 연다.
2. **검사 대상**에서 부품 전체 또는 자식 요소를 선택한다.
3. **제작 상태 설정**에서 **가상 검사 상태 사용**을 켠다.
4. 캐릭터·활동, 필요한 능력치·자원, 사용자 정의 상태, 플래그를 이름으로 선택한다. 숫자는 프로젝트에 정의한 범위 안에서만 입력한다.
5. 적용 후 **현재 화면 렌더링**을 누른다. 해상도·언어·버튼 상태도 바꿔 검사할 수 있다.
6. 화면·표현 규칙 목록에서 적용된 첫 규칙과 탈락 이유를 확인한다. 요소 행을 누르면 제작 대상으로 이동한다. **비교 기준으로 보관**하면 두 결과를 나란히 볼 수 있다.

기본은 편집 중인 화면을 고정해서 검사한다. **조건에 따라 연결된 화면 확인**을 켜면 플레이와 같은 화면 연결 우선순위를 사용한다. 화면 고정과 실제 연결 결정은 이유 목록에서 구분한다.

캐릭터·활동 변경은 선택한 부품 인스턴스에만 적용한다. 다른 부품의 명시적 연결과 자식의 더 구체적인 연결은 유지한다. 능력치는 선택한 캐릭터의 개인 값 또는 프로젝트의 공용 값으로 구분된다. 같은 캐릭터를 참조하는 다른 UI에는 같은 임시 수치가 표시된다.

**초기 상태 유지**는 해당 값을 덮어쓰지 않는다. **초기화 → 적용**은 가상 검사를 해제한다. 프로젝트를 바꾸면 검사 설정을 지운다. 설정·콘텐츠가 바뀐 후에는 이전 결과라는 안내가 표시된다.

## 격리와 호환성

- 기존 프로젝트와 저장 스키마 변경 없음. 검사 설정은 프로젝트에 저장하지 않는다.
- 편집기 서비스의 현재 초안과 같은 검증·내보내기를 거친 임시 번들에 별도 검사 파일을 만든다. 저장하지 않은 UI도 검사할 수 있다.
- 초기 실행 상태의 복사본만 수정한다. 프로젝트 파일, 버전, 실행 취소/다시 실행, 본편 저장과 도감 기록을 변경하지 않는다.
- Windows 렌더러는 `--preview-screen`과 함께 전달된 `--preview-inspection`만 받아들이며 번들의 지문을 검사한다. 미리보기 중 게임 명령·저장·자동 진행은 기존 격리 정책을 따른다.
- `authoring-preview-v1` 기능이 없는 구형 런타임은 명시적으로 거부한다. 기존 초기 상태/장면 미리보기는 계속 지원한다.
- 조건부 화면 연결과 부품 확장·표현 조건은 기존 공통 함수를 사용한다. 버튼의 실제 실행 가능성은 렌더러의 진단 결과에서 확인한다.

## 범위

이 기능은 초기 진행 상태에서의 가상 제작 검사다. 실제 도달 가능한 상태라는 보장은 없으며, 전투 중간·사건 선택 직후 등 임의 진행 지점 가져오기는 포함하지 않는다. 그런 경로의 검증에는 실제 플레이와 목표 경로 회귀 검사를 사용한다.

렌더러 검사 화면은 Qt/Windows 기반이다. 웹은 같은 작성 데이터로 내보내고 실제 브라우저 플레이·저장 복원을 별도로 검사한다. 웹에서 이 제작 검사 패널을 제공한다는 의미는 아니다.

## 검증

- `tests/qt-studio/authoring-preview.test.mjs`: 검사 값/대상 검증, 개인 상태 격리, 표현 이유, 조건 화면 우선순위, 구형 런타임 거부, 파일·초안·이력 불변성.
- `native/studio/authoring-preview-test.inc`: 실제 Qt 제작 위젯으로 텍스트 작성 → 초안 미리보기 → 캐릭터/활동/상태/능력치 변경 → 조건 버튼/표현 확인 → 세로 해상도 → 프로젝트 저장.
- `tests/native-player/authoring-preview.test.mjs`: 실제 Windows 렌더링, 명령 차단, 저장 격리, 다른 지문/플레이 모드 검사 파일 거부.
- 기존 `component-context` Windows·브라우저 시험은 GUI로 저장한 같은 프로젝트 복사본을 받아 독립 캐릭터 행동·배정·조건·엔딩 및 중간/엔딩 저장 복원을 확인한다.

Qt 시험은 `RAISING_QT_AUTHORING_PREVIEW=1`, `RAISING_QT_PROJECT=<component-context 복사본>`을 사용한다. 플레이 시험은 `RAISING_COMPONENT_CONTEXT=<root가 복사본인 fixture JSON>`을 공유한다. 새 런타임 경로는 `RAISING_NATIVE_PLAYER_RUNTIME`으로 지정할 수 있다.

- Qt UI 시험 통과: 실제 팔레트/속성 입력으로 텍스트를 만들고, 저장 전 렌더링에 반영. 연화의 검술 15/45, 연회/수련 표현, 버튼 비활성/활성 확인 후 저장.
- 720×1280 창에서는 이 샘플의 1280×720 고정 설계 화면을 720×405로 표시하며 위아래 여백을 유지한다. 검사 이미지도 게임 표시 영역을 캡처한다.
- 같은 GUI 저장본으로 Windows의 두 캐릭터 행동·활동 배정·선택지·엔딩, 중간/엔딩 저장 복원 통과.
- Chrome 실제 창에서 웹 내보내기 실행: 41개 상태 확인, `certified` 엔딩, 저장 다운로드/업로드·새 페이지에서 복원 통과. 브라우저 오류 없음.
- `npm run test:qt-service` 13개 검사 통과. 기존 단일 캐릭터 샘플의 새 미리보기도 별도로 포함한다. 기존 장면·조건·화면 연결 회귀 검사와 Windows 격리 검사 통과.
- Chrome 검증 중 파일 읽기 완료 전에 상태를 비교하던 시험의 대기 조건을 수정했다. 실제 UI가 “플레이 중”으로 복귀한 뒤 상태를 검사한다.
- Orca 데스크톱 제어는 `runtime_unavailable`이었다. Qt 검증은 실제 생산 위젯·창과 Windows 렌더러를 사용하는 QTest로 실행하고 캡처했다. 사람이 수동으로 검수한 결과라는 뜻은 아니다.
