# 단편 완성도 검토 — 잔설 아래 막내손자

## 이번 순서

사용자 요청에 따라 장편 내구성 검증보다 먼저 단편의 화면·조작·연출을 다듬는다. 실행 가능한 검토 빌드와 제작 프로젝트를 제공하고 **사용자 검토를 받은 뒤** 대규모 검색·편집·검증·경로 탐색 및 저장 마이그레이션 시험으로 넘어간다. 이번 단계에서 장편 내구성 검증을 완료했다고 주장하지 않는다.

원본 `tests/fixtures/projects/last-grandson`과 기존 사용자 프로젝트·저장은 보존한다. 별도 `tests/fixtures/projects/last-grandson-polished`에 동일한 두 달/두 엔딩 규칙을 유지한 시각 완성판을 제작한다.

## 검토 기준

- 타이틀 → 일정 선택 → 활동 결과 → 선택지 → 두 엔딩의 시각 언어를 통일한다.
- 캐릭터와 배경은 신규 제작한 무협 이미지이며 원작 게임의 추출 에셋을 쓰지 않는다.
- 현재 엔진에 통합된 cutout-animation 1.13.0을 사용한다. 별도 개발 중인 `RaisingEngine-anim` 작업 트리는 수정하지 않는다.
- 캐릭터의 대기·활동 반응을 실제 플러그인으로 재생하고 저장·복원 후에도 표시한다. 전신 관절 연기나 입 모양 합성까지 완료했다고 표현하지 않는다.
- 일정의 비용·효과를 읽을 수 있고, 진행/저장/불러오기와 선택지가 겹치지 않아야 한다.
- 실제 Windows 플레이에서 두 엔딩과 중간 저장·복원, 서로 다른 화면 크기를 확인한다. Qt 편집기에서 화면·애니메이션 데이터를 열고 수정·저장할 수 있어야 한다.

## 제작 기록

원본 게임은 이전 단계의 Qt GUI 제작 결과다. 이번 시각 배치는 공통 데이터 계약으로 작성한 후 실제 편집기에서 열어 조정·검증한다. 외부에서 작성한 데이터까지 전부 수작업 GUI 제작이라고 주장하지 않는다. 신규 삽화는 기본 image_gen 도구로 생성하고 사용한 프롬프트와 출처를 샘플에 기록한다.

## 구현과 수정

- 겨울 저택·약방 배경, 투명 캐릭터와 명상 표정, 종이색 일정 카드, 두 엔딩 화면을 추가했다. 신규 이미지와 원본 합성 배경음의 출처는 샘플 `assets/PROVENANCE.md`에 있다.
- cutout-animation 1.13.0의 실제 런타임과 Qt 작업실을 사용한다. 단일 초상 레이어의 숨쉬기·수련·피로·명상이며, 다관절 전신 애니메이션은 아니다.
- 공통 일정 위젯에 `showActivityDescription` 옵션을 추가했다. 기존 프로젝트는 기본값 false이며, 열 형태의 일정 칸 아래에 선택한 활동 설명을 이스케이프한 텍스트로 표시한다. 네이티브·웹·Qt 설정을 함께 연결했다.
- 기존 프로젝트 복제 기능이 `plugins` 폴더를 누락하던 문제를 수정했다. 잠금 파일·리그·컨트롤러와 에셋은 보존하고 기존처럼 저장 파일·분석 기록은 복제하지 않는다. 플러그인 실행 모듈 자체는 별도 설치가 필요하다.
- 일정 위젯 설정이 필드 조회 중 `attributeIds: null`을 삽입하여 저장을 막던 오류를 수정했다. 필드 조회가 데이터를 변경하지 않도록 했다.

## 검증 기록

- 네이티브 실제 플레이어: 생존·이별 두 엔딩, 선택지 앞과 활동 결과의 저장·복원, 프로그램 재실행 후 복원, 표정과 단발 동작 커서 복원, 960×540 및 1600×900 화면, 음악 재생·음소거 통과. 모든 게임 상태 체크포인트는 공통 런타임 결과와 비교했다.
- Qt 실제 위젯: 기존 프로젝트 복제 → 일정 검색 → 설명 표시 해제/설정 → 저장 → 애니메이션 작업실에서 idle 길이 4000→5000ms 수정 → 저장·재열기 → 검증 통과. 이 편집본으로 네이티브 두 엔딩 검증을 다시 통과했다.
- 원본 `last-grandson`의 기존 실제 플레이어 시험도 새 런타임에서 통과했다. 원본 데이터·저장 파일은 수정하지 않았다.
- 시각 계약·렌더러 회귀 58건 중 57건 통과, 기존 선택적 시험 1건 건너뜀. 첫 실행의 브라우저 4건은 기본 Chromium 실행 파일이 없어 실패했고, 설치된 Edge로 전환하여 모두 통과했다. 새 설명 옵션의 기본 비표시·선택 변경·HTML 이스케이프 검사도 통과했다.
- 복제 서비스 회귀 4건 통과. 소스와 목적지의 플러그인 자료·참조 이미지 일치 및 유효성도 검사했다.

반복 애니메이션은 기존 플러그인 정책에 따라 불러올 때 0ms부터 재생한다. 단발 클립은 저장된 시간과 자세를 복원한다. 이 시험은 원본 프로젝트의 기존 세이브를 새 시각 샘플로 이식하는 마이그레이션 시험이 아니다.

## SD 일정 실행 화면 추가 — 2026-10-15

위 검증 기록은 최초 초상 버전이다. 이후 사용자 피드백에 따라 일정 화면에 `seol-sd` 리그를 추가했다. 계획을 정할 때만 일정표·설명·상태 카드가 보이고, 활동 결과에서는 이를 숨겨 SD 동작과 능력치·자원 증감을 보여준다. 배경, 결과 확인, 저장·불러오기·음소거는 유지한다.

새 실제 플레이어 시험은 두 엔딩, 저장·복원, 각 활동의 클립 선택·프레임 변화, 활동 중 일정표 비표시를 검사한다. 수련·명상·심부름의 런타임 캡처 72프레임을 이어 붙인 9초 영상은 `.cache/short-polish/sd-activities.mp4`다. 이 영상은 실제 실행 프레임으로 구성했다.

## 순차 수치·자동 일정 — 2026-10-15

- 선택형 `visual.resultPlayback` 계약을 추가했다. `leadInMs`, `changeMs`, `holdMs`로 SD 화면의 결과 위젯 안에서 수치를 순차 보간한다. 활동에 명시적으로 연결한 기존 타임라인이 있으면 해당 연출이 우선한다. 설정 없는 기존 프로젝트는 변경되지 않는다.
- 기존 `schedulePlayback: continuous`와 타임라인 저장 커서를 재사용한다. 계산 완료된 비용·효과 기록의 `before`와 `after`만 표시하며, 연출 시간은 시뮬레이션 시간이나 난수·효과 적용 횟수를 바꾸지 않는다.
- 샘플에서 결과 확인 버튼을 없앴다. 활동 사이에는 일정표를 다시 띄우지 않고, 대사·선택지·다음 달 계획에서 멈춘다. 자동 실행 오류가 나면 계획 조작을 다시 표시한다.
- Qt 프로젝트 설정의 새 활동 결과 연출 탭에서 활성화와 세 시간을 편집한다. 신규 계약을 지원하지 않는 내보내기 런타임은 `inline-result-playback-v1` 기능 검사로 거부한다.
- 실제 Qt에서 끄기/켜기·시간 편집·저장·재열기와 기존 프로젝트 설정 시험을 통과했다. 단위/회귀 16건은 중간 표시, 음수 비용, 저장 커서, 완료 전 진행 차단, 사건 정지, 기존 타임라인 우선권, 변화 없는 결과와 수동 프로젝트 검증을 포함한다.

## 일정 실행 조작 — 2026-10-15

인라인 활동 결과 화면에 일시정지/재생, 1배/4배속, 현재 활동 연출 건너뛰기를 추가했다. 기존 타임라인 명령을 재사용하며 SD 플러그인의 표시 시계도 같은 정지·배속을 따른다. 건너뛰기는 이미 계산한 수치의 최종 표시로 이동하고, 다음 사건·선택지는 자동 통과하지 않는다. 다음 활동과 다음 달에도 선택한 배속을 유지한다.

저장 연출 정보에 선택형 `scheduleSpeed`(1 또는 4)를 추가했다. 기존 커서 전용 저장은 계속 읽을 수 있으며, 커서의 배속과 모순되는 새 저장은 거부한다. 정지 상태·표시 커서는 기존 연출 저장을 사용한다. 저장은 계산된 게임 상태와 별개이고, 불러오기 실패 시 기존 배속도 보존한다. 기존 플러그인의 반복 클립 재시작 정책은 유지하므로 일시정지 저장의 SD 포즈 자체까지 동일 프레임 복원을 보장하지는 않는다.

`tests/native-player/result-controls.test.mjs`는 실제 플레이어에서 두 엔딩을 보통·4배속·건너뛰기 각각 실행해 전체 상태·난수·이력을 비교한다. SD/수치 정지, 정지·배속 저장 및 별도 프로세스 복원, 다음 활동·월 배속 유지, 모든 대사·선택지에서 정지를 검사했다. 단위/기존 연출 회귀 17건도 통과했다. 실제 검증 보고서는 `.cache/result-controls`, 로그는 `.cache/controls-native-test.log`, `.cache/controls-unit-tests.log`에 있다.

최신 런타임은 `dist/native-player-controls/RaisingPlayer.exe`, 검토 게임은 `release/last-grandson-controls-review/RaisingPlayer.exe`다. 웹도 같은 조작 바와 SD 시계 연결을 구현하고 빌드·타입 검사를 수행했다. 실제 GUI 플레이 검증은 Windows 플레이어 기준이다.

최종 추가 회귀 3건(기존 자동 진행·실시간 사건 정지, 기존 활동 타임라인과 저장 무결성)도 통과했다. `.cache/controls-regression.log`에 기록했다. 수치가 절반 변한 시점에서 정지·복원한 실제 화면은 `.cache/result-controls/survival-fast-paused.png`다.

## 사용자 검토 후

먼저 화면의 밀도, 글자 크기, 활동 설명의 읽기 쉬움, 캐릭터 연출 강도와 이야기 분위기를 검토받는다. 상용 출시를 위한 삽화 세부 보정, 분절 캐릭터 연기, 최종 음향·현지화·출시 QA는 별도 작업이다. 사용자 검토 전에는 다음 단계인 대규모 검색·편집·검증·경로 탐색 성능과 기존 저장 파일 마이그레이션·복구 시험을 시작하지 않는다.
