# 편집기에서 GitHub Actions 경로 검토

## 사용 순서

1. 프로젝트를 열고 **디자인 → GitHub Actions · CI 경로 검토…**를 선택한다.
2. `owner/repository`와 선택적 브랜치를 입력하고 **GitHub 실행 조회**를 누른다. 프로젝트 Git origin이 github.com이면 저장소를 기본 입력한다.
3. 실행 번호·결과·브랜치·커밋·시간·제목으로 실행을 선택한다. 목록은 20개씩 이전/다음 페이지를 지원한다.
4. **선택 실행의 보고서 가져오기**로 `goal-regression-reports` 아티팩트를 메모리에서 읽는다. 별도 다운로드·압축 해제는 필요 없다.
5. 기본 선택한 **프로젝트** 보고서를 연다. **테스트/기타** 보고서는 통합 테스트가 의도적으로 만든 실패 결과를 포함할 수 있다. 이 표시를 실제 프로젝트 실패로 해석하지 않는다.
6. 경로별 CI 원본 결과와 로컬 재검증, 남은 변화, 첫 차이, 저장 복원 결과를 확인한다. **실패·변화 경로만**은 CI 또는 현재 결과에 변화가 있는 행을 남긴다.
7. 행을 두 번 누르거나 **첫 차이 그래프 · 승인 / 복원**을 선택한다. 원인과 원본·기대·현재 값을 확인하고 부분 승인·기준 복원·재검증을 수행한다.

현재 지원 워크플로 파일은 `goal-regression.yml`, 아티팩트 이름은 `goal-regression-reports`이다. `ci-goal-regression/report.json`이 프로젝트 보고서이며 다른 report.json은 테스트/기타로 표시한다. 기존 로컬 JSON 열기도 유지한다.

## 인증과 오류

- GitHub CLI `gh`를 PATH에서 실행하며 기존 `gh auth login` 인증을 사용한다. 편집기는 토큰을 입력받거나 저장하지 않는다. github.com을 명시하고 읽기 API만 호출한다.
- 인증·권한, 미완료 실행, 보고서 없음, 만료, 네트워크/요청 제한 오류를 표시하며 재조회·재시도할 수 있다. 실행 실패가 보고서 생성 전 발생하면 경로 보고서가 없을 수 있다.
- 각 요청 제한은 90초, ZIP 최대 64 MiB, JSON 하나 최대 16 MiB, 보고서 최대 32개, ZIP 항목 최대 2048개다. 아카이브 경로는 표시만 하며 디스크에 추출하지 않는다. 중복 경로·경로 탈출·손상·해제 크기 초과를 거부한다.

## 신뢰와 비교 기준

원격 보고서는 읽기 전용 원본이다. 저장소·실행 URL·SHA·아티팩트 ID·보고서 경로·SHA-256을 보존한다. 원격 파일 경로나 보고서 ID를 실행·승인 권한으로 사용하지 않는다. 현재 프로젝트 재검증이 만든 로컬 ID로만 그래프와 승인 기능을 연다.

그래프는 현재 콘텐츠와 저장된 기준으로 재실행한 결과다. CI 시점과 콘텐츠·경로·승인 기준이 다르면 차이를 명시한다. 과거 콘텐츠 전체를 자동 체크아웃하거나 GitHub에 승인 결과를 자동 쓰지는 않는다. 초안이 있으면 저장 후 재검증해야 하며, 원격 원본은 부분 승인·복원 후에도 유지된다.

## 검증

- `npm run test:regression`: 기존 CLI/보고서 승인·복원·런타임 호환 재생과 GitHub 목록/선택/재시도/세션 격리/ZIP 제한 검사.
- `goalCiReview` Qt 테스트는 기본으로 로컬 보고서를 검사한다. `RAISING_GITHUB_RUN`에 실제 실행 ID를 지정하면 편집기에서 직접 GitHub 조회 → 보고서 가져오기 → 실패 경로 → 그래프 → 부분 승인 → 복원 → 저장 복원 재검증을 수행한다. 프로젝트는 `RAISING_CI_PROJECT`의 격리된 테스트 복사본을 사용한다.
- 실제 네트워크 테스트는 로그인과 살아 있는 아티팩트가 필요하므로 일반 CI에서 강제하지 않는다. 캡처와 결과는 `docs/evidence/goal-github/`에 저장한다(로컬 증거, Git 제외).

2026-10-15 검증: 실제 실행 [38768411025](https://github.com/miandbits/RaisingStudio/actions/runs/38768411025)의 성공한 프로젝트 보고서와 의도적 실패 통합 테스트 보고서를 직접 조회했다. Qt 자동 조작으로 실패 경로의 첫 차이 이동, 소지금 부분 승인, 기준 복원, 저장/불러오기 재검증을 통과했다. 성공한 Actions 실행 안의 테스트용 실패 보고서를 사용했으며, 프로젝트 CI 실패로 주장하지 않는다. 로컬 회귀 테스트 7개도 통과했다.
