# 한 화면의 조건별 표현

Qt 속성 패널의 **조건별 표현 · 이미지·동작 연결…**에서 선택한 요소에 표현을 추가한다. 위에 있는 표현부터 평가하여 처음 맞는 한 개를 적용한다. 조건이 맞지 않으면 원래 속성으로 돌아간다. 기본 화면과 요소의 ID·위치·크기·행동은 유지된다.

## 제작

1. 텍스트, 이미지 또는 플러그인 요소를 선택한다.
2. 표현에 이름을 붙이고, 필요하면 활동을 선택한다. 활동 필터는 해당 활동의 **결과 표시 중**에만 맞는다. 다음 일정이나 지난 활동을 현재 활동으로 오인하지 않는다.
3. **조건 편집…**에서 기존 시각 조건 편집기로 능력·자원·플래그·관계 등의 조건을 연결한다.
4. 바꿀 문구·이미지·애니메이션 컨트롤러·색·불투명도를 설정한다. 애니메이션 컨트롤러 목록은 설치한 플러그인의 기존 참조 선택 목록을 재사용한다.
5. 위로/아래로 버튼으로 우선순위를 조정하고 적용한다. 화면을 복사하지 않아도 각 표현이 같은 요소에서 바뀐다.

이미지는 기본 에셋을 계속 요구한다. 컨트롤러는 먼저 애니메이션 편집기에서 만들어야 한다. 이 기능 자체가 새 클립을 생성하지 않는다. 한 컨트롤러 내부의 동작 전환과 블렌딩은 플러그인의 기존 연결 기능을 사용한다. 현재 캔버스는 기본 표현을 보여주며, 실행 결과에서 조건별 표현을 확인한다.

재사용 UI 부품은 **부품 작업실 → 자식 요소 선택 → 선택 요소의 조건별 표현…**에서 같은 편집기를 연다. 원본에 저장한 표현은 모든 배치본에 적용된다. 실제 세 활동 제작·플레이 검증은 [재사용 제작 시험](reusable-activities.md)에 기록했다.

## 계약

`element.variants`와 재사용 부품 자식의 `variants`에 최대 64개 규칙을 저장한다. 각 규칙은 `label`, 기존 조건 AST인 `when`, 선택적 `activityIds`, `values`를 가진다. `values`는 `text`, `imageAssetId`, `extensionRef`, `color`, `fill`, `opacity`만 허용한다. 게임 행동·비용·효과를 표시 규칙으로 변경할 수 없다.

원본 요소를 수정하지 않고 화면을 그릴 때 표현을 계산한다. 문구를 덮어쓰면 해당 표현에서 텍스트 바인딩을 해제하고, 이미지를 덮어쓰면 고정 에셋 연결을 사용한다. 컨트롤러 변경은 같은 플러그인·요소 종류·속성을 유지한 채 참조만 바꾼다.

조건별 플러그인 참조도 기존 플러그인 검증·내보내기 경로에 포함한다. 조건별 표현이 있는 프로젝트는 `presentation-variants-v1`을 지원하지 않는 렌더러로 내보내지 않는다. 기존 프로젝트와 구형 저장 파일의 계약은 유지한다.

플레이어는 조건별 표현 사용 여부와 관계없이 플러그인 저장에 `exact: true`를 요청한다. 결과 화면에서만 표시되는 요소도 동작을 시작시킨 명령을 받으며, 표시를 준비하는 과정에서 기존 요소에 같은 명령을 중복 전달하지 않는다. 지원하는 플러그인은 반복 보조 트랙을 포함해 재생 위치를 보존한다. 웹은 새 화면의 요소가 마운트된 후 복원하므로, 이전 컨트롤러에 복원 요청이 전달되어 저장이 무시되지 않는다. 별도 UI 없이 호스트를 사용하는 기존 호출자는 기존 tick 복원 방식을 유지한다.

## 검증 기록

- Qt `presentationVariantsAuthoring`: 실제 폼에서 활동별 문구 연결, 취소 보존, 저장, 참조 오류 0개 확인.
- `tests/runtime/presentation-variants.test.mjs`: 우선순위, 기본값 복귀, 활동 필터 범위, C++ 조건과 참조 구현 일치, 상태·난수 불변, 저장 재생, 잘못된 참조와 게임 행동 주입 거부.
- `tests/runtime/free-screen-export.test.mjs`: 부품 내부 표현을 포함한 구형 렌더러 차단.
- `tests/native-player/free-screens.test.mjs`: Qt 제작본으로 두 선택 분기를 엔딩까지 플레이하면서 모든 단계의 조건별 문구를 비교. 대화 도중 및 엔딩 이후 저장 복원.
- `tests/visual/presentation-variants-web.test.mjs`: 실제 Chrome/WASM에서 활동별 문구 전환, 파일 다운로드·업로드 복원, 해상도 변경 후 상태 보존.
- `tests/plugins/presentation-variants.test.mjs`: 테스트 전용 프로그램 작성 프로젝트로 실제 네이티브/웹 플러그인 컨트롤러 전환, 기본 동작 복귀, 모든 애니메이션 트랙의 저장 복원. 이 플러그인 시험 프로젝트를 GUI로 제작했다고 주장하지 않는다.

로컬 제작본은 `.cache/designer-freedom/authored-final`, 로그는 `.cache/designer-freedom`, 브라우저 스크린샷은 `output/playwright/presentation-variants`에 있다. 다음 단계인 사용자 정의 상태 그룹·값과 통합 작업실은 아직 완료되지 않았다.

최종 확인: 새 계약·내보내기 및 기존 웹 컨트롤러 9개, 기존 플러그인 프로젝트·내보내기 16개, 실제 네이티브/웹 애니메이션 전환 2개 통과. 별도로 Qt 제작 시험, 두 분기의 네이티브 플레이, 실제 웹 파일 저장·불러오기를 통과했다. 빌드·플레이어 타입 검사·공개 콘텐츠 경계 검사도 통과했다. 서로 겹치는 테스트 실행 횟수는 합산하지 않았다.


## 부품별 활동 연결

`uiContext.activityId`를 명시한 요소는 연결한 활동의 표현을 모든 단계에서 사용한다. 수행 캐릭터만 연결한 경우에는 결과 단계에서 그 인물의 활동 결과를 따른다. 연결이 없는 요소의 기존 대표 활동 동작은 유지한다. 자세한 제작 방법과 우선순위는 [부품 대상 연결](component-context.md)을 참고한다.
