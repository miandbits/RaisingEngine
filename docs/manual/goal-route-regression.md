# 목표 플레이 경로 기록과 회귀 검사

목표를 지정해 자동으로 경로를 찾거나 실패한 경로의 대안을 등록하려면 [목표 경로 탐색](goal-route-search.md)을 참고한다. 기존 엔딩 경로와 새 사건 목표 경로를 함께 검사한다.

## 사용 흐름

`start-commercial-pilot.cmd`로 최신 편집기를 연다. **디자인 → 목표 경로 기록 · 회귀 검사…**에서 다음 순서로 사용한다.

1. **새 플레이 기록**을 누르고 평소처럼 실제 플레이한다. 내부 명령과 seed, 시작 입력을 기록한다. 월말 자동 대본 진행도 포함한다.
2. 원하는 중간 지점에서 게임을 저장한다. 저장 위치는 검사 지점으로 기록된다. 불러오기로 되돌린 경우 최종적으로 선택한 분기만 남으며 새 게임은 이전 기록을 초기화한다.
3. 플레이어를 닫으면 경로 창으로 돌아온다. **최근 기록 읽기**를 누른다. 다른 실행의 `recording.json`은 파일 선택으로 읽을 수 있다.
4. 이름·ID·목표 엔딩·저장 검사 간격을 설정하고 **목표 경로 저장**을 누른다. 엔딩에 도달하기 전의 기록도 목표 엔딩을 지정해 등록할 수 있지만, 해당 기록만으로 목표에 도달하지 않으면 검사 실패다.
5. **선택 경로 검사 / 전체 검사**로 현재 초안을 재생한다. 등록된 경로는 **프로젝트 저장 때마다 자동 검사**한다. 콘텐츠 저장 성공과 회귀 실패는 별도로 표시하며, 회귀 실패가 저장한 콘텐츠를 되돌리지는 않는다.

표에는 명령 수, 통과 여부, 중간 저장 복원 횟수, 실패 명령 번호·코드·원인이 나온다. 상세 기록에는 실패 명령 본문과 기대/실제 엔딩, 검사 콘텐츠 지문과 초안 버전이 있다. 검사 후 초안이 바뀌면 재검사가 필요하다는 안내가 표시된다.

## 기록과 검사 계약

- 영구 경로: 프로젝트의 `playtests/routes/<id>.json`. 프로젝트와 함께 버전 관리한다. 파일명과 ID가 일치해야 한다.
- 임시 플레이 기록: 편집기 실행별 `.cache/qt-preview/run-*/recording.json`. 편집기를 끝내기 전에 목표 경로로 등록하거나 파일 경로를 보관한다.
- 검사 보고서: 프로젝트의 `.studio/goal-report-*.json`. 오래된 콘텐츠 지문은 비교 정보이며 새 콘텐츠의 검사를 막지 않는다.
- 검사는 과거 상태를 주입하지 않고 **현재 스냅샷**에서 원래 seed·시작 입력·명령을 다시 실행한다.
- 실제 저장 지점, 지정한 명령 간격, 시작과 끝에서 공통 저장 형식으로 직렬화·복원한다. 저장 없이 진행한 세션과 복원 세션을 다음 명령마다 비교하므로 명령 이력·난수·최종 상태의 차이를 검출한다.
- 목표 엔딩 삭제, 명령 대상 삭제, 조건·비용 변경으로 인한 거부, 다른 엔딩 도달, 저장/재생 불일치를 구분한다.
- 경로 저장은 파일 해시 기반 버전 확인과 전용 쓰기 잠금으로 다른 편집기 창의 변경을 조용히 덮어쓰지 않는다. 프로젝트 초안/디스크 버전 검사도 기존 서비스를 사용한다.
- 기존 콘텐츠와 저장 스키마를 변경하지 않았다. 프로젝트당 128경로, 경로당 10,000명령/4 MiB, 전체 검사 60초 제한이며 제한 도달은 통과로 표시하지 않는다.

자동화 환경에서는 같은 검사기를 실행할 수 있다.

```powershell
node scripts/check-goal-routes.mjs examples/starlight-three-months
# 한 경로만
node scripts/check-goal-routes.mjs examples/starlight-three-months success
```

종료 코드는 0=통과, 1=회귀 실패/미완료, 2=실행 설정·로드 오류다. 실행 전에 TypeScript 산출물과 런타임을 빌드해야 한다.

## 탐험 입구 문제

파일럿의 시련의 공터는 `skill >= 16`, 숨겨진 길은 `reputation >= 99` 조건을 사용한다. 시작 시 두 값이 0이라 이동 버튼이 비활성화됐지만 이전 화면에는 원인이 표시되지 않았다.

탐험 이동과 귀환 버튼을 실제 코어의 실행 가능 판정에 연결하고, 잠긴 지점에는 요구 조건과 현재 값을 표시하도록 보완했다. 이 조건은 샘플의 규칙이며 임의로 제거하지 않았다. 실제 창 좌표 클릭으로 잠긴 이동의 상태 불변과 귀환을 확인하고, 훈련 후 공터 이동·전투 승리 경로도 검사한다.

## 검증과 범위

실제 플레이 증거 및 자동 시험 결과는 `docs/evidence/goal-routes/`에 저장한다. Qt 등록 시험은 실제 폼·버튼을 사용하며 경로 JSON을 직접 작성하지 않는다. 세 엔딩의 기록 파일은 Windows 플레이어의 실제 입력에서 얻는다.

이번 파일럿에는 다음 세 경로를 실제 편집기에서 등록했다. GUI 등록 후 닫고 재열어 유지되는 것을 확인했으며 CLI에서도 같은 결과를 얻었다.

| 경로 | 목표 | 명령 | 저장/복원 검사 |
|---|---|---:|---:|
| `success` | 별빛 길드의 동료 | 82 | 18 |
| `relationship` | 마을에 남은 약속 | 62 | 9 |
| `ordinary` | 다시 시작하는 계절 | 52 | 7 |

총 **196명령·34개 저장 지점**을 통과했다. Qt에서 화면 문구 수정 → 저장 → 세 경로 자동 통과를 확인했고, 경로의 목표 엔딩을 일부러 잘못 지정해 82번째 명령에서 실패가 표시되는 것도 확인한 뒤 원래 목표로 복원했다. 별도 임시 프로젝트에서는 엔딩 조건을 높인 콘텐츠 변경으로 목표 경로만 실패하고 나머지 두 경로는 통과했다. 삭제된 행동은 정확한 명령 위치에서 실패하며, 경로 파일의 동시 수정 충돌은 기존 변경을 보존했다.

- `editor-goal-routes.png`, `editor-goal-failure.png`, `editor-registration.json`: 실제 Qt 등록·성공/실패 표시·저장 자동 검사·재열기.
- `service-regression.json`: 최신 콘텐츠 재생, 밸런스 변경, 실패 위치, 동시 수정 충돌, 취소 검사.
- `play-recording.json`, `relationship-recording.json`, `ordinary-recording.json`: 실제 플레이어의 세 엔딩 기록. 불러오기 후 버린 분기의 명령이 남지 않는 것도 대조했다.
- `entry-conditions.png`, `entry-gate-verification.json`: 실제 창 입력의 잠긴 이동·조건 표시·귀환·복원. 훈련 이후 이동과 승리는 목표 엔딩 실제 플레이 기록에서 확인했다.

서비스/회귀 시험 6개, 실제 플레이 시험 4개, 탐험 입력 시험 1개와 Qt 통합 시험을 통과했다. Qt 통합은 전투·사건·연출 저장 복원을 포함하는 성공 경로를 플레이 버튼으로 다시 실행한다.

검사기는 기록된 seed와 명령 경로를 확인한다. 한 경로의 실패는 게임 전체의 도달 불가능 증명이 아니다. 화면 배치·버튼 가림·애니메이션 시간·오디오·플러그인의 표시 상태는 이 명령 회귀 검사만으로 증명하지 않으며 실제 UI 시험을 병행한다. 이번 통합은 Windows Qt/네이티브 플레이어 기준이다. 구형 런타임은 기록 기능 지원 검사를 통해 시작 전에 안내한다.


경로의 시각적 비교와 단계 재생은 [목표 경로 그래프와 단계 비교](goal-route-comparison.md)를 참고하세요.
