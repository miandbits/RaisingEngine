# 7단계: 연출 작업실과 플러그인 호환성

## 계약과 제작

`project.visual.direction`은 선택 항목이다. 기존 프로젝트에는 추가하지 않아도 된다. 배우는 기본 이미지와 이름을 갖고, 표정·의상은 투명 PNG 레이어, 동작은 이미지 프레임 목록과 프레임 시간으로 정의한다. 외부 에셋을 등록한 뒤 디자인 → **연출 작업실…**에서 작성한다.

작업실의 네 탭은 배우, 표정·의상·동작, 연출 연결, 구간·동시 동작이다. 같은 연출 ID·구간 번호의 행들은 동시에 재생한다. 구간은 번호 순서대로 진행한다. 같은 구간의 이름·기간은 같아야 하고 같은 배우를 중복 지정할 수 없다. 좌표와 크기는 프로젝트 화면 좌표이며 종료 X/Y를 지정하면 선형 이동한다. 불투명도는 0~1이다.

변형 종류는 `expression`, `outfit`, `motion`이다. 동작 이미지 ID들은 쉼표로 나열한다. 프레임은 해당 구간의 시작 시각부터 반복한다. 합성 순서는 기본 이미지 또는 동작 프레임 → 의상 → 표정이다. 세 레이어의 캔버스 크기와 기준점을 맞춰 제작한다. 구간에 없는 배우는 직전 모습과 위치를 유지하고, 행에 있는 배우의 빈 변형 ID는 기본 모습으로 돌아간다.

연출 연결 탭에 화면 ID를 입력하면 일반 버튼이 배치된다. 화면 캔버스에서 위치·크기·문구를 바꿀 수 있고, UI 구성 도구의 `playSequence` 행동과 연출 ID로 기존 버튼도 연결할 수 있다. 작업실 저장은 프로젝트 초안을 갱신하며 실행 취소·다시 실행과 일반 프로젝트 저장을 사용한다. 참조·중복·수치 오류는 공통 JSON Schema와 의미 검증 서비스가 검사한다.

## 재생과 저장

연출 버튼은 게임 시작 후 사용한다. 연출 중에는 게임 명령을 막고 일시정지/계속, 1배속/4배속, 중단, 끝으로 이동, 저장, 불러오기, 닫기를 제공한다. 중단은 해당 위치에서 재생을 끝내고, 다시 시작하려면 닫은 뒤 연출 버튼을 누른다. 닫기·중단·배속은 비용·능력치·난수·게임 상태 버전을 변경하지 않는다.

게임 저장의 선택 항목 `playerPresentation.direction`에 연출 ID, 경과 시간, 속도, 일시정지, 완료/중단 상태를 보관한다. 기존 저장에는 이 항목이 없어도 된다. 불러오기 전에 콘텐츠 지문과 커서를 검사하며 잘못된 재생 위치는 현재 세션을 덮어쓰지 않고 거부한다. TypeScript와 네이티브 C++는 같은 프레임·레이어 계산을 사용한다.

## 플러그인과 경계

기존 애니메이션 플러그인 호스트의 버전/API·필요 기능·대상 플랫폼·런타임 모듈 검사와 불투명 연출 상태 저장 계약을 유지한다. 플러그인의 관측/렌더링과 시뮬레이션 명령은 분리된다. 이 작업실은 엔진 내장 이미지 프레임 연출 도구이며, 임의 플러그인의 클립·스킨 이름을 자동 해석하는 범용 스켈레탈 타임라인은 아니다. 기존 cutout 플러그인의 행동→클립 연결은 플러그인의 제작 도구에서 설정한다.

신규 연출은 `direction-sequences-v1` 기능을 요구한다. 지원하지 않는 구형·웹 런타임으로 내보내면 차단한다. Windows 네이티브에서 검증하며 모바일·콘솔·웹의 신규 연출 지원 완료를 의미하지 않는다. 현 버전은 배우 32명, 연출 100개, 연출당 구간 100개, 구간당 최대 60초다. 오디오 트랙·카메라·스켈레탈 클립 교차 혼합·연출 완료 후 규칙 자동 실행은 후속 범위다.

## 샘플과 증거

`start-direction-lab.cmd`로 `tests/fixtures/projects/direction-lab`을 연다. 기반은 6단계 `party-tactics-lab` 복사본이다. 테스트용 원본 PNG를 코드로 준비하고, Qt 이미지 가져오기 창으로 등록한 뒤 실제 작업실 위젯에서 두 배우·프레임 동작·웃는 표정·의상과 2개 구간을 작성한다. 에셋 그림 자체를 GUI로 그렸다고 주장하지 않는다.

집의 **두 사람의 출발 인사** 버튼으로 동시 등장 → 출발 준비를 재생한다. 움직이는 중 일시정지하고 저장한 뒤, 계속/4배속으로 다음 구간에 진입했다가 불러오기를 눌러 비교한다. 기존 탐험·전투도 같은 샘플에 유지한다.

검증 기록과 스크린샷은 `docs/evidence/direction/`에 있다. `verification.json`, `play-report.json`, `fresh-report.json`, `invalid-report.json`, `editor-play-report.json`을 참조한다.

검증 완료(2026-10-14):

- 실제 Qt 이미지 가져오기·연출 제작·실행 취소/다시 실행·저장/다시 열기, 편집기 플레이 실행: 2개 테스트 통과.
- 연출 단위 및 기존 플러그인 내보내기 검사 7건, 연출 의미 검증 2건 통과.
- 새 플레이어에서 기존 UI 계층·데이터 UI·다인 전투의 실제 플레이 3건 통과.
- 기존 cutout 애니메이션 플러그인의 실제 렌더링·행동 클립·저장 복원·프레임 간격에 따른 게임 상태 불변·모듈 누락 대체 표시 3건 통과.
- 기존 저장·활동 타임라인 회귀 20건 통과.
- 새 연출의 실제 입력·동시 이동·순차 표정/의상·중단·배속·중간 저장/불러오기·새 프로세스 복원·변조 거부·TS/C++ 프레임 일치·게임 상태 불변 검사 1건 통과.
- 합계 JavaScript 테스트 36건 및 Qt 기능 테스트 2건 통과. 구형 런타임 내보내기가 `direction-sequences-v1` 부족으로 거부되는 것도 확인했다.

제작 자동화 과정에서 기본 Windows 파일 창의 조작 대기를 발견해 테스트 모드에 Qt 파일 선택 창을 명시하고 입력 대기를 보완했다. 실제 플레이에서 발견한 C++ 저장 커서 필드 수 검사 오류도 수정한 뒤 저장·복원·변조 테스트를 통과했다.
