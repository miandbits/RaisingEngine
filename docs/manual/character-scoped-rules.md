# 2단계: 캐릭터 소유 상태와 대상 지정 규칙

1단계의 `roster`는 그대로 유지한다. 새 기능은 `roster.stateModel: "character-v1"`을 선언한 프로젝트에서만 활성화한다. 이 필드가 없는 프로젝트·저장은 기존 상태 형태와 재생 결과를 유지한다.

- 각 member에 `initialInventory`, `initialRelationships`, `actionIds`를 선택적으로 설정한다. 인물 문서의 관계 정의는 관계 상대 및 수치 범위의 정의이며 소유자는 각 육성 캐릭터다. 기존 전역 관계·소지품은 공유 상태로 남는다.
- 공통 numericTarget에 선택적 `owner`를 추가한다. 생략하면 기존 해석, `{kind:"actor"}`이면 현재 행동/대본의 실행자, `{kind:"character",characterId:...}`이면 고정 캐릭터다. 조건 수식과 효과가 같은 대상 해석기를 사용한다. 캐릭터 능력은 roster의 개별 능력 목록에 있는 항목만 허용한다.
- `executeActorAction` 명령은 actorId/actionId/quantity로 기존 범용 행동을 실행한다. member.actionIds에 연결된 행동만 실행할 수 있다. 전체 비용·효과·확률·사건 진입은 한 트랜잭션이며 오류 시 모두 취소한다. 대상은 내부 실행 문맥으로만 전달하고 전역 능력이나 다른 캐릭터 상태를 임시 덮어쓰지 않는다.
- `scope:"actor"`인 interaction 사건은 캐릭터별 완료 기록을 사용한다. 대본 커서에 실행자를 보관해 선택·조건·효과와 중간 저장 복원에 같은 문맥을 사용한다. 기간 자동 사건은 기존 계약을 유지한다. 다인 자동 사건 큐는 후속 범위다.
- 기존 활동 배정도 실행자 문맥을 제공하므로 같은 활동에서 owner actor 조건·효과를 재사용할 수 있다.
- 초기값 범위·소유자·물품·관계·행동 참조, 사건 범위, 미지원 런타임을 검증한다. 캐릭터별 장비·경제·정책·관계 단계 트리거 전체를 구현했다고 주장하지 않는다.

제작 수용 흐름: Qt에서 두 대상의 소지품/관계 초기값 및 행동 연결 → 공통 조건·효과 편집기로 실행자/고정 대상 설정 → 서로 다른 사건 연결 → 실제 플레이에서 개인 상태 차이 확인 → 대본 중 저장 → 완료 → 불러오기 → 같은 결과 재생. 기존 단일 대상과 1단계 저장 회귀를 함께 검사한다.

## 구현 및 검증 결과 (2026-10-14)

Qt의 **디자인 → 캐릭터 소유 상태**에서 물품 정의·개별 소지품·관계 초기값·대상별 행동을 편집한다. 관계 탭의 **관계 종류 정의**로 상대 인물에 새로운 관계 수치를 추가할 수 있다. 조건/효과 트리의 소유자에서 공용·행동 실행자·지정 캐릭터를 고른다. 사건 편집기의 범위에서 캐릭터별 사건을 고른다. 같은 프로젝트 서비스의 버전 검사·일괄 변경·되돌리기를 사용한다.

최종 샘플은 `tests/fixtures/projects/character-state-demo`, 실행은 `start-character-state.cmd`이다. Qt 위젯 자동화로 새 프로젝트, 두 캐릭터, 꽃/책, 존경 관계 정의, 각 행동·조건·효과·사건과 행동 위젯을 제작했다. 프로젝트 JSON을 외부 생성한 뒤 GUI 제작으로 간주한 사례가 아니다. 회귀용 코어 테스트의 JSON fixture는 별도로 구분한다.

## 현재 경계

개인 소지품 비용은 소유자 지정 감소 효과로 구성하며 실패하면 전체 행동을 취소한다. 기존 비용 필드의 공용 자원 의미는 변경하지 않았다. 개인 장비·플래그·정책, 자동 기간 사건의 다인 큐, 개인 관계 단계 트리거, 다인 탐험/전투는 후속 범위다. 이번 `character-scoped-rules-v1` 기능을 광고하고 실제 검증한 배포 런타임은 Windows 네이티브 플레이어다. 웹·모바일·콘솔 지원 완료를 의미하지 않는다.

샘플의 12개월 기반 콘텐츠는 남아 있지만, 기반 템플릿의 단일 대상 고정 시나리오를 다인 시나리오로 이식한 것은 아니다. 이번 완료 기준은 서로 다른 활동 배정과 개인 행동·사건·저장 흐름이다.
