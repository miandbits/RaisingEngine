# 인물부터 후속 사건까지 연결하기

상단 **연결 작업실**을 연다. 기존 프로젝트 형식을 그대로 사용하며 적용, 되돌리기, 저장, 검증, 플레이를 같은 작업실에서 실행한다.

## 기본 순서

1. **인물**을 추가한다. 복수 육성 대상 프로젝트에서는 인물을 육성 대상으로 함께 등록하고 기본 활동을 고른다. 기존 인물에서도 육성 대상과 배정 활동으로 이동할 수 있다.
2. **활동**에서 조건·비용·효과를 편집한다. 규칙 편집은 가운데에 열리며, 확인하거나 취소하면 선택한 항목으로 돌아온다.
3. 활동에서 **만남 만들기**를 선택한다. 말하는 인물, 대사, 두 선택을 작성하고 캐릭터별 기록 여부를 정한다. 생성 후 발생 활동·장소·날짜·조건을 조정한다.
4. 사건의 **대사·선택 목록**을 두 번 누른다. 선택의 조건·효과와 다음 대사를 편집한다.
5. **이 사건·선택에서 후속 사건 연결**로 다음 만남을 만든다. 선행 사건 완료와 선택 기록 조건은 자동으로 연결한다. 캐릭터별 사건에서 시작하면 그 인물의 기록을 사용한다.
6. 변경 적용 → 프로젝트 저장 → 검증 → 플레이로 확인한다. 선택을 바꾸어 플레이하고 중간 저장·불러오기도 확인한다.

검증의 오류·경고 건수와 실행 실패 사유는 작업실 상단에 표시한다. 플레이는 실제 플레이어 프로세스가 시작된 뒤 실행 완료를 표시한다. 상세 오류 위치는 기존 검증 목록에서 이동할 수 있다.

선택 바로 뒤에 연결한 효과·장면 노드는 다음 대사 전에 자동 진행된다. 선택 안내는 이 구간의 연속 효과도 보여주며, 선택 결과는 상한 적용 등을 거친 실제 변화량을 표시한다. 결과 안내는 저장을 불러올 때도 명령 기록으로 복원한다.

## 대상과 저장을 확인하기

- **공용**은 모든 인물이 함께 쓰는 상태다. **행동 실행자**는 지금 활동하거나 사건을 경험하는 인물이다. 특정 인물에게만 영향을 주려면 **지정 캐릭터**를 고른다.
- 기존 공용 사건은 **캐릭터별 전환 미리보기…**로 조건·효과·선택 기록과 연결된 후속 사건을 함께 바꾼다. 기록 범위를 캐릭터별로 바꾸고 적용하거나, 대본 편집기에서 범위를 바꾸어도 같은 미리보기를 거친다. 새 후속 연결은 시작 사건의 범위를 따른다.
- 규칙 편집의 확인은 작업실 입력에 반영한다. **변경 적용**은 프로젝트 초안을 변경하며, **프로젝트 저장**이 디스크에 저장한다.
- 미적용 입력이 있는 상태에서 종료·프로젝트 전환을 하면 돌아가기 또는 입력 버리기를 선택한다. 버린 입력은 폼에서도 원래 값으로 복원된다. 이미 적용한 미저장 변경은 기존 저장 확인에서 별도로 처리한다.
- 다른 도구가 초안 버전을 변경하면 오래된 입력의 적용을 거절한다. 입력을 확인한 뒤 새로 고침으로 최신 내용을 읽는다.

## 기존 공용 사건을 캐릭터별로 전환하기

1. 연결 작업실에서 공용 사건을 선택하고 **캐릭터별 전환 미리보기…**를 누른다. 캐릭터별 상태를 사용하는 프로젝트에서 이용할 수 있다.
2. 위쪽 목록에서 각 데이터가 개인 기록인지 공용 기록인지 검토한다. 개인 능력·관계·소지품·사용자 상태는 행동 실행자에게 연결하며, 선택·약속 플래그는 기록하는 효과와 읽는 조건을 함께 바꾼다. 공동 자금처럼 프로젝트가 공용으로 정의한 능력치는 공용을 유지한다.
3. 아래 목록에서 사건별 **변경 전 → 변경 후**를 확인한다. 선행 사건의 완료 기록이나 선택·약속 플래그를 읽는 후속 사건을 연쇄적으로 포함한다. 외부에서 만든 활동 경험과 선행 사건 기록은 기본적으로 공용을 유지한다. 이미 특정 인물로 지정한 대상은 보존한다.
4. 필요한 데이터는 개인별 체크를 해제해 공용으로 유지할 수 있다. 다른 행동도 같은 기록을 쓰거나 지정 인물이 섞인 경우 경고를 읽고 확인한다. 플러그인 내부 규칙은 임의로 다시 쓰지 않는다. 실행자를 결정할 수 없는 발생 시점 등은 전환을 막고 수정할 항목을 표시한다.
5. **검토한 전환 적용**으로 관련 사건을 한 번에 변경한 뒤 프로젝트를 저장한다. 취소하면 아무것도 바뀌지 않는다. 작업실의 되돌리기·다시 실행은 전체 전환을 하나의 편집으로 처리한다. 대본 편집기에서는 기존 저장 버튼으로 검토한 초안을 적용한다.

미리보기를 연 뒤 다른 편집이나 프로젝트 재열기로 초안 내용이 달라지면 적용을 거절한다. 최신 내용을 다시 열어 검토한다. 이 도구는 콘텐츠 규칙을 바꾸며, 기존 저장의 공용 선택 기록을 특정 인물이 경험했다고 추측해 복제하지 않는다. 전환 후 각 인물로 선택·후속 사건을 플레이하고 저장·불러오기를 확인한다.

자동 검증: `qt-story-scope-test`는 중첩 조건·효과, 연쇄 연결, 공용 유지, 지정 인물 보존, 취소와 차단을 검사한다. Qt `storyScopeConversion`은 미리보기·취소·초안 충돌·일괄 적용·되돌리기·다시 실행·저장 재열기를 검사한다.

## 전환한 프로젝트를 웹에서 확인하기

프로젝트를 저장한 뒤 웹으로 내보낸다. 캐릭터별 조건·효과·선택·약속·후속 사건은 Windows와 동일한 콘텐츠와 C++ 코어를 사용한다. 웹용으로 사건을 다시 만들 필요는 없다. 내보낸 폴더는 HTTP 서버로 제공하고, 브라우저에서 시작·일정 배정·선택·후속 사건을 확인한다.

두 인물의 수락·거절을 서로 바꾸어 플레이한다. 선택 효과와 약속은 해당 인물에게만 남고, 거절한 인물에게는 수락 후속 사건이 발생하지 않아야 한다. 공동 자금은 계속 공용이다. 선택 전·선택 후·후속 사건 도중·결말에서 저장하고, 새 탭에서도 불러와 확인한다. 전환 전 공용 기록을 개인 기록으로 추정해서 옮기지 않는 규칙은 웹에서도 같다.

개발자 회귀 검사: 네이티브 코어와 TypeScript 패키지를 빌드한 뒤 `npm run build:web`, `node --test tests/journey/personal-story-web.test.mjs`를 실행한다. 별도 웹 런타임을 검사하려면 `WEB_TEST_RUNTIME`으로 출력 폴더를 지정한다. 기본 브라우저는 설치된 Microsoft Edge이며 `PLAYWRIGHT_CHANNEL`로 다른 설치 채널을 선택할 수 있다. 이 검사는 실제 브라우저 버튼·선택·파일 저장/불러오기를 사용해 두 인물의 분리와 네이티브 재생 상태 일치를 확인한다. 짧은 표시 영역의 불필요한 스크롤, 긴 설명의 스크롤 유지도 함께 검사한다.

## 범위

기본 인물·활동·사건·선택·규칙·후속 연결을 한 작업실에서 편집한다. 복잡한 대본 배치, 화면 캔버스, 일부 고급 행동 흐름에는 기존 전용 도구도 사용한다. 캐릭터별 상태를 사용하지 않는 기존 프로젝트에 복수 육성 대상을 자동 도입하지 않는다.

검증은 `authoring-workspace.test.mjs`의 참조·초안 서비스 시험과 Qt의 `unifiedConnectionAuthoring`, `authoringWorkspaceRoundtrip`, `logicAstEditor`에서 실행한다. Qt 시험은 실제 위젯을 조작하며 생성·취소·후속 조건·저장 재열기·미적용 입력 보호를 확인한다. Owner 드롭다운은 클릭 처리 중 위젯을 삭제하지 않는 수명 회귀 검사를 포함한다.
