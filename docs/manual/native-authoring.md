# C++ 런타임과 육성게임 제작

Raising Studio에서 장소와 행동, 자유 화면, 아이템·상점·선물·관계 사건을 편집하고 같은 초안을 바로 플레이할 수 있습니다. `examples/academy-journey`는 12개월 샘플을 기반으로 실제 편집기 조작으로 제작한 예제입니다. 게임의 실행 규칙은 C++로 처리하며, 인간 편집기와 MCP는 같은 JSON 데이터·초안 버전·검증 서비스를 사용합니다.

## 실행 구조

| 구성 | 역할 |
| --- | --- |
| Electron·React·TypeScript Studio | 콘텐츠 탐색, 육성 작업실, 화면 배치, 진단, 자동 플레이, 미리보기와 내보내기 |
| 공유 JSON Schema와 검증 서비스 | 구조·참조·범위·사건 기간·대본 연결·시각 요소 참조 검사 |
| C++ 코어 | 시간·일정·비용·효과·성공 판정·사건·대본·엔딩·게임 행동·상태 버전 |
| Node-API 연결 | Studio·CLI·MCP의 기본 실행 경로. 조건 불일치 시 동일 C++ 프로세스로 연결 |
| SDL3·RmlUi 플레이어 | Windows에서 Electron·Node 없이 실행하는 그래픽 게임 |
| WebAssembly 코어와 React 화면 | 웹 브라우저에서 같은 게임 규칙과 저장 기록 실행 |

TypeScript 코어는 비교 검증용으로 유지합니다. C++ 연결 실패를 TypeScript 실행으로 숨기지 않습니다. 콘텐츠 계약은 기존 프로젝트를 계속 허용하며, 새 `project.gameplay`와 자유 화면 정보를 선택적으로 추가합니다. 기존 저장 파일과 새 행동을 포함하는 저장 파일 모두 명령 기록을 재실행하고 상태를 비교해 불러옵니다.

## 편집기에서 제작하는 순서

1. **도시·선물 샘플 새 프로젝트**에서 새 폴더를 선택합니다. 기존 프로젝트는 **열기**로 선택합니다.
2. **육성 작업실**에서 시작 장소를 정하고 집·도시·상점을 만듭니다. 장소 사이의 이동 연결과 각 장소의 화면·배경을 지정합니다.
3. 아이템에 이름·설명·최대 소지 수량·이미지를 지정합니다. 이미지는 편집기의 에셋 가져오기로 프로젝트 안에 복사합니다.
4. 상점을 장소에 연결하고 화폐로 사용할 능력·자원을 선택합니다. 판매 아이템·가격·재고를 설정합니다.
5. 교류 행동에 장소·인물·필요 아이템·비용·조건·효과를 지정합니다. 선물 행동은 아이템을 소비하고 관계 수치를 변경할 수 있습니다.
6. 관계 사건 만들기에서 사건과 행동 연결을 함께 추가합니다. 이 작업은 한 번의 실행 취소로 함께 되돌립니다. 대사·선택·후속 조건은 사건과 대본 편집에서 다듬습니다.
7. 화면 편집기에서 집·도시·상점·교류 템플릿 또는 빈 화면을 추가합니다. 버튼의 행동을 화면 이동·장소 방문·구매·교류로 연결합니다. 장소 이동과 단순 화면 전환은 구분됩니다.
8. 텍스트 요소의 **UI 데이터 연결**에서 능력·자원 수치, 인물 관계 수치, 아이템 수량을 선택합니다. 표시 형식은 `{label}`과 `{value}`를 지원합니다. 예: `소지금 {value} G`.
9. **검증**에서 오류 위치를 확인하고 **초안 미리보기**를 실행합니다. 편집기로 돌아와 변경한 후 미리보기를 다시 시작하면 새 초안이 적용됩니다.
10. 초안을 저장하고 **게임 내보내기**에서 Windows 또는 웹을 선택합니다. 새 출력 폴더를 사용하며 기존 폴더는 덮어쓰지 않습니다.

미리보기에서 돌아오거나 콘텐츠 탐색과 화면 편집 사이를 이동하면 선택한 화면·요소, 배치/연출 탭, 연출 대상, 스냅 설정과 추가할 요소 종류가 유지됩니다. 다른 프로젝트를 열면 해당 프로젝트의 기본 선택으로 초기화합니다. 이 작업 위치는 실행 중 편의를 위한 상태이며 프로젝트 콘텐츠에 저장하지 않습니다.

## 샘플 플레이 확인

새 게임의 소지금은 60입니다. 집에서 일정을 확인한 뒤 도시 광장과 작은 상점을 방문할 수 있습니다. 감사의 꽃 하나를 40에 구매하면 소지금은 20, 꽃은 1개가 됩니다. 도시에서 유나에게 선물하면 꽃을 하나 소비하고 신뢰가 15 증가하며 관계 사건이 시작됩니다. 대본을 마친 뒤 집으로 돌아오면 자유 배치한 수치 UI에도 결과가 표시됩니다.

저장은 현재 상태와 실행한 명령 기록을 함께 보관합니다. 구매 전·후 또는 선물 전·후에 저장한 다음 다른 행동을 하고 불러오면 해당 시점으로 돌아갑니다. 웹은 파일 다운로드·업로드 방식, Windows는 파일 선택 방식입니다. 같은 콘텐츠의 저장 파일은 검증 후 서로 교환할 수 있습니다.

이동·구매·교류만으로 기간이 진행되지는 않습니다. 일정 실행이 시간을 진행시키며, 기간별 사건과 행동으로 시작하는 사건은 각각의 발동 경로를 따릅니다. 한 기간에 한 번만 허용된 교류와 조건 미충족 행동은 실행할 수 없습니다.

## 내보내기와 플랫폼 범위

Windows 출력 폴더의 `RaisingPlayer.exe`를 실행합니다. 게임 데이터·이미지·폰트·라이선스가 함께 필요하므로 폴더 전체를 배포합니다. 웹 출력은 정적 HTTP 서버에 올립니다. `file://`로 HTML만 여는 방식은 지원하지 않습니다.

내보내기는 프로젝트 검증과 에셋 경로·내용 해시·런타임 지원 형식을 검사한 다음 임시 폴더를 완성하고 최종 폴더로 바꿉니다. 실패하면 기존 프로젝트나 출력 폴더를 수정하지 않습니다. Windows 런타임은 PNG·JPEG·WebP, WAV·MP3·OGG·FLAC을 지원합니다. 플랫폼별 허용 형식은 번들 `capabilities.json`으로 검사합니다.

실행 검증을 마친 배포 대상은 Windows x64와 웹입니다. macOS·Linux·Android·iOS·콘솔용 패키징과 기기별 입력·저장·인증은 후속 작업입니다. C++ 전환 자체가 콘솔 지원 완료를 의미하지 않습니다. 이 버전은 요청한 도시·상점·선물 제작 경로를 제공하며, 상용 육성게임의 모든 전투·탐험·장비·연출 시스템이 완성된 상태는 아닙니다.

## 검증을 읽는 방법

[독립 QA 기록](native-journey-qa.md)은 GUI 제작·저장·내보내기·실제 플레이와 대량 콘텐츠 탐색의 근거를 제공합니다. [컴파일러 검사](../../native/PORTABILITY-AUDIT.md)는 MSVC·Clang과 ASan·UBSan 결과를 구분합니다.

자동 무작위 플레이는 실행 중 오류와 실제로 관찰한 사건·엔딩을 찾습니다. 목표 탐색이 찾은 명령 기록은 도달 사례입니다. 제한된 횟수나 탐색 예산에서 찾지 못한 결과를 도달 불가능하다는 증명으로 취급하지 않습니다.

이 Windows 호스트의 최종 분석 워커는 샘플 1,000회를 82.9초에 모두 정상 종료했습니다. 동일한 3회 작업 비교에서는 2.815초에서 0.307초로 줄었습니다. 별도로 같은 콘텐츠·seed 42000·명령 제한으로 실행한 1,000회 결과도 개선 전후 전체가 일치했습니다. 워커로 전달하며 복제된 콘텐츠를 한 번 읽기 전용으로 고정해, 매 행동마다 전체 데이터를 다시 보내던 비용을 제거했습니다. 프로젝트 크기와 컴퓨터에 따라 소요 시간은 달라집니다. 1,000회 기록 (historical internal evidence; not distributed), 속도 비교 (historical internal evidence; not distributed), 1,000회 결과 비교 (historical internal evidence; not distributed)에 근거를 보관합니다.
