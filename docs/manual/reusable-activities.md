# 5단계: 같은 화면·부품으로 만드는 세 활동

디자이너 자유도 계획의 마지막 제작 시험이다. 수련·잠입·연회를 **기존 활동 계약과 조건별 표현**으로 만들었다. 화면을 복제하거나 게임 이름을 판별하는 실행 코드를 추가하지 않았다.

## 제작 도구 보완

- 재사용 UI 부품 작업실에 **선택 요소의 조건별 표현…**을 추가했다. 화면 요소와 부품 자식이 같은 표현 편집기를 사용한다. 부품 원본의 규칙을 바꾸면 배치본 전체에 반영된다.
- 활동 선택 목록은 실제 활동 계약의 `label`을 표시한다. 없는 단일 활동 참조와 외부에서 작성한 여러 활동 필터는 임의로 지우지 않고 유지한다.
- 부품 이름을 바꾸면 작업실 목록에도 즉시 반영한다.
- 부품 작업실을 연 뒤 프로젝트 버전·루트가 바뀌면 저장을 거부한다. 표현 창에서도 선택 대상·프로젝트 변경을 검사한다. 취소는 원본 문서를 바꾸지 않는다.
- 새 데이터·런타임·저장 스키마를 추가하지 않았다. 기존 `variants`, 활동 비용·효과, roster, 사건·선택·엔딩 계약을 사용한다.

## 실제 GUI 제작

기존 조건별 화면 연결 시험 프로젝트를 별도 폴더로 복사한 뒤 실제 Qt 위젯을 QTest로 조작했다. 복사 자체는 GUI 제작으로 계산하지 않는다. 이후 게임 문서 변경은 제작 작업실, 조건·효과 편집기, 다인 육성 창, 대본 편집기, 화면 연결 창, 부품 작업실, 캔버스 속성에서 수행했다.

| 활동 | 비용 | 효과 |
|---|---|---|
| 수련 | 공용 소지금 1 | 실행자의 현재 검술을 읽고 같은 양만큼 검술 증가 |
| 잠입 | 개인 체력 3 | 검술 2 증가, 만남 사건을 여는 플래그 설정 |
| 연회 | 공용 소지금 2 | 개인 체력 5 회복 |

소운의 초기 검술은 10, 연화는 40이다. 동일한 수련 규칙이 각각 20, 80을 만든다. 이후 서로 다른 활동을 배정하고 다시 교환해 개인 수치와 공용 비용을 확인한다. 원래 있던 다른 활동·사건·엔딩은 보존했다.

‘활동 안내 카드’ 정의 하나를 기존 화면 두 곳에 배치한다. 수련·잠입·연회 결과일 때만 각각의 문구를 표시하고, 계획·사건·엔딩에서는 원래 문구로 복귀한다. 두 배치본을 만든 뒤 원본의 기본 문구를 한 번 수정해 둘 다 바뀌는지 검사했다. 화면 추가·복제 없이 화면 ID 목록은 제작 전후 동일하다.

기존 화면 템플릿은 프로젝트에 남아 있지만 검증 경로는 시작부터 엔딩까지 `screen-1`을 사용한다. 활동 필터는 현재 표시하는 **주인공의 활동 결과**를 기준으로 한다. 두 캐릭터의 서로 다른 활동과 수치 변화는 결과 UI에서 개별 표시한다. 부품마다 임의의 실행자를 지정하는 새로운 문맥 계약을 만든 것은 아니다.

## 플레이·저장 검증

Windows의 실제 SDL/RmlUi 플레이어에서 대상별 활동 선택과 버튼 입력을 실행했다.

- 첫 수련: 소운 검술 10→20, 연화 40→80, 공용 소지금 30→28.
- 세 활동의 결과 화면에서 두 부품의 문구를 비교하고 저장·복원했다.
- 잠입 만남 사건에서 자동으로 다음 활동을 실행할 수 없음을 확인했다. 선택 도중 저장하고 선택 결과까지 진행한 뒤 불러오면 다시 같은 선택을 기다린다.
- 동료와 함께 탈출 / 혼자 탈출의 관계 결과는 각각 +3 / -1이었다. 고정 seed와 배정 경로에서 각각 `ordinary`, `certified` 엔딩에 도달했다. 이는 보존한 기존 사건·엔딩 규칙을 포함한 관측 결과다.
- 두 경로의 36개·38개 체크포인트에서 실제 UI의 전체 상태가 코어 명령 실행 결과와 같았다. 모든 체크포인트가 같은 화면을 사용했고, 두 부품의 표현이 기준 평가 결과와 일치했다.
- 엔딩 저장 후 새 게임→불러오기, 별도 플레이어 프로세스의 불러오기에서도 상태·화면을 확인했다.
- 저장을 거치는 실행과 거치지 않는 실행의 최종 전체 상태를 두 선택 분기 모두 비교했다.

최종 Qt 제작 시험 1개, 기존 화면 표현·부품 계층 회귀 2개, 기존 상태·표현·화면·내보내기 Node 회귀 19개, 공개 콘텐츠/새 샘플 회귀 3개가 통과했다. Windows 실제 플레이 시험은 두 분기를 포함한다. 초기화·정리와 반복 실행 횟수는 별도 기능 시험으로 합산하지 않았다.

## 재현 가능한 샘플과 기록

- 공개 회귀 프로젝트: `tests/fixtures/projects/reusable-activities`
- 제작 결과 식별 정보: `tests/fixtures/reusable-activities.json` — 개인 절대 경로 없음.
- Qt 제작: `native/studio/reusable-activities-test.inc`
- 코어·저장 회귀: `tests/runtime/reusable-activities.test.mjs`
- 실제 Windows 플레이: `tests/native-player/reusable-activities.test.mjs`
- 로컬 편집기: `dist/qt-studio-reusable-activities/RaisingStudioQt.exe`
- 최종 GUI 저장 원본: `.cache/reusable-activities/final-authored`
- 최종 제작 로그: `.cache/reusable-activities/qt-final.txt`
- 기존 GUI 회귀 로그: `.cache/reusable-activities/qt-compatibility.txt`
- 실제 플레이·스크린샷·저장 파일 위치: `.cache/reusable-activities/play-evidence.json`

공개 프로젝트는 GUI 저장본의 게임 문서를 그대로 복사했다. `.studio`와 상속된 단일 인물용 `scenarios/` 시험 파일은 배포에서 제외했다. 기존 `planMonth` 시나리오는 다인 배정용이 아니므로 두 캐릭터 전용 Node 회귀 경로로 대체한다. README와 상대 경로 검증 메타데이터는 시험 도구가 작성한 문서이며 GUI 제작 콘텐츠로 계산하지 않는다. 에셋 매니페스트는 비어 있다.

실행 명령과 대상별 배정 표는 샘플의 README를 따른다. 원본 사용자 프로젝트·저장·실행 창은 유지한다.

## 템플릿과 플러그인의 경계

활동의 이름·비용·효과·사건 조건은 콘텐츠다. 화면 템플릿은 시작 배치이며 실행 가능한 상태를 제한하지 않는다. 재사용 부품은 화면 요소의 원본을 공유하며 게임 규칙을 복사하지 않는다. 조건별 표현은 문구·이미지·컨트롤러 등의 표시를 선택할 뿐 비용·효과를 실행하지 않는다.

이번 샘플은 문구 기반으로 재사용을 검증했다. 이미지·애니메이션 컨트롤러 선택은 기존 계약을 사용하지만 새 그림·클립을 생성하거나 애니메이션 플러그인 자체를 변경하지 않았다. 클립 제작·블렌딩·정확한 재생 위치 복원은 해당 플러그인의 역할이다. 이번 실제 플레이 검증은 Windows이며 웹·모바일·콘솔을 새로 검증한 것으로 간주하지 않는다.
