# CI 실패 보고서에서 편집기 검토로

1. GitHub Actions 실행의 `goal-regression-reports` artifact를 다운로드해 압축을 풉니다. 편집기에서 해당 게임 프로젝트를 엽니다.
2. **디자인 → CI 경로 보고서 열기…**에서 `report.json`을 선택하고 **보고서 열기**를 누릅니다. JSON 파일의 절대 경로를 직접 입력할 수도 있습니다.
3. 현재 저장된 프로젝트로 자동 재검증합니다. 표에는 **CI 결과(원본)**와 **현재 결과**, 승인/남은 변화 수, 각각의 첫 차이 단계, 중간 저장 복원 결과가 나란히 표시됩니다. 경로를 선택하면 아래에서 비용·효과·능력치 차이와 실패 원인을 확인할 수 있습니다.
4. **첫 차이 그래프 · 승인 / 복원**을 누르거나 경로를 더블클릭합니다. 현재 결과의 첫 차이 단계로 이동합니다. 원본 기준·승인 기대값·현재 값을 확인하고 원하는 항목만 체크해 부분 승인하거나 이전 기준/부분 승인 상태로 복원합니다.
5. 승인·복원 후 경로와 중간 저장 복원을 다시 실행합니다. 그래프와 CI 창의 현재 결과가 갱신됩니다. CI 원본 결과는 바뀌지 않습니다. **현재 프로젝트 재검증 · 저장 복원 포함** 버튼으로 명시적으로 다시 검사할 수도 있습니다.
6. 검토를 마치면 콘텐츠, 경로, 기준 파일과 `playtests/baselines/.approvals`를 커밋·푸시합니다. 로컬 승인은 원격 CI 결과를 소급 변경하지 않으며 다음 Actions 실행에서 반영됩니다.

## 오래된 보고서와 오류

- 보고서의 콘텐츠 지문, 경로 목록, 기준 체크섬, 승인 버전을 현재 프로젝트와 비교합니다. 다르면 이유를 표시합니다. **그래프는 현재 로컬 재실행 결과**이며 오래된 CI 실행의 상태를 현재 상태로 가장하지 않습니다. CI 당시 실행을 재현하려면 그 시점의 콘텐츠·경로·기준 파일을 준비해야 합니다.
- 원본 CI JSON에는 모든 단계의 실행 상태가 들어 있지 않으므로, JSON만으로 과거의 전체 그래프를 복원하지 않습니다. 동일 입력이 있는 프로젝트에서 재실행해 연결합니다.
- 기준 파일이 없거나 손상된 경로는 원인을 표시하고 그래프 승인 버튼을 비활성화합니다. Git에서 해당 기준 파일을 복원한 다음 재검증하세요.
- 엔딩 미도달·명령 실패는 부분 승인으로 통과시킬 수 없습니다. 그래프에서 원인을 확인하고 콘텐츠 또는 경로를 수정해야 합니다.
- 저장하지 않은 초안은 먼저 저장해야 재검증할 수 있습니다. 재검증 뒤 콘텐츠·경로·승인 기준이 바뀌면 오래된 그래프에서 승인/복원할 수 없습니다.
- 다른 프로젝트로 전환하면 보고서 창이 닫힙니다. 파일을 다시 열면 새 보고서 세션으로 바뀝니다.

## 데이터 경계

원본 보고서는 읽기 전용으로 메모리에 보관하며 원본 파일을 수정하지 않습니다. 파일은 JSON 형식과 16 MiB 크기 제한, 최대 128개 경로 및 중복 ID를 검사합니다. 보고서가 지정하는 프로젝트 경로·기준 경로·변경 항목 ID로 실행하거나 승인하지 않습니다. 실행 대상은 사용자가 연 프로젝트이고, 승인 가능한 ID는 로컬 재실행 결과에서 새로 계산합니다.

편집기 CI 검토는 CLI의 `verify-replay` 정책을 사용합니다. 실행 파일 해시가 달라도 원본 콘텐츠·경로의 단계별 상태와 규칙 관측을 재현한 경우에만 기존 부분 승인 기대값을 적용합니다. 그래프에서도 같은 검사와 승인 문맥을 사용합니다.

## 검증

`tests/analysis/goal-ci.test.mjs`는 보고서 원본 보존, 로컬 결과 ID 발급, 첫 차이 그래프 이동, 부분 승인, 복원, 중간 저장 복원 재검사, 초안 차단, 중복/잘못된 보고서 거부와 다른 런타임 해시에서의 승인 호환성을 검사합니다. `qt-studio-test goalCiReview`는 실제 Qt 창에서 파일 열기부터 그래프 승인·복원·재검증까지 수행합니다.
