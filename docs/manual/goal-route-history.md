# 콘텐츠 수정 전 실행 결과와 비교

디자인 → 목표 경로 기록 · 회귀 검사 → **경로 그래프 · 재생 / 비교**에서 사용한다.

## 제작 흐름

1. 콘텐츠를 수정하기 전에 디자인 → **기준 기록 일괄 등록…**에서 등록할 경로를 선택하고 각각 이름을 입력한다. 공통 접두어로 작업 시점을 구분할 수 있다. 시작하면 등록된 경로의 seed·초기 조건·명령을 현재 초안의 스냅샷에서 실행하고 상세 기록을 백그라운드에서 저장한다. 경로 그래프의 **재생 경로를 기준 기록으로 저장**도 같은 도구를 해당 경로가 선택된 상태로 연다. 자동 탐색 경로는 먼저 회귀 경로로 등록한다.
2. 콘텐츠를 수정한다. 기존 기준 기록은 자동 갱신하거나 덮어쓰지 않는다.
3. **수정 전 기준과 비교**를 켜고 저장된 기준을 선택한 다음 **현재 초안으로 불러오기**를 누른다. 왼쪽은 당시 저장된 결과, 오른쪽은 그 기록에 포함된 같은 명령·seed·초기 조건으로 현재 초안을 실행한 결과다. 현재 경로 파일을 수정하거나 삭제해도 기준에 포함된 명령은 유지된다.
4. **첫 분기로** 이동한다. 최초 상태 차이와 최초 검사 차이는 따로 표시한다. 결과 값이 같아도 조건 검사나 비용·효과 추적이 달라질 수 있다. ◆가 붙은 보라색 노드는 검사 결과가 달라진 단계다.
5. **능력 · 자원 · 상태**, **조건 차이**, **실제 행동 검사**에서 당시 값과 현재 값을 비교한다. **콘텐츠 변경 원인**에는 해당 단계가 검사한 활동·행동 및 목표 조건에 관련된 정의 변경을 우선 표시한다. 나머지 콘텐츠 변경도 함께 제공한다.
6. 이전 단계에서 상태가 이미 달라졌다면 누적 영향이라는 안내가 나온다. 상세 탭의 `history.beforeDifferences`와 `observationChanges`로 입력 상태 차이와 검사 결과 차이를 구분할 수 있다. 좌우 단계를 독립 이동할 수 있지만 서로 다른 명령을 비교할 때는 동일 명령의 인과 비교가 아니다.

## 저장 계약

등록 창은 경로 재생과 상세 기록 진행률을 따로 표시하며, 검사 중에도 편집기는 응답한다. 등록 도중 초안·프로젝트 파일·경로·런타임이 바뀌면 미완료 기록의 게시를 중단한다. 이미 등록된 불변 기록은 남으며, 변경된 버전은 새 작업으로 등록한다. 취소하거나 창을 닫아도 완료된 기록을 삭제하지 않는다. 미완료·취소·시간 초과는 등록 성공이 아니다.

기준 파일: `playtests/baselines/<UUID>.json` (버전 1).

- 이름, 생성 시각, 콘텐츠 지문, C++ 런타임 실행 파일의 SHA-256 식별자
- 기준 콘텐츠 정의 스냅샷 (외부 이미지·소리·폰트 파일은 포함하지 않음)
- 경로의 명령·seed·초기 조건과 각 시점의 실행 상태
- 각 단계의 조건 평가, 명령 실행 가능 여부, 비용·효과 검사 추적 및 목표 도달 결과
- 파일 내용의 SHA-256 무결성 값

과거 상태와 검사 결과는 현재 런타임으로 재계산하지 않는다. 현재 콘텐츠만 재실행한다. 지문과 런타임 버전 같은 메타데이터 차이는 게임 상태의 최초 분기점으로 계산하지 않고 별도 표시한다. 런타임 식별자가 바뀌면 콘텐츠 변경만으로 결과 차이의 원인을 단정할 수 없다는 안내가 나온다.

UUID 단위 불변 파일이며 동일 파일의 덮어쓰기를 거부한다. 다른 편집기 창과의 저장 충돌은 전용 쓰기 잠금으로 보호한다. 임시 파일을 완성한 뒤 게시하고, 읽을 때 크기·형식·단계 정합성·무결성을 검사한다. 무결성 값은 우발적인 손상을 검출하며 디지털 서명은 아니다. 기준 기록은 프로젝트 파일과 함께 백업/버전 관리할 수 있다.

## 해석과 제한

- 이 기능은 실제 기록과 규칙 변경을 연결하는 디버깅 도구다. 여러 규칙을 동시에 수정하거나 이전 상태가 달라지면 하나의 규칙을 유일한 원인으로 증명하지 않는다. 해당 단계의 검사 경로와 관련된 변경, 전체 정의 변경, 전후 상태를 함께 보여준다.
- 명령 실행 실패 뒤에는 현재 경로 재생을 중단한다. 과거 경로의 이후 단계는 계속 볼 수 있고, 현재 경로의 미실행 수는 표시한다. 실패 후의 현재 상태를 만들어 내지 않는다.
- 같은 엔딩을 얻었더라도 중간 자원이나 조건 검사 차이를 찾는다. 반대로 화면 제목처럼 게임 상태에 영향 없는 정의 변경만 있으면 상태 분기를 표시하지 않는다.
- 기준은 사전에 저장해야 한다. 기록하지 않은 과거 콘텐츠의 실행 결과를 추정해 복원하지 않는다.
- 기준 파일은 64 MiB, 프로젝트당 128개로 제한한다. 백그라운드 등록은 기본 경로당 300초, 전체 3,600초 제한이며, 한도 초과는 실패로 표시한다. 개별 그래프 비교는 60초 제한이고 저장 후 전체 비교는 별도 [저장 검사 예산](goal-save-impact.md)을 사용한다. 지도는 60단계씩 탐색하고 규칙 변경 표는 2,000행까지 표시한다. 실제 플레이어 화면·애니메이션·외부 에셋의 픽셀 차이 검사는 포함하지 않는다.
- 기준 비교의 동일 결과는 실제 배포된 플레이어 저장 파일의 호환성 보장이 아니다. 출시 업데이트는 내보내기의 기존 저장 검사와 명시적인 표현 변경 검증, 실제 저장 파일의 불러오기·진행·다시 저장으로 별도로 확인한다.

## 검증

`tests/analysis/goal-history.test.mjs`: 디스크 저장과 서비스 재시작, 같은 명령의 최초 분기, 비용·효과·조건 변화, 조건 강화에 따른 실행 실패, 누적 상태 차이, 원본 보존, 손상 감지, 덮어쓰기 거부, 런타임 변경 경고, 무관한 표시 변경.

`native/studio/goal-history-test.inc`: 실제 Qt 기준 저장, 편집기 재생성 후 기록 선택, 분기 이동, 값 비교, 규칙 원인 표, 그래프 표시, 앞뒤 단계 이동.

`tests/qt-studio/baseline-background.test.mjs` 및 `native/studio/route-batches-test.cpp`: 백그라운드 등록, 응답성, 입력 변경 차단, 취소, 게시 무결성, 등록된 기록 보존과 실제 Qt 등록 흐름.

증거: `docs/evidence/goal-history/`. 시험 프로젝트는 사용자 원본의 별도 복사본이다.


콘텐츠 저장 시 모든 등록 경로를 기준과 자동 비교하려면 [저장 기준 비교 결과](goal-save-impact.md)를 참고하세요.
