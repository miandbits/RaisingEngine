# 인간과 LLM의 콘텐츠 작성 규칙

콘텐츠는 프로젝트의 JSON 파일이며 인간용 편집기와 LLM이 같은 파일을 사용합니다. 현재는 편집기가 없으므로 샘플을 복사해 텍스트 편집기로 수정하고 계약 테스트로 확인합니다.

## 파일 편집

활동·사건·인물·엔딩은 항목별 파일을 사용합니다. ID는 영어 소문자·숫자·하이픈으로 유지하고 표시 이름을 바꿀 때 ID는 바꾸지 않습니다. 프로젝트 밖의 파일이나 URL을 에셋으로 참조하지 않습니다. 스키마에 없는 필드는 추가하지 않습니다.

requirements는 항상 명시합니다. 조건이 없으면 `{ "op": "always" }`입니다. 효과가 없으면 빈 배열입니다. 단순한 활동은 successCheck·successEffects·failureEffects를 모두 생략합니다. 성공 판정을 넣을 때는 세 필드를 모두 작성합니다.

## 사건 작성

기간은 0부터 시작합니다. 두 달 샘플에서 0은 1월 상순, 2는 1월 하순, 5는 2월 하순입니다. 창의 시작·끝은 모두 포함됩니다. 사건은 해당 기간 활동 뒤에 발생합니다.

대본 진입 ID와 모든 다음 노드를 연결합니다. 선택지는 비활성 조건까지 고려하여 최소 하나가 선택 가능하도록 설계합니다. 부정적인 수치 효과를 결제로 쓰면 별도의 잔액 조건도 작성합니다. end 없는 경로나 순환은 지원하지 않습니다.

기본 엔딩은 requirements가 always, priority가 0입니다. 다른 엔딩이 모두 조건에 맞지 않을 때만 사용됩니다.

## 수정과 검증

`npm test`는 빌드 후 계약·로더·의미 검사·CLI 회귀 테스트를 실행합니다. 새 프로젝트는 `npm run build` 후 `npm run validate -- <프로젝트 폴더>`로 검사합니다. [CLI 사용법](../reference/cli.md)에 자동화용 JSON 출력과 오류 코드가 있습니다.

스키마·정적 의미 검사 통과는 플레이 가능성을 보장하지 않습니다. 조건에 따른 실제 사건 발생과 엔딩 도달은 코어 단계에서 확인합니다. 샘플 시나리오는 현재 기대 결과를 담은 명세이며 실행 가능한 게임 파일이 아닙니다.

향후 프로젝트 도구에서는 예상 파일 버전을 지정하여 수정합니다. 외부 편집 전에 Studio에 미저장 변경이 있는지 확인하고, 충돌 시 어느 변경을 유지할지 비교합니다. 실행 중인 세션에 새로운 데이터를 직접 섞지 않습니다.
