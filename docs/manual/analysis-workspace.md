# 콘텐츠 탐색·흐름·자동 플레이 작업실

2026-10-11 구현. 기존 프로젝트와 시뮬레이션 규칙을 유지하면서 편집기, CLI, MCP에 같은 콘텐츠 색인과 분석 실행기를 연결했습니다.

## 미리보기 실행

사건·엔딩의 **도달 분석** 바로가기를 추가한 최신 빌드는 `release/context-analysis-preview/Raising Studio-win32-x64/Raising Studio.exe`입니다. 이전 창에 자동 반영되지 않으므로 새 실행 파일에서 프로젝트를 여세요. 수정 중인 초안이 있다면 먼저 저장하세요.

새 기능은 `release/analysis-preview/Raising Studio-win32-x64/Raising Studio.exe`에 별도 포터블 빌드로 패키징했습니다. 실행 후 **열기**에서 기존 프로젝트 폴더를 선택하세요. 기존 배포 실행 파일과 설치 파일, `projects/my-first-year`의 콘텐츠는 변경하지 않았습니다.

포터블 빌드에서도 분석·재생·취소와 엔딩 1,200개 탐색을 포함한 GUI 테스트 2개를 통과했습니다. 별도 번들 MCP의 14개 도구 노출, 3회 분석 완료, 기록 재생도 확인했습니다.

## 사용 순서

1. 편집 가능한 프로젝트를 엽니다. 기본 내장 샘플은 새 프로젝트로 복사합니다.
2. **콘텐츠**에서 종류를 선택하고 이름·ID·설명, 태그, 인물, 발생 기간, 진단으로 좁힙니다. 능력·자원·플래그·에셋은 배열의 개별 항목으로 탐색합니다.
3. 항목을 선택해 상세 폼에서 편집합니다. 문서 탭과 이전 문서 버튼으로 이동합니다. 입력이 멈춘 뒤 650ms 후 전체 구조·의미 검증을 수행합니다. 실행·저장·검사에도 기존 검증이 적용됩니다.
4. **흐름**에서 선택 항목 중심의 관계도, 사건 기간 정렬표, 실제 next/choice/branch 연결을 표시하는 대본 그래프를 봅니다. 관계 노드를 누르면 중심이 바뀌고, 근거를 누르면 상세 폼으로 이동합니다.
5. **테스트**에서 횟수·seed·전략·명령 한도·시간 한도를 지정해 분석을 시작합니다. 목표 종류를 고르면 제한된 빔 탐색으로 사건·엔딩·선택지 경로를 찾습니다.
6. 결과에서 미방문 사건·엔딩·선택지, 엔딩 분포, 최종 능력 분포, 후보 거부 이유를 확인합니다. 재현 기록의 명령 위치를 지정해 실제 미리보기에서 이어서 플레이할 수 있습니다.
7. 끝까지 완료한 경로는 새 ID로 회귀 시나리오를 저장할 수 있습니다. 변환한 시나리오를 먼저 실제로 재실행하고 최종 상태를 확인한 뒤 기존 버전 검사·저장 서비스를 통과합니다.

사건·엔딩을 선택하면 콘텐츠 상세와 흐름 화면 위쪽에 **이 사건 도달 분석 / 이 엔딩 도달 분석** 버튼이 나타납니다. 누르면 입력 중인 필드의 변경 반영을 기다린 뒤 현재 초안으로 해당 항목을 목표로 분석을 즉시 시작하고 테스트 탭으로 이동합니다. 기본값은 seed 42, 최대 3회, 실행당 2,000명령, 60초, 탐색 폭 24, 탐색 상태 20,000개입니다. 이동한 테스트 탭에서 목표와 설정을 확인하고 조정해 다시 실행할 수 있습니다. 내장 읽기 전용 샘플은 프로젝트로 복사한 뒤 사용할 수 있습니다. 저장 전 초안 분석, 사건에서 엔딩으로 목표 전환, 대량 플레이 전환 시 목표 해제를 실제 Electron GUI에서 확인했습니다.

검색 결과는 가상 목록으로 최대 22개 행만 렌더링합니다. 관계도는 깊이 1~3단계, 최대 200개 연결로 제한하며 생략 사실을 표시합니다. 검색 조건은 프로젝트 경로별로 로컬 편집기 저장소에 최대 20개 보관합니다. 문서 탭은 최대 12개, 이동 이력은 최대 50개입니다.

다중 선택 태그는 **선택한 항목의 소속 문서**에 적용합니다. 루트 문서의 선택적 `tags` 필드를 공통 스키마에 추가했습니다. 기존 데이터는 수정 없이 열립니다. 새 필드를 사용하는 문서는 이전 배포판의 스키마에서 거부될 수 있으므로 새 편집기로 사용하세요. 배열 항목별 태그와 항목별 일괄 수치 변경은 이 버전의 범위 밖입니다.

## 실행·판정 계약

- 모든 실행은 검증된 콘텐츠 스냅샷과 기본 초기값을 사용합니다. 테스트 중 편집해도 해당 실행에는 영향을 주지 않습니다.
- 활동·선택 후보는 실제 코어 명령으로 실행 가능 여부를 검사합니다. 봇이 능력·플래그를 직접 수정하지 않습니다. 실패한 후보 검사는 원본 상태·난수를 소비하지 않습니다.
- 기본 전략은 균등 랜덤, 지정 능력 증가 우선, 자원 증가 우선, 미방문 선택·사건 우선입니다. 전략 판단용 난수와 게임 난수는 분리합니다. 실행 번호 n의 게임 seed는 `(기준 seed + n) >>> 0`입니다.
- 동일 스냅샷·설정·seed의 실행은 같은 명령과 결과를 냅니다. 시간 제한에 도달하기까지 완료한 실행 개수는 기기 성능에 따라 다릅니다. 동시 작업 간 결과 일치도 검사합니다.
- 최대 10,000회, 실행당 10,000명령, 작업 시간 1시간까지 설정합니다. 목표 탐색 폭은 1~64, 확장 상태 한도는 최대 100,000입니다. 작업은 별도 Node worker에서 실행하고 취소·진행 조회가 가능합니다.
- 목표 탐색은 조건 거리와 플래그 생성 사건, 경쟁 엔딩 우선순위를 참고합니다. 성공 판정은 실제 코어 상태로만 수행합니다. 엔딩 목표는 해당 엔딩 대본까지 종료된 `finished` 상태를 요구합니다.
- `found`: 실제 도달 기록 발견. `not-found`: 설정한 탐색 범위 내 미발견. `impossible`: 지원하는 범위에서 불가능 증명. 불가능 증명은 상수와 선언된 능력 범위의 직접 비교 및 그 all/any 조합으로 제한합니다. not, 복합 수식, 모든 분기·seed의 완전 탐색을 증명하지 않습니다. 기본 엔딩에는 이 증명을 적용하지 않습니다.
- 후보 거부 횟수는 실행 실패 횟수가 아닙니다. 비용 부족 후보를 거부한 뒤 다른 활동으로 정상 진행한 경우도 포함됩니다.
- 대량 실행의 커버리지는 실행별 방문 횟수입니다. 같은 실행에서 같은 선택을 반복해도 해당 선택의 방문 횟수는 1입니다. 목표 탐색 결과의 커버리지는 보관한 대표/발견 경로 기준이며 탐색 공간 전체 통계가 아닙니다.

## 기록과 버전

`<project>/.studio/analysis/<UUID>.json`에 설정·진행·결과를, `<UUID>.snapshot.json`에 당시 콘텐츠를 보관합니다. GUI와 MCP가 같은 파일을 읽습니다. 결과에는 콘텐츠 fingerprint, 원본 디스크 버전 또는 초안 내용 해시, seed, 명령과 최종 상태가 포함됩니다. 작업 상태는 임시 파일을 쓴 뒤 교체합니다.

모든 실행의 집계는 유지하지만 전체 명령 기록은 발견·신규 커버리지·문제 사례 등 최대 30개만 보관합니다. 재생은 원래 스냅샷으로 수행하며 전체 재생 시 저장된 최종 상태와 비교합니다. 별도의 에셋 바이너리는 복사하지 않으므로 미리보기 이미지는 현재 프로젝트 파일에 의존합니다.

이전 버전 결과는 화면에 표시하며 회귀 시나리오 등록 시 콘텐츠 fingerprint가 다르면 거절합니다. 편집기의 미저장 초안 버전은 내용 해시이므로 재실행 후 revision 숫자가 우연히 같아도 최신으로 오인하지 않습니다. 외부 디스크 변경 탐지는 기존 저장·불러오기 흐름을 따릅니다.

취소하면 완료된 집계와 보관 기록을 유지합니다. 호스트가 사라진 실행은 조회 시 중단 오류로 표시합니다. 분석 결과 자동 정리와 중단 지점에서 작업 자체를 재개하는 기능은 제공하지 않습니다.

회귀 시나리오는 기존 계약을 사용합니다. 끝나지 않은 사건 도달 경로와 엔딩 내부 선택이 있는 경로는 재현 기록으로 사용할 수 있지만 현재 시나리오 계약으로 내보내지는 않습니다. 같은 시나리오 ID는 덮어쓰지 않습니다.

## 모듈과 인터페이스

| 파일 | 책임 |
| --- | --- |
| `packages/analysis-service/catalog.ts` | 개별 항목 색인, 검색, 조건·효과·참조 관계 |
| `model.ts` | 분석 설정, 집계, 재현 기록, 작업 상태 계약 |
| `runner.ts` | 실제 코어 기반 대량 실행, 제한 목표 탐색, 재생 |
| `jobs.ts`, `worker.ts` | 백그라운드 작업, 영속 기록, 취소, 공유 조회 |
| `scenario.ts` | 완료 경로를 기존 시나리오로 변환하고 재검증 |
| `bridge.ts` | Electron preload의 제한된 IPC 계약 |
| `legacy/studio/renderer/Explorer.tsx`, `Flow.tsx`, `Tests.tsx` | 탐색·흐름·테스트 화면 |
| `apps/tools/cli/analyze.ts` | 명령행 실행·조회·취소 |

MCP에 `search_content`, `content_relationships`, `start_analysis`, `analysis_status`, `cancel_analysis`, `replay_analysis`, `export_analysis_scenario`를 추가했습니다. 기존 7개 도구와 함께 총 14개입니다. 검색·시작·시나리오 저장은 expectedVersion을 요구합니다. 상태 조회는 최근 20개 작업과 기록 요약을 반환하며 전체 명령은 명시적 재생 조회에서 반환합니다. 읽기 전용 MCP는 분석 시작·취소·시나리오 저장을 거절합니다.

CLI 예:

```powershell
npm run build
node dist/apps/tools/cli/analyze.js projects/my-first-year start '{"runs":1000,"seed":42,"strategy":"random"}'
node dist/apps/tools/cli/analyze.js projects/my-first-year list
node dist/apps/tools/cli/analyze.js projects/my-first-year cancel <작업-ID>
```

- `.cache/analysis-regression.log`, `.cache/analysis-final-gui.log`, `.cache/analysis-scale/summary.json`, `.cache/analysis-targets.json`, `.cache/analysis-ui/*.png`에 근거를 남겼습니다.

실행: `npm run test:analysis`, `npm run test:analysis:ui`, `node scripts/verify-analysis-scale.mjs`, `node scripts/verify-analysis-targets.mjs`.

## 이번 버전 이후

드래그로 연결선을 수정하는 그래프 편집, 달력 형태의 기간 배치, 범용 SAT/SMT 증명, 분산 실행, LLM이 플레이 전략 코드를 생성·실행하는 기능은 포함하지 않습니다. 현재 기간표는 검색·정렬 가능한 사건 표입니다. 관계도는 의존성 근거이고 실행 순서를 보장하지 않습니다. 추가적인 증명 기법은 현재의 미발견/불가능 구분을 유지하며 확장합니다.
