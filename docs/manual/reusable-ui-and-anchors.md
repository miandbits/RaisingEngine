# 재사용 UI 부품과 반응형 앵커

2026-10-12. Qt 편집기, Windows SDL/RmlUi 플레이어, 웹 플레이어에 적용.

## 직접 확인

`Edit-PM2-Components.cmd`로 별도 샘플 `projects/pm2-components-lab`을 연다. 기존 PM2 프로젝트는 변경하지 않았다.

1. 프로젝트 목록에서 **부품 상품 진열 A**, **부품 상품 진열 B**를 연다.
2. **디자인 → 재사용 UI 부품 작업실**에서 **공통 상품 카드**를 고른다.
3. 내부 `heading`을 선택하고 문구를 바꾼다. **속성 반영**으로 캔버스에서 확인하고 **저장**한다. 두 화면이 같은 원본 문구를 사용한다.
4. 화면의 카드 배치본을 선택하고 **부품 문구·행동 덮어쓰기**를 연다. 진열 B의 상품 설명·이미지·이동 대상은 이 배치본에만 적용된다. **이 요소의 덮어쓰기 초기화**는 원본을 다시 따르게 한다.
5. 작업실의 **상품 카드 / 확인창 / 빈 부품 → 부품 만들기**로 새 원본을 만든다. 패널·문구·이미지·버튼을 추가하고 캔버스에서 이동·크기를 조절한다. **저장하고 현재 화면에 배치**로 인스턴스를 추가한다. 다른 화면에서 같은 원본을 선택해 다시 배치할 수 있다.
6. **프로젝트 저장 → 처음부터 플레이 → 새 게임 → 외출 → 도구점 → 재사용 UI 실험실**로 진입한다. 진열 A/B, 구매 내용 확인, 구매/취소를 실행한다. 꽃다발 구매는 30 G를 소모한다. F5 저장, F9 불러오기로 복원을 확인한다.

작업실의 저장은 편집 세션에 적용한다. 디스크에 기록하려면 프로젝트 저장을 누른다. 원본/인스턴스 편집 모두 기존 공용 서비스의 revision 검사, 되돌리기·다시 실행, 검증·내보내기를 사용한다.

## 앵커

기존 프로젝트는 **화면: 비율 유지**가 기본이다. 고정 논리 화면 전체를 확대·축소하므로 개별 요소가 창 비율에 맞춰 재배치되지는 않는다.

**화면: 반응형 앵커**를 선택하면 창 비율에 따라 논리 영역이 넓어진다. 기준 설계 크기보다 논리 영역을 줄이지 않고, 전체 배율을 적용한다. 너비가 넓으면 가로 영역, 세로가 길면 세로 영역을 확장한다.

| 앵커 | 부모 크기가 바뀔 때 |
| --- | --- |
| 왼쪽 / 위 | 기준 위치와 크기 유지 |
| 가운데 | 부모 크기 변화의 절반만큼 위치 이동 |
| 오른쪽 / 아래 | 반대쪽 여백을 유지하며 위치 이동 |
| 좌우 / 상하 늘이기 | 양쪽 여백을 유지하며 크기 증가 |

화면 요소는 논리 화면을 부모로, 부품 내부 요소는 배치본의 사각형을 부모로 사용한다. 따라서 비율 유지 화면에서도 배치본 너비를 바꾸면 그 안의 늘이기 앵커가 작동한다. 위치·크기는 항상 기준 설계 좌표로 저장한다. 배치 도구의 16:9·4:3·9:16 미리보기에서는 캔버스 직접 이동을 잠가 기준 좌표를 잘못 덮어쓰지 않는다. 배치하려면 **설계 크기 · 배치 가능**으로 돌아간다.

## 데이터 계약

- `visual.components[]`: `id`, `label`, 기준 `width/height`, `elements`로 원본 정의.
- 화면 요소 `kind: component`, `componentId`: 복제한 자식 데이터 대신 원본을 참조.
- `overrides[]`: `elementId`와 변경할 `values`. 문구·이미지·스타일 일부·행동/대상을 재정의한다. 원본과 같은 값은 저장하지 않으며 초기화하면 다시 상속한다.
- `anchorX`: left/center/right/stretch, `anchorY`: top/center/bottom/stretch.
- `visual.viewportMode`: fit/responsive. 누락하면 기존 동작.
- 실행 시 `배치본ID__자식ID`로 확장한다. 원본 프로젝트와 시뮬레이션 상태는 배치 계산으로 변경하지 않는다.
- 부품 ID·자식 ID 중복, 누락된 참조, 잘못된 재정의, 병합 후 행동 대상/수치/범위를 검증한다. 사용 중인 부품 삭제를 막고, 재정의가 남은 자식 삭제도 먼저 정리하도록 안내한다.
- 런타임 capability의 `components-v1`, `anchors-v1`, `responsive-v1` 지원을 확인한다. 해당 기능이 필요한 프로젝트를 구형 런타임으로 내보내지 않는다.

## 검증 범위와 현재 제한

Qt GUI 테스트는 상품 카드 생성 → 집/타이틀 배치 → 개별 문구와 시작 행동 재정의 → 원본 문구 수정 → 확인창 생성과 일정 연결 → 실제 플레이를 수행한다. 배치본 확대에 따른 내부 앵커, 가로/세로 창 변경, 원본 수정 전파, 재정의 유지, 저장·복원의 상태 일치를 확인한다. GUI로 작성한 데이터와 실행 증거는 `docs/evidence/components`에 보존한다.

검증 결과: 전체 Qt 테스트 **10/10**, 공통 스타일·다국어·부품·내보내기 회귀 **20/20** 통과. `scripts/verify-components.mjs`의 Windows 실제 실행에서 진열 A/B의 공유 문구·개별 설명, 꽃다발 구매 30 G, 취소 무과금, 저장/복원 상태 일치, 중앙 앵커의 가로/세로 이동을 확인했다. 편집기·플레이어·웹 빌드와 TypeScript 검사도 통과했다.

실제 브라우저에서도 새 게임 → 도시 → 도구점 → 실험실 → 두 상품 화면 → 취소/구매를 클릭해 확인했다. 취소 후 500 G 유지, 구매 후 470 G, 1600×900과 700×1000 창에서 우측 40 논리 px 여백 및 확인창의 중심 상대 위치 유지가 통과했다. `browser-report.json`과 `output/playwright/components-web*.png`에 증거를 남겼다. 테스트 전용 브라우저와 서버는 종료했다.

별도 PM2 샘플은 Windows·웹 내보내기 검증용이다. 공통 카드/확인창을 각각 두 화면에서 사용하며 상품별 텍스트·이미지·구매 행동을 재정의한다. 취소는 화면 이동 명령이므로 화면 ID와 상태 revision은 변경되지만 재화·소지품 등 경제 효과는 발생하지 않는다.

이번 버전은 **패널·문구·이미지·버튼으로 구성하는 한 단계 부품**이다. 중첩 부품, 자동 반복 상품 목록, 변수/슬롯 기반 템플릿, 임의 이벤트 핸들러, 모달 팝업 스택, 오토 레이아웃/줄바꿈 배치는 포함하지 않는다. 확인창은 사용자가 만든 화면에 놓는 재사용 구성으로 검증했다. 이 샘플은 PM2 전체 UI를 반응형으로 재설계한 것이 아니며, 새 실험실 화면과 명시적으로 설정한 앵커에만 반응형 배치가 적용된다. 모바일·콘솔 실제 기기 검증은 이번 작업 범위에 포함하지 않았다.
