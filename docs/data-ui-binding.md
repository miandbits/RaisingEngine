# 4단계: 데이터와 재사용 UI 연결

2026-10-12 구현. Qt 편집기의 **디자인 → 데이터 · 반복 UI 연결**에서 사용한다.

## 제작 흐름

1. 화면을 만들거나 기존 화면을 연다.
2. 데이터 연결 작업실에서 재사용 UI 부품을 선택한다. 부품이 없으면 **기본 카드 부품 만들기**로 시작한다.
3. 데이터 종류와 대상을 고른다: 상점 상품, 정책 선택지, 인물 관계, 디자이너 데이터 표.
4. **기본 연결 채우기**로 시작하고, 부품 요소의 문구·이미지·행동·대상 ID·수량·표시 여부·허용 여부를 데이터 열에 연결한다. 문구 형식에는 `{value}`를 사용할 수 있다.
5. 세로 목록 또는 격자, 열 수, 간격, 행 높이를 정한다. 화면상의 전체 위치와 크기·앵커는 기존 속성 편집기로 조절한다.
6. 행 표시 필터와 목록 표시/행동 허용 조건을 설정한다. 조건은 기존 조건·수식 편집기를 사용한다.
7. 구매 확인창을 쓰려면 작업실의 프로젝트 전체 구매 확인 설정을 켠다. 공통 행동의 확인창은 정책·행동 작업실에서 설정한 내용을 사용한다.
8. 저장한 뒤 실제 플레이한다. 부품의 모양을 바꾸면 그 부품을 사용하는 모든 목록에 반영된다.

디자이너 표는 문자열·숫자·참/거짓 열과 안정적인 행 ID를 가진다. 예를 들어 문구, 행동 종류, 공통 행동 ID, 수량, 표시 여부를 열로 만든 뒤 각 열을 버튼에 연결하면 독자적인 서비스 목록을 만들 수 있다. 특정 식단·병원 이름에 종속되지 않는다.

## 데이터 계약과 실행

- `visual.dataTables`: `id`, `name`, `columns`, `rows`. 열 ID와 행 ID는 소문자·숫자·하이픈으로 구성한다. `id` 열은 예약되어 있다.
- `kind: collection`: `componentId`, `source`, `bindings`, `layout`, `columns`, `gap`, `rowHeight`, 선택적 `rowFilter`.
- `source.type`: `shopOffers`, `policyOptions`, `relationships`, `table`. 각각 상점·정책 그룹·인물·표를 지정할 수 있다.
- `bindings`: 부품의 `elementId`, 바꿀 `property`, 읽을 `field`, 선택적 `format`.
- `visibleCondition`, `enabledCondition`: 공통 Condition AST. 게임 조건과 행동 가능 여부는 기존 C++ 평가/검사 경로를 사용한다.
- 구매 가능 수량, 자원 부족, 방문 장소, 정책 공유 한도, 선택 상태는 현재 게임 상태에서 계산한다. 디자이너 바인딩이 기본적인 행동 불가 상태를 강제로 허용할 수 없다.
- 행의 실제 ID로 클릭 대상을 유지한다. 필터링·재정렬 후에도 행 번호로 다른 대상에 행동을 보내지 않는다. 확인 시점에는 현재 상태와 버전으로 다시 검사한다.
- 일반 컴포넌트의 버튼은 독립적으로 유효한 기본 행동을 유지한다. 목록 안에서 데이터가 행동과 대상 인자를 덮어쓴다.
- 공유 JSON Schema·의미 검증으로 열/부품/대상 참조, 자료형, 중복 연결, 허용 행동을 검사한다. 내보내기 기능 식별자는 `data-ui-v1`이다.

Qt 작업실은 숫자처럼 보이는 텍스트 필터(`123`, `true`)를 문자열로 보존한다. 누락된 참조를 임의의 첫 항목으로 교체하지 않으며, 목록을 전환할 때 저장하지 않은 변경을 확인한다.

## 샘플과 검증

`projects/data-ui-lab`은 기존 규칙 샘플을 복사한 뒤 Qt GUI 테스트로 네 화면과 사용자 표를 제작한 프로젝트다. 프로젝트 JSON을 생성 스크립트로 주입하지 않았다.

- `Data products`: 시장 방문 후 상품 카드에서 구매·취소. 다른 장소에서는 구매 대상이 나오지 않는다.
- `Data policies`: 정책 선택, 선택 상태, 24시간 공유 한도, 스크롤.
- `Data relationships`: 인물과 관계 수치 표시, 카드 버튼으로 사용자 표 화면 이동.
- `Designer table`: 행 필터로 숨김, 표의 행동 ID·수량 연결, 확인·취소.

검증 결과:

- Qt GUI 제작과 저장 후 재열기 일치, 재편집 시 필터 자료형·표 데이터 보존 통과.
- 기존 Qt 회귀 16개 통과. 별도 샘플을 요구하는 시나리오는 기본 회귀에서 건너뛰며 새 데이터 UI 시나리오는 따로 실행했다.
- 데이터 UI/비주얼/게임플레이 계약 회귀 47개 통과.
- 네이티브 및 Wasm 컨트롤러의 바인딩·조건·수량·오래된 명령 거부 테스트 통과.
- Windows 실제 플레이: 구매 60→20, 정책 한도, 관계 표시, 숨김 행, 수량 2 행동의 비용 8·체력 +20, 기도 행동, 저장·복원 일치 통과.
- 실제 Chrome 웹 플레이: 동일 흐름, 구매 확인 취소 시 상태 불변, 공유 부품 변경 반영, 반응형 카드 폭 변경, 스크롤 위치 보존 통과.

재현 도구:

- `native/studio/data-ui-test.inc`: `dataUiAuthoring`, `dataUiEditRoundtrip`. 제작 테스트는 새 규칙 샘플 복사본에 `RAISING_DATA_UI_PROJECT`를 지정한다.
- `tests/native-player/data-ui.test.mjs`: 실제 네이티브 렌더러 동작.
- `tests/native-player/data-ui-authoring.test.mjs`: GUI 제작본을 읽기 전용으로 내보내 실제 플레이.
- `scripts/verify-data-ui.mjs`: GUI 제작본의 Windows/웹 내보내기 및 실제 브라우저 검증.
- 최근 브라우저 실행 정보: `.cache/data-ui/latest.json`.
- 보존 증거: `docs/evidence/data-ui/`.

## 현재 범위

반복 템플릿은 텍스트·이미지·패널·버튼으로 구성된 재사용 부품이다. 중첩 반복 목록, 임의 JavaScript 표현식, 대규모 목록 가상화는 포함하지 않는다. Qt 캔버스에서 사용자 표는 정적 값을 미리 보고, 게임 상태가 필요한 내장 데이터 소스는 필드 자리표시자를 본다. 실제 상태의 필터·가능 여부·조건은 플레이에서 확인한다. 모바일·콘솔 기기 실행을 이번 단계에서 검증한 것은 아니다.
