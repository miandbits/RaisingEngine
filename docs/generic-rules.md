# 범용 정책 · 행동 · 공유 한도

후속 Qt 빌드에는 [조건·수식 시각 편집, 실행 흐름, 규칙 디버거](visual-logic-and-debugging.md)가 추가되었다. 아래 지원 범위는 최초 범용 정책 버전의 기록이며 최신 사용법은 후속 문서를 참고한다.

프린세스 메이커의 식단과 병원은 엔진의 고정 기능이 아니라, 프로젝트에서 정의하는 정책과 행동의 사용 예다. 새 콘텐츠는 **디자인 → 정책 · 행동 · 공유 한도 작업실**에서 작성한다. 거래의 상품·재고·구매·판매는 기존 거래 시스템을 재사용한다.

## 제작 순서

1. **공통 행동**에서 이름, 이용 장소, 비용, 효과, 실행 조건, 최대 수량, 확인창을 설정한다. 장소를 선택하지 않으면 어디서나 실행할 수 있다. 병원·성당·신전·암흑가 등의 이름이나 종류를 엔진에 추가할 필요가 없다.
2. 지속적으로 적용할 규칙은 **정책 그룹**에서 만든다. 식단·공부량·수면량을 각각 별도 그룹으로 만들고, 각 선택지에 공통 행동을 연결한다. 같은 행동을 여러 그룹에서 재사용할 수 있다.
3. 그룹마다 일정 실행 전/후와 적용 간격을 정한다. 간격 단위는 프로젝트의 일정 칸이며, 반드시 달력 하루를 뜻하지는 않는다.
4. 선택 조합에 제약이 있으면 **공유 한도**를 만든다. 예를 들어 하루 시간 24를 정의하고 공부 8시간·수면 8시간 선택지에 각각 8을 배정한다. 합계 16은 허용되고 공부 20 + 수면 8은 거부된다. 시간·슬롯 등 단위와 이름은 디자이너가 정한다.
5. 화면을 열고 **현재 화면에 목록 배치**를 누른다. 모든 항목 또는 체크한 항목만 표시할 수 있다. 화면 여러 곳에서 같은 정의를 참조하므로 비용·효과 변경이 함께 반영된다.
6. 캔버스에서 크기·위치·앵커를 조정하고 이동 버튼으로 연결한다. 저장한 뒤 처음부터 플레이하여 정책 선택, 직접 행동, 일정 진행을 확인한다.

`Edit-Rules-Lab.cmd`는 새 Qt 빌드와 별도 실습 프로젝트 `tests/fixtures/projects/rules-lab`를 연다. 집 화면의 **Policies**와 **Services** 버튼으로 독립 정책 및 재사용 서비스를 시험한다. 이 예제의 데이터와 화면 연결은 Qt 폼으로 작성했다.

이전 PM2 예제의 변환본은 `projects/pm2-rules-lab`에 별도로 저장했다. 기존 `projects/pm2-facilities-lab`는 보존했다. 변환본은 Qt에서 저장·다시 열기와 참조 검증을 확인했다.

## 실행 계약

- `gameplay.actions`: 조건·비용·효과·수량·확인창·선택적 사건 연결을 가진 재사용 행동.
- `gameplay.policyGroups`: 그룹별 선택지, 행동 참조, 실행 시점과 간격. 여러 그룹을 동시에 선택할 수 있다.
- `gameplay.policyBudgets`: 선택 조합 전체가 공유하는 한도. 각 선택지의 `budgetUses`가 사용량을 정의한다.
- 직접 실행 명령은 `executeAction`, 정책 선택/해제는 `selectPolicy`다. 화면 목록은 `actions`와 `policies`이며 `actionIds`/`groupIds`로 필터링한다.
- 선택 시점에는 정책의 비용·효과를 적용하지 않는다. 선택 해제·재선택으로 적용 주기를 앞당길 수 없다. 직접 행동의 장소 제한은 직접 실행에, 정책 그룹의 장소 제한은 정책 선택에 적용한다. 선택한 정책은 다른 장소에서 일정이 진행되어도 적용된다.
- 일정 전 정책 → 활동 판정·비용·효과 → 일정 후 정책 순서다. 일정 전 정책으로 변경된 능력은 그 활동의 조건·성공 판정에 반영된다.
- 정책 중 하나나 활동이 실패하면 해당 일정 명령 전체를 되돌린다. 비용·효과·주기·난수 상태 일부가 남지 않는다.
- 수량은 공통 행동의 비용과 효과를 반복 적용한다. `rejectNoEffect`를 켜면 실제 변화가 전혀 없는 행동은 청구 없이 거부한다.
- 정책 선택과 행동 실행도 상태 버전을 검사한다. 확인 취소는 상태를 바꾸지 않는다. 선택·다음 적용 시점·마지막 적용 시점은 저장과 명령 재생에 포함된다.

## 기존 프로젝트 변환

기존 `diets`/`services`와 저장 기록의 실행 경로는 유지한다. 새 작업실의 **기존 시설을 범용 규칙으로 변환**은 현재 편집 초안에서 서비스→행동, 식단→정책 그룹/행동, 화면·컴포넌트·버튼 연결을 함께 바꾼다. 저장 전 취소할 수 있고 저장 후에는 편집기의 실행 취소를 사용할 수 있다. 원본 프로젝트의 복사본에서 변환하여 검토하는 것이 좋다.

변환 시 기존 식단들의 이용 장소와 간격이 다르면 자동으로 하나의 그룹에 합치지 않고 이유를 표시한다. 없는 참조와 의미가 달라지는 빈 서비스 위젯도 변환을 거부한다. ID 충돌은 새 ID를 만들고 연결을 함께 바꿔 해결한다.

변환은 과거 진행 저장의 명령이나 프로젝트 외부 시나리오를 자동 이식하지 않는다. 프로젝트 내용과 명령 종류가 바뀌므로 새 게임을 시작하고 외부 시나리오를 갱신해야 한다. 또한 새 일정 전 정책은 활동 조건·성공률에도 영향을 주므로, 이 부분의 밸런스는 변환 후 재검토해야 한다.

## 현재 지원 범위

이번 기반은 특정 게임 이름이나 시설 종류를 하드코딩하지 않는다. 다만 모든 규칙을 작성할 수 있는 범용 비주얼 스크립트 전체가 완성된 것은 아니다.

- 자동 실행 훅은 현재 일정 실행 전/후 두 종류다. 일·월·장소 진입 등 별도 훅은 아직 추가하지 않았다.
- Qt 폼은 능력/자원 비용과 증감·고정 효과, 비교 조건을 제공한다. 기존 복합 조건·효과는 원본을 보존하지만 모든 표현식의 시각 편집을 제공하지는 않는다.
- 직접 행동에는 상호작용 사건을 연결할 수 있다. 일정 정책에서 사건을 시작하는 연결은 중간 대본 진입을 막기 위해 검증에서 거부한다.
- 행동은 기존 효과 모델을 사용한다. 상품 재고·장비 판매 등은 기존 거래 시스템에서 처리한다.
- 배포 기능 표시는 `generic-rules-v1`이다. Windows와 웹 검증 범위이며 모바일·콘솔 실기 검증을 의미하지 않는다.

검증 소스는 `native/studio/rules-test.inc`, `native/studio/rules-migration-test.inc`, `tests/gameplay`, `tests/native`에 있다. GUI 제작 및 실제 플레이 증거는 `.cache/qt-rules-evidence`에 기록한다.

`scripts/verify-rules.mjs`는 GUI 작성 프로젝트를 Windows·웹으로 내보내고 실제 브라우저의 C++ Wasm 플레이를 검증한다. `.cache/rules/latest.json`에서 내보내기 경로를 확인한다. 검증 로그와 스크린샷 사본은 `docs/evidence/rules`에 보관한다.

TypeScript 회귀 45개, C++ 기존 회귀 12개, C++ 범용/시설 검증 9개와 정책 검증 5개가 통과했다. 웹 실제 플레이에서는 세 그룹 선택, 24시간 한도, 취소 시 동일 상태, 중복 확정 방지, 두 트리거의 적용과 저장 복원을 확인했다. 무료 휴식 한 칸에서 식단·공부·수면 정책이 함께 적용되어 돈 60→55, 지식 0→4, 체력 60→96이 되었다. 별도 초기 상태에서는 회복 행동 2회로 돈 60→52·체력 60→80, 기도 행동으로 평판 +2를 확인했다.

최종 Qt 회귀는 16개 통과, 실패 0개, 조건부 테스트 2개 생략이다. 생략 항목은 기존 PM2 시설 샘플의 재생성·화면 정리 전용 테스트이며 해당 환경 변수를 주지 않았다. 이번 범용 예제의 GUI 제작·저장·재열기·Windows 실제 플레이, PM2 복사본 변환·재열기, 변환 경계 사례는 실행했다. 별도로 실제 SDL 휠 스크롤과 창 좌표 클릭으로 아래쪽 정책을 선택하는 동작도 확인했다.
