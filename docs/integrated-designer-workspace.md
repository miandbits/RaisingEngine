# 이름으로 연결하는 통합 제작 작업실

디자이너 자유도 계획의 4단계다. 기존 제작 작업실을 확장하며 프로젝트 계약이나 저장 파일 형식을 변경하지 않는다.

## 제작 순서

**디자인 → 제작 작업실 · 데이터 / 행동 / 진행**에서 시작한다.

1. 왼쪽의 생성 종류에서 능력·자원, 플래그, 사용자 정의 상태, 일정 활동, 공통 행동, 물품, 자동 규칙, 예약 사건, 화면을 선택한다. 능력·플래그·활동은 이름을 입력하면 내부 ID가 자동 생성된다. 상태와 화면은 기존 전용 제작 창으로 이어진다.
2. 능력·자원의 종류·초기값·범위를 정한다. 활동이나 행동에서 비용 데이터를 이름으로 선택하고 수량을 입력한다. 조건·효과 편집기의 상태 변경에서 상태 그룹과 값을 이름으로 고른다.
3. 화면을 선택해 행동 버튼이나 데이터 문구를 추가한다. 화면 요소 목록에서 버튼을 선택하고 **공통 행동 실행 / 화면 이동**과 연결 대상을 이름으로 고른다. 기본 선택인 **기존 버튼 동작 유지**는 원래의 동작과 설정을 보존한다.
4. 문구는 데이터 바인딩 편집기에서 능력·관계 등에 연결한다. **조건별 문구·이미지·애니메이션**으로 동일한 요소의 상태별 표현을 만든다. 위치·크기는 **화면에서 위치·크기 편집**으로 캔버스와 속성 편집기를 사용한다.
5. 기본 화면 연결 또는 조건별 화면 연결을 선택해 표시할 화면·조건을 편집한다. 전체 우선순위 편집과 선택 이유 검사는 기존 화면 연결 창으로 이어진다.
6. **변경 적용 → 프로젝트 저장 → 검증 / 플레이**로 확인한다. 규칙 디버거에서는 기존 실행 서비스로 조건·비용·효과·상태를 검사한다.

목록과 선택지는 이름을 우선 표시한다. 내부 ID 열은 기본적으로 숨기지만 검색은 계속 가능하다. 참조·영향에서 항목을 두 번 누르면 검색을 해제하고 연결된 편집 위치로 이동한다. 파일·JSON Pointer는 오류 추적용 정보이며 제작 입력값이 아니다.

## 초안과 삭제 보호

- 적용하지 않은 입력이 있으면 다른 전용 편집기, 저장·플레이로 넘어가지 않도록 안내한다. 기존 초안 버전 검사와 되돌리기·다시 실행을 재사용한다.
- 활동의 파일 생성과 기본 데이터 설정은 하나의 배치 편집이다. 한 번의 되돌리기로 생성 전체가 취소된다.
- 비용 행에서 수량·데이터만 바꾸고 기존 대상 등 다른 필드는 보존한다.
- 삭제는 이름으로 사용처를 표시하고 외부 참조가 있으면 차단한다. 인덱스에 없는 시스템·초기값 맵·부품의 참조도 보수적으로 확인한다. 같은 ID 문자열을 사용하는 다른 범주의 참조 때문에 삭제가 차단될 수 있으며, 자동 연쇄 삭제는 하지 않는다.
- 잘못된 초안의 배열에 null 등의 항목이 있어도 실제 문서의 배열 위치를 보존한다. 잘못된 항목을 걸러낸 순번으로 다른 콘텐츠를 덮어쓰지 않는다.

## 실제 검증

기존 조건별 화면 연결 시험 프로젝트를 별도 폴더에 복사했다. 복사는 GUI 제작으로 계산하지 않는다. 그 이후 변경은 실제 Qt 위젯을 QTest로 조작했으며 콘텐츠 JSON을 외부에서 작성하지 않았다.

- ‘기운’ 자원 생성, 초기값 10, 자원 종류 설정.
- ‘내공 수련’ 활동 생성과 생성 전체 되돌리기·다시 실행. 기운 비용 1과 연회 상태 변경 연결.
- gameplay 정의가 없는 프로젝트에 ‘호흡 가다듬기’ 공통 행동 생성. 기운 비용 2와 수련 상태 변경 연결.
- 화면에 버튼을 추가하고 공통 행동을 이름으로 연결. 조건별 문구 ‘기운을 모으며 수련 중’ 제작.
- 사용 중인 기운의 삭제 차단, 상태의 사용처 탐색, 조건별 화면 연결 창 진입, 저장·재열기와 편집기에서 실제 플레이 실행.
- Windows 플레이어에서 취소 시 상태 유지, 행동 실행 후 기운 10→8 및 수련 화면·문구, 활동 실행 후 8→7 및 연회 화면 확인.
- 중간 저장을 불러와 활동 재실행 후 전체 상태 일치. 별도 플레이어 프로세스에서 중간 저장을 불러와 화면·문구·상태 일치.
- 기존 두 선택 분기의 사건·관계·엔딩과 중간/엔딩 저장 복원 회귀 통과. 편집 초안·버전 충돌·배치 편집·사용자 정의 상태·화면 연결 회귀 통과.

주요 자동 시험:

- `native/studio/integrated-authoring-test.inc`: 실제 Qt 제작. `RAISING_QT_INTEGRATED_AUTHORING=1`, `RAISING_QT_PROJECT`에 독립된 조건별 화면 연결 시험 프로젝트 지정 후 `qt-studio-test.exe integratedAuthoringRoundtrip` 실행.
- `tests/qt-studio/integrated-authoring.test.mjs`: 이름·상태·화면 요소·표현·참조 인덱스 및 잘못된 초안 위치 보존.
- `tests/native-player/integrated-authoring.test.mjs`: `RAISING_INTEGRATED_AUTHORING`에 Qt 시험이 생성한 authoring.json, `RAISING_NATIVE_PLAYER_RUNTIME`에 호환 런타임 경로 지정. 제작된 프로젝트를 변경하지 않고 내보내 실제 플레이·저장 복원을 검사한다.

이 작업의 로컬 결과:

- 편집기: `dist/qt-studio-integrated-authoring/RaisingStudioQt.exe`
- 제작 프로젝트: `.cache/integrated-authoring/final-authored`
- Qt 제작 기록: `.cache/integrated-authoring/qt-authoring-final.txt`
- 제작 화면: `.cache/integrated-authoring/workspace.png`
- Windows 검증 출력 위치: `.cache/integrated-authoring/play-evidence.json`

로컬 프로젝트·플레이 기록·빌드는 Git 공개 대상에 추가하지 않는다. 원작 에셋을 추가하지 않았다.

## 범위

작업실은 기존 상세 편집기를 연결하는 제작 중심점이다. 대본 전체, 복잡한 정책·상점·부품·플러그인 설정까지 모두 하나의 속성 폼으로 대체하지 않는다. 기존 프로젝트는 새 데이터나 연결을 만들지 않는 한 형식 변경이 없으며, 런타임·저장 계약은 그대로 사용한다. 이번 실제 플레이 검증은 Windows 기준이다. 웹·모바일·콘솔을 새로 검증한 것으로 간주하지 않는다.

다음 5단계는 같은 화면·부품을 재사용하는 여러 규칙의 제작 시험과 템플릿 정리다.
