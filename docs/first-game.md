# 첫 게임 만들기 — Qt 검토판

이 검토판은 Windows x64용이다. 설치 폴더의 `RaisingStudioQt.exe`를 실행한다. Node·Qt 개발 도구를 별도로 설치할 필요는 없다. 코드 서명과 새 Windows 가상 머신 검증은 아직 완료되지 않았다.

1. 프로젝트 선택기에서 **최소 일정 육성 · 2개월**을 고른다. 프로젝트 경로는 설치 폴더 밖의 비어 있는 폴더로 지정하고 **프로젝트 만들기**를 누른다. 기존 파일이 있으면 덮어쓰지 않고 거부한다.
2. 콘텐츠 탐색에서 활동 **휴식**을 열고 이름·비용·효과를 수정한다. **적용** 후 저장하고 **검증**에서 오류 위치를 확인한다. 사건·선택지·관계·결말도 콘텐츠 편집기에서 연결할 수 있다.
3. 화면 캔버스에서 화면과 부품을 배치한다. **디자인 → 규칙 확장 패키지 · 진행 방식**에서 조건·효과·진행을 작성하거나 `engine/examples/rule-extension-lab/dojo.raiserules`를 가져올 수 있다.
4. 처음부터 플레이를 실행하고 활동별 일정을 정한다. 사건 대사와 선택지를 진행하고 엔딩을 확인한다. 저장·불러오기는 게임 화면 버튼 또는 Windows 플레이어의 F5·F9로 확인한다.
5. **파일 → 게임 내보내기**에서 Windows 또는 Web을 고르고 빈 출력 폴더 이름을 입력한다. 성공하면 출력 폴더를 열 수 있다. 오류를 고친 뒤 같은 창에서 다시 내보낼 수 있다.
6. Windows 출력은 `RaisingPlayer.exe`로 실행한다. Web 출력은 HTTP 서버로 제공한다. `file://`에서 직접 여는 방식은 지원하지 않는다. 브라우저에서 저장을 다운로드해 보관하고 불러오기 입력으로 복원한다.

프로젝트 데이터와 저장 파일은 설치·업데이트·제거 대상과 분리해 보관한다. 콘텐츠를 수정하면 오래된 저장은 일반 불러오기에서 거부될 수 있다. 이전 버전 프로젝트를 보관한 뒤 **파일 → 콘텐츠 업데이트 · 저장 이전 / 복구**에서 차이를 검토하고 새 저장으로 이전한다.

참고: MIT는 엔진 코드의 이용 조건이다. 게임에 넣는 글·이미지·음악·폰트·플러그인의 권리는 별도로 확인해야 한다. GitHub Actions 보고서 기능에는 별도의 GitHub CLI와 로그인이 필요하다. 모바일·콘솔 빌드는 이 검토판의 검증 범위에 포함되지 않는다.
