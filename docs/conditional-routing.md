# 조건 기반 화면 연결

디자인 메뉴의 **화면 전환 연결**에서 기본·진행 단계 연결과 조건별 연결을 편집한다. 조건 편집기는 사용자 정의 상태, 특정 캐릭터의 상태, 능력·자원·관계 등 기존 조건 계약을 그대로 사용한다. 화면 연결은 게임 상태를 변경하지 않는 표시 규칙이다.

## 우선순위

1. 버튼·명령으로 지정한 명시적 화면 이동.
2. 조건별 연결 목록에서 조건과 적용 진행 단계가 모두 맞는 첫 항목.
3. 장소 연결 화면. 기존 옵션을 켰을 때 일정 계획·준비에서만 적용한다.
4. 기존 진행 단계별 연결.
5. 기본 화면.

명시적 이동의 기존 수명은 유지한다. 진행 단계 변경, 장소 이동, 대사 진행, 선택지 선택 시 해제된다. 같은 단계에서 사용자 정의 상태만 바뀌면 명시적 이동은 유지된다. 예를 들어 메뉴로 이동한 뒤 같은 단계에서 수련 상태가 되더라도 메뉴가 우선한다.

조건별 연결은 추가·편집·삭제·위/아래 이동할 수 있다. 새 연결은 계획·준비·활동 결과에 적용된다. 필요한 진행 단계를 체크하거나 모두 해제하여 모든 단계에 적용한다. 대사·선택지에서도 같은 자유 캔버스를 사용할 수 있지만, 그 화면에 진행·대사·선택 요소를 배치해야 한다. 화면 연결은 콘텐츠의 진행 가능성을 보장하지 않는다.

모달은 현재 화면 위의 임시 UI이며 자동 연결 대상으로 선택할 수 없다. 모달 닫기와 일반 화면 이동은 별개다. 일반 화면 이동은 뒤로 가기 이력을 만들지 않는다. 화면 요소의 조건별 표현도 화면 선택과 별도로 적용되므로 애니메이션만 바꾸려면 화면을 추가할 필요가 없다.

## 선택 이유 검사

화면 전환 연결의 **연결 적용 후 화면 선택 이유 검사…**에서 편집 내용을 적용하고 규칙 디버거를 연다. 프로젝트 충돌이나 적용 오류가 있으면 검사로 넘어가지 않는다.

- **초안으로 새 검사**: 실제 C++ 초기 상태에서 시작한다.
- 일정·활동·행동·대사·명시적 화면 이동을 한 단계씩 실행한다.
- **화면 선택 이유** 탭: 선택된 연결, 조건 불일치, 단계 불일치, 일치했지만 상위 연결이 우선한 항목을 순서대로 표시한다. 대상은 화면 이름으로 표시한다.
- **현재 상태** 탭에서 `customStates`, `uiScreenId` 등을 확인한다.
- **플레이 저장 불러오기**로 재생 검증을 통과한 저장 상태에서 검사할 수 있다. 프로젝트 변경 후에는 새 검사를 시작한다.

복수 조건이 동시에 참인 것은 오류가 아니다. 처음 맞는 항목 하나만 선택하므로 화면 사이를 재귀적으로 오가거나 게임 명령을 실행하지 않는다.

## 데이터와 호환성

`visual.routing.conditions`는 선택 필드다. 각 항목은 `label`, `screenId`, `when`을 가지며 `phases`로 적용 단계를 제한할 수 있다. 최대 64개, 배열 순서가 우선순위다. 기존 `defaultScreenId`, `phases`, `useLocationScreens`는 유지한다.

조건은 JS가 재구현하지 않고 C++ 런타임/웹 Wasm 평가 결과를 사용한다. 네이티브 플레이어도 같은 조건 계약을 평가한다. 대상 화면 누락·모달 참조·잘못된 상태 값·화면에서 사용할 수 없는 실행자 문맥은 기존 검증 서비스가 파일과 위치를 보고한다. 캐릭터 상태는 구체적인 캐릭터를 지정한다.

실행 상태나 저장 형식을 추가하지 않았다. 조건 연결이 없는 프로젝트는 기존 우선순위와 저장 재생을 유지한다. 새 연결은 `conditional-routing-v1` 기능을 광고하는 내보내기 런타임이 필요하며, 구형 Windows·웹 런타임은 내보내기 전에 차단한다.

## 검증

- 계약·의미 검증·사용자 정의 상태·저장·화면 연결 회귀: 112개 통과.
- 실제 Qt 위젯으로 기존 샘플에서 수련/연회 화면 복제, 이름 기반 상태 조건 연결, 순서 변경, 저장·다시 열기, C++ 디버거의 중복 조건 우선순위 및 Play 내보내기를 확인했다.
- 실제 Windows 플레이어: 두 선택 분기에서 엔딩까지 진행, 모든 체크포인트의 상태와 화면 선택을 기준 실행과 비교. 대화 중 명시적 메뉴 이동, 중간·엔딩 저장 복원과 새 프로세스 복원을 확인했다.
- 실제 Chrome/Wasm: 수련/연회 상태에 따른 화면·문구 변경, 저장 다운로드 후 불러오기에서 상태와 화면 일치.
- 기존 화면 연결, 장소/단계/기본 우선순위, 조건의 단계 제한, 잘못된 대상/조건, 구형 런타임 차단을 확인했다.

로컬 결과는 `.cache/conditional-routing/`, 웹 스크린샷은 `output/playwright/conditional-routing/`에 보관한다. 사용자 기존 프로젝트와 창은 수정하지 않았다. 공개 커밋에는 원작 에셋·개인 저장·실험 프로젝트를 넣지 않는다.
