# 편집기로 만드는 도감 화면

2026-10-15. Qt 편집기와 Windows 네이티브 플레이어에서 검증했다.

## 제작 방법

1. **프로젝트 설정 → 회상 · CG · 음악 도감**에서 도감 항목과 해금 조건을 설정한다.
2. **편집 가능한 도감 화면 만들기**를 누르고 적용한다. 목록·상세 화면, 두 카드 부품, 종류 탭, 해금 필터, 본편의 진입 버튼이 만들어진다. 생성 취소는 프로젝트를 변경하지 않으며, 적용은 하나의 실행 취소 작업이다.
3. 화면 목록에서 **도감 · 목록 / 도감 · 상세**를 연다. 일반 캔버스에서 위치·크기·색·폰트·앵커를 수정한다.
4. **데이터·UI 연결**에서 목록을 선택해 열 수, 행 높이, 카드 부품, 표시 조건과 데이터 연결을 수정한다. 카드 자체는 **재사용 UI 부품**에서 편집한다.
5. 새 버튼을 추가하고 **행동 → 도감 탭 · 필터**를 선택한다. 대상에서 CG·음악·사건·엔딩, 해금 여부, 프로젝트의 분류를 선택한다.
6. 본편의 버튼에는 **도감 열기**를 연결한다. 도감에서는 **항목 보기 → 원본 연출 회상 / 음악 재생**으로 이어진다. **본편으로**는 닫기 행동이다.

생성된 화면에는 전용 고정 위젯이 없다. 화면, 재사용 부품, 반복 목록, 문구, 이미지, 버튼으로 구성된다. 생성기를 쓰지 않고 기존 화면을 목록·상세 화면으로 지정해 직접 제작할 수도 있다. 목록 화면에는 닫기 버튼을, 상세 화면에는 목록/닫기 버튼을 배치해야 한다.

## 데이터 계약

`project.gallery.screenId`는 작성한 목록 화면, `detailScreenId`는 상세 화면이다. 두 필드는 선택 사항이며 서로 다른 유효한 화면 ID여야 한다. 두 필드가 없는 기존 프로젝트는 종전 도감 UI를 유지한다. 목록만 지정하면 상세는 기존 도감을 사용한다.

| 데이터 원본 | 용도 |
| --- | --- |
| `galleryEntries` | 현재 종류·해금·분류 필터에 맞는 도감 항목 |
| `gallerySelection` | 현재 선택한 해금 항목 1개. 목록 필터와 독립적 |

| 카드 필드 | 연결 예 |
| --- | --- |
| `name`, `category`, `hint`, `statusText` | 제목·분류·잠금 힌트·해금 문구 |
| `imageAssetId`, `hasImage` | CG/썸네일과 이미지 표시 여부 |
| `entryId`, `action` | 항목 보기 버튼의 대상 및 행동 |
| `unlocked`, `locked`, `enabled` | 버튼 활성화, 자물쇠 등 표시 조건 |
| `kind`, `recordCount`, `recordLabel` | 종류 필터, 기록 개수, 현재 기록 번호 |
| `isCG`, `isMusic`, `isNarrative`, `canReplay` | 매체별 버튼과 원본 연출 회상 버튼 표시 |
| `musicLabel` | 음악 재생/일시정지 문구 |

목록의 기존 `rowFilter`, 정렬, 격자·세로 배치, 스크롤도 그대로 사용할 수 있다. `galleryFilter` 행동의 값은 `kind:cg`, `status:unlocked`, `category:인연` 등이다. 각 축은 독립적이며 `all`은 모두 초기화한다. 선택된 탭에는 표시점이 붙는다. `gallery-summary`, `gallery-filter`, `gallery-error` 문구 연결도 제공한다.

잠긴 항목은 데이터 단계에서 제목을 `???`로, 이미지를 빈 값으로 바꾼다. 완전히 숨기는 항목은 행 자체를 반환하지 않는다. 카드 전체는 표시하되 보기 버튼을 `unlocked`에 연결한다. 런타임에서도 대상 ID와 해금을 다시 검사한다. 프로필의 ID가 같더라도 매체 종류나 원본 대상이 달라졌으면 해금으로 취급하지 않는다.

## 본편과 회상 분리

- 도감 열기부터 닫기까지 본편 일정·연출·음악·플러그인 시계를 멈춘다. 도감 화면으로 바뀌어도 본편 플러그인 인스턴스를 해제하지 않는다.
- 도감에서 본편 입력 필드·일정 변경 이벤트를 처리하지 않는다. 회상은 기존 독립 재생 세션을 사용한다.
- 회상 저장·불러오기는 회상 위치용 파일을 사용한다. 본편 저장, 난수, 명령 이력, 해금 기록을 덮어쓰지 않는다.
- 데이터 연결 이미지에는 고정 에셋을 요구하지 않도록 공통 검증을 보완했다. 연결이 없는 다른 목록이나 일반 부품 인스턴스의 누락 이미지는 여전히 오류다.

## 실제 검증

- `galleryUiAuthoring`: 새 프로젝트 마법사로 공개 샘플 복사 → 도감 화면 생성 → 실행 취소/다시 실행 → 일반 버튼을 추가해 ‘인연’ 분류 연결 → 목록을 2열로 변경 → 공통 카드 배경 수정 → 저장·다시 열기·오류 0건. JSON 파일 외부 수정 없이 Qt UI로 제작했다.
- `tests/native-player/gallery-ui.test.mjs`: 그 GUI 제작 결과를 내보내 두 달 일정을 플레이하고 엔딩 도달. CG·음악·사건·엔딩 탭, 종류/해금 조합, 빈 결과, 분류 버튼, CG 상세, 음악 재생·일시정지·정지, 원본 연출 회상, 회상 중 저장·복원, 본편 저장·복원, 새 프로세스에서 도감 재열기를 검증했다.
- 도감·회상 전후 본편 상태/RNG/명령/해금 기록의 동등성, 일정 중 도감에서 캐릭터 플러그인 인스턴스·포즈·시계 보존을 검사했다. 성능 진단 카운터는 상태 동등성 비교에서 제외했다.
- 기존 고정 도감 및 CG·음악·원본 회상 테스트 2개, 기존 UI 부품·데이터·구성 테스트 15개, 도감 계약·잠금 정보 보호·구형 런타임 내보내기 차단 테스트 5개 통과.
- 별도 리뷰 창에서 실제 마우스로 도감 열기, 스크롤바와 휠 이동, 새 분류 버튼, 상세 카드, 원본 연출 회상 및 목록 복귀를 확인했다.

재현 명령(먼저 TypeScript 빌드 및 스키마 복사):

```powershell
$env:QT_STUDIO_OUT='dist/qt-studio-gallery-ui'
node scripts/build-qt-studio.mjs
node scripts/test-qt-studio.mjs galleryUiAuthoring
$env:NATIVE_PLAYER_OUT='dist/native-player-gallery-ui'
node scripts/build-native-player.mjs
$env:RAISING_NATIVE_PLAYER_RUNTIME='dist/native-player-gallery-ui'
node --test tests/native-player/gallery-ui.test.mjs
```

테스트는 `.cache/gallery-ui/editor-project.txt`의 GUI 제작 프로젝트를 사용한다. 별도 프로젝트는 `RAISING_GALLERY_UI_PROJECT`로 지정한다. 스크린샷·플레이 보고서는 `.cache/gallery-ui/`에 저장된다.

## 리뷰 파일과 범위

- 편집기: `Edit-Gallery-UI-Lab.cmd`
- GUI 제작 프로젝트: `projects/last-grandson-gallery-ui-review`
- 해금 기록을 포함한 플레이: `release/last-grandson-gallery-ui-review/Play-Gallery-Review.cmd`
- 처음부터 별도 저장으로 플레이: 같은 폴더의 `Play-Fresh-Review.cmd`

기존 프로젝트·릴리스·저장 파일은 유지했다. 리뷰 프로젝트와 빌드는 로컬 산출물이며 공개 저장소에는 테스트와 생성 기능을 포함한다. 리뷰 프로젝트가 없는 체크아웃에서는 편집기 실행기가 공개 기본 샘플을 연다.

현재 지원·검증 대상은 Qt 제작 + Windows 네이티브 실행이다. 웹·모바일·콘솔 지원 완료를 의미하지 않는다. 새 플레이어 능력 `authored-gallery-v1`이 없는 Windows 런타임으로 내보내기는 차단한다. 원본 회상 내부의 재생 제어도 별도 화면으로 편집할 수 있으며, 미설정 프로젝트는 기존 공통 UI를 유지한다. 작성한 도감 화면 자체의 플러그인 애니메이션은 본편 인스턴스 보호를 위해 재생하지 않으며 안내 문구를 표시한다. 오래된 텍스트 전용 회상 기록을 읽으려면 상세 화면을 기본 도감 UI로 두면 된다.
