# 전투 HUD 제작

Qt **디자인 → 전투 HUD 제작…**에서 아군·적 상태, 행동, 대상, 로그, 실제 지급 보상을 배치한다. 일반 재사용 UI 부품과 데이터 목록으로 저장하므로 캔버스의 위치·크기·앵커와 부품 작업실의 공유 원본 편집을 그대로 이용한다.

## 샘플과 제작 순서

`Edit-Battle-HUD-Lab.cmd`는 `dist/qt-studio-battle-hud/RaisingStudioQt.exe`로 `tests/fixtures/projects/battle-hud-lab`을 연다. HUD는 Qt GUI 인수 테스트에서 제작·수정·저장했다.

1. 프로젝트 패널에서 **전투 · battle** 화면을 더블클릭한다.
2. **전투 HUD 제작…**에서 이름·위치·크기·행 높이를 편집한다. 새 구성에는 **기본 전투 HUD 배치** 또는 개별 목록 추가를 사용한다. 기본 배치는 기존 단일 전투 위젯만 대체하며, 다른 요소와 저장/불러오기 버튼을 보존한다.
3. **데이터 · 반복 UI 연결…**에서 부품·데이터 열·표시 필터·조건을 변경한다. 아군과 적은 같은 `battleActors` 데이터의 `side = ally / enemy` 필터로 나눈다. 기본 연결 채우기는 게이지와 행동도 지원한다.
4. **재사용 UI 부품 작업실**에서 문구·버튼·이미지·게이지를 편집한다. 아군과 적 게이지는 같은 원본을 참조한다. 게이지 `value`와 `maxValue`는 소수도 보존한다. `fill`은 바탕색, `color`는 채워진 막대 색이다.
5. 전투 종료 후 코어가 탐험 또는 활동 결과 단계로 이동하므로 해당 화면에도 로그·보상 목록을 배치한다. 샘플은 **탐험 · expedition**에 두 목록을 배치했다.

전투 단계는 ID `battle` 화면을 사용한다. 임의의 새 화면에 HUD를 넣는 것만으로 전투 화면 경로가 변경되지는 않는다. 작은 설계 화면에서는 기본 배치의 새 요소·카드 크기를 조정하며 기존 요소를 변경하지 않는다.

## 실제 플레이

1. **처음부터 플레이 → 새 게임 → 집의 일정 화면**을 연다.
2. **숲 탐험**(`forest-trip`)을 편성하고 확정한 뒤 다음 기간을 진행한다.
3. 입구에서 **이동 · 슬라임 공터**를 선택한다.
4. **방어 → 주인공 → 선택한 행동 실행**, 또는 **공격 → 숲의 슬라임 → 선택한 행동 실행** 순서로 진행한다. 선택·취소는 턴·자원·난수를 소비하지 않는다.
5. 행동과 대상을 선택한 상태에서 저장하고, 취소한 뒤 불러온다. 게임 상태와 아직 실행하지 않은 선택이 함께 복원된다.
6. 승리 후 탐험 화면에서 마지막 로그와 **감사의 꽃 +1**을 확인한다. 긴 로그는 목록 내부에서 스크롤한다. 승리 후 저장을 불러와도 보상은 중복 지급되지 않는다.

## 공통 계약

| 데이터 목록 | 주요 열 |
| --- | --- |
| `battleActors` | `id`, `name`, `side`, `hp`, `maxHp`, `hpText`, `battleTarget`, `value`, `maxValue` |
| `battleActions` | `name`, `displayName`, `battleAction`, `itemId`, `target`, `selected`, `enabled`, `reason`, `action` |
| `battleTargets` | `name`, `displayName`, `battleTarget`, `selected`, `enabled`, `reason`, `action` |
| `battleLog` | `text`, `turn`, `battleAction`, `heroDamage`, `enemyDamage`, `healed`, `outcome` |
| `battleRewards` | `name`, `amount`, `discarded`, `text`, `kind` |

버튼 행동은 `selectBattleAction`, `selectBattleTarget`, `confirmBattleAction`, `cancelBattleAction`이다. 실행 시 현재 코어 상태에서 행동·대상을 다시 검사하고 기존 `battleAction` 명령을 호출한다. 표시 조건으로 코어의 실행 제한을 우회할 수 없다.

`systems.battleHistoryLimit`(1–256, 작업실 기본 64)을 설정하면 확정된 턴 로그와 실제 보상 변경량을 기록한다. 생략한 기존 프로젝트는 이전 상태 구조와 저장 재현을 유지한다. 보상은 예상값이 아니라 실제 적용된 변화량이며 수용량 초과로 버린 아이템은 별도로 표시한다.

미실행 선택은 저장 파일의 `playerPresentation.battleSelection`에 보관한다. 코어 상태·revision·명령 이력과 분리되고, 복원 시 유효성을 검사한다. 내보내기 기능 식별자는 `battle-hud-v1`이다.

## 검증 기록

- Qt GUI 최종 인수 3개(초기화/종료 포함 5개) 통과: 기본 배치, 공유 게이지 수정, 실행 취소/다시 실행, 저장/재열기, 범용 바인딩 왕복. 별도 640×360 사례에서 경계·ID 충돌·행 높이 기본값 보존 검사.
- 공통 전투 HUD 계약 7개 통과: 잘못된 대상·소모품·게이지 범위, 소수 게이지 재정의, 보상 수용량 초과 포함.
- 전투 기록 3개 통과: TypeScript·네이티브·Wasm 로그/보상 일치, 저장 재현, 패배·도주, 이전 프로젝트 호환. 기존 전투 시스템 회귀 7개 통과.
- 네이티브/Wasm 컨트롤러 2개 통과: 회복 아이템, 대상 검증, 취소, 미실행 선택 복원, 오래된 revision 거부, 같은 seed 재현과 보상 중복 방지.
- 실제 Windows: `.cache/native-battle-hud/run-ZR0KQU/report.json`. GUI 제작 프로젝트에서 방어/자신·공격/적 선택, 저장/취소/정확한 복원, 승리 보상, 처리된 전장 재방문 시 중복 보상 없음, 완료 저장 복원 확인.
- 실제 웹: `.cache/battle-hud/run-Fa20cn/web-result.json`. 행동·대상 선택, 취소, 파일 저장/불러오기, 해상도 변경, 승리, 마지막 로그까지 휠 스크롤, 완료 저장 복원을 확인했다.
- 네이티브 실제 HUD 1개, 기존 타임라인 2개·입력/오디오 9개 통과. 기존 교류 피드백 `신뢰 +15`를 빈 문자열로 기대하던 테스트는 정상 피드백과 정확히 일치하도록 수정했다.
- 일정 연출 저장 회귀 11개, 기존 Qt 회귀 16개 통과. 전용 샘플 경로를 요구하는 Qt 사례 11개는 전체 실행에서 건너뛰며, 새 HUD 인수 사례는 전용 경로로 별도 실행한다.

## 현재 범위

**아군 1명·적 1명** 전투다. 공격은 적, 방어·회복은 자신을 대상으로 하며 도주는 대상 선택이 없다. 파티·다수 적, 자유 스킬 제작, 전투 연출 타임라인, 콘솔 인증은 이번 완료 범위가 아니다. 샘플에는 회복 아이템이 없어 실제 샘플은 공격·방어를 검증했으며, 아이템은 별도 코어/컨트롤러 사례로 검증했다.

스크린샷과 결과 요약은 `docs/evidence/battle-hud/`에 모았다.
